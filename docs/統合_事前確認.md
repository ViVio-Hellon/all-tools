# 4ツールの統合とデスクトップ版(Python/Tauri/Rust)── 事前確認

日報管理ツール(VER4.22.0)・資材発注看板システム(VER3.1.0)・ライン管理カレンダー(VER4.0.0)・
点検表 選択・印刷(VER2.0.0)を、**1つの入口(1つの exe と1つの Start.vbs)に大きなタブで並べ、中は分けたまま**
動かしたときに、**今の機能を維持できるか**を、作り始める前に確かめた結果です。
参照したのは移行済みの python-web-tools(梱包資材総合ツール VER4.0.0〜4.3.2)と、
すでにデスクトップ版のある3ツール(看板・カレンダー・点検表)の外枠です。

## 結論

**すべて維持できる。** 業務の処理(Python)と画面(HTML/JS)は書き直さない。変わるのは
「画面と Python のつなぎ方」と「ブラウザが代わりにやっていたこと」と「1つの窓に並べるための取り決め」だけで、
それは外枠(Rust)と入口(Python)が引き受ける。ただし、そのまま並べると壊れる所が次の 14 点あるので、
移行の中で手当てする(各ツールの元のリポジトリには手を入れず、`tools/` に取り込んだ写しで直す)。

### そのまま並べると壊れる所と、手当て

| # | そのまま並べると起きること | 手当て |
|---|---|---|
| A | **日報だけデスクトップ版が無い**(ポートで待ち受けるブラウザ版のみ) | 日報に `bridge.py`(標準入出力の入口)と `desktop.js` を足す。作りは他の3ツールと同じ。**保存の応答を先に返してから共有への写しを始める**(日報は応答のあとで `LocalBackup` へ写す作り。参照の作りのまま移すと、保存のたびに共有フォルダの写しを待たされる) |
| B | 4ツールとも**同じ宛先 `app://localhost`** を使い、同じ名前の Python モジュール(`app` `server` `start_app` `bridge` …)を持つ。1つの宛先・1つの Python には並べられない | **ツールごとに宛先と Python を分ける**(`nippou://` `kanban://` `calendar://` `inspection://`、Windows は `http://<名前>.localhost`)。Python はツールごとに別のプロセス(別の import の空間)。1つが落ちても、ほかのタブは動き続ける |
| C | 各ツールの Python は **Host が `app.localhost` / `localhost` 以外を断る**(DNS リバインディング対策)。カレンダーは Origin と Host の一致も見る | 外枠が、ツールへ渡すときに Host・Origin を**ツールが単体のデスクトップ版で受けていたものと同じ形**に直す。ツールの守りはそのまま |
| D | 日報・看板・点検表は **`X-Frame-Options: SAMEORIGIN`** を返す。大きなタブの中(iframe)に出せない | デスクトップ版: 外枠がこの見出しを外す(独自の宛先はアプリの外から読めないので、はめ込みの心配が無い)。ブラウザ版: `frame-ancestors` で**この PC の入口だけ**に許す |
| E | 各ツールの `desktop.js` は `window.__TAURI__` を見て窓まわりを外枠に頼む。iframe の中では Tauri の口が無い(Linux)/ あっても OS で振る舞いが違う(Windows は子の枠にも入る) | 外枠が各ツールの画面に**小さな台本(`embed.js`)を差し込む**。台本が `window.__TAURI__` の代わりになり、頼みごとを大きなタブの画面へ `postMessage` で渡す(送り元の宛先と枠を確かめる)。**各ツールの `desktop.js` は書き換えずに動く** |
| F | 単体の外枠は、Python の「終了してよい」で**アプリごと**終わり、落ちたら**窓ごと**読み直し、× で**自分だけ**に訊く | 統合の外枠は: × と大きなタブの「終了」で**全ツールに訊く**(訊くだけの問い合わせ → まとめて1つの確認 → 終える)。落ちたら**そのタブだけ**理由の画面。あるツールの「終了」は「アプリを閉じる」と同じ扱い(ほかのツールにも訊く) |
| G | 看板のモード切替は「Python を立て直して窓を読み直す」「帳票の窓を**全部**閉じる」 | **看板の Python とそのタブだけ**を立て直し、看板の帳票の窓だけ閉じる |
| H | **ブラウザ版とデスクトップ版の同時起動の止め方がツールごとにバラバラ**(点検表: 後から開いたほうが止まる / 看板: デスクトップ版が勝つ / カレンダー: 止めていない) | 統合では1つにそろえる: **どちらを後から開いても、後から開いたほうが止まる**。錠は Windows の**名前付きミューテックス**(点検表と同じ。Store 版 Python のファイル振り替えに左右されない) |
| I | ブラウザ版の待ち受けの番号が**ぶつかっている**(日報と点検表がどちらも 8733〜8736、カレンダーが 8730〜8733) | デスクトップ版は**ポートを使わない**ので起きない。ブラウザ版(予備)は各ツールの「空いている番号を探す」がそのまま効く(入口は 8700〜)。**点検表は 8781〜8784 へ移した**(日報と同じ番号で、起動の順で番号が入れ替わっていた) |
| J | 日報の静的ファイルは `/static/` ではなく `/sv/<版>/…`、音は `/sound/…`(206 の部分応答あり) | 外枠は `/sv/` も自分で返し、`/sound/` の部分応答(Range / 206)はそのまま通す |
| K | 日報の「タブの取り合い」(入力できるタブは1つ)は、ページを離れる合図を `sendBeacon` だけで送る。窓の中では届かないことがある(看板で実際に起きた) | 合図が届かなくても、窓の中のタブは1つなので取り合いにならない。`keepalive` 付きの送り直しを足す |
| L | F5 / Ctrl+R / Ctrl+P は WebView が**窓全体**に効かせる(1つのタブで F5 を押すと全タブが読み直しになる) | 差し込む台本が、**そのタブだけ**を読み直す / そのタブの画面を印刷するように受け止める(各ツールが自分で持っている Ctrl+P などはそのまま) |
| M | 帳票・印刷・VC早見表を開く `window.open`(日報 5 か所)は、窓の中では新しいタブが無い | 外枠が**別の窓**で開く(看板・カレンダーと同じ `open_window`)。窓はツールごとに数え、立て直しのときはそのツールの窓だけ閉じる |
| N | 大きなタブ(どのツールを出すか)を決める表が無い | **大設定**を作る。表は python-web-tools と同じ共有の DB(`梱包資材マスタ.sqlite3`)に**別の表 `タブ表示権限`** として置く(アクセス権限と同じ「ログインID・PC名、空欄は問わない、当てはまる行を全部足す」) |

### 移行の途中で見つけて直したこと

- Linux の WebKitGTK では、窓の `on_navigation` に**枠の中の移動も来る**ため、ツールの画面が枠に出なかった
  → Linux では各ツールの宛先を通す(Windows の WebView2 は窓そのものの移動だけが来る)
- 看板は、ブラウザを開かない起動(`--no-browser`)で心拍の見張りを立てていなかった → 統合ツールのブラウザ版が
  起こしたとき(`ALLTOOLS_PORTAL=1`)は立てる(入口が先に落ちても残らない)
- ブラウザ版とデスクトップ版の止め方を「**自分の錠を取ってから相手を見る**」にそろえた(同時に開いても少なくとも一方が気づく)
- 大設定: **最初の1行を足すと、登録の無い端末からツールのタブが消える**ので、足す前に確かめるようにした

## 何をどの言語に書かせるか

| 言語 | 受け持ち | 理由 |
|---|---|---|
| **Rust**(`統合ツール.exe`) | 1つの窓・各ツールの Python の起動と監視(**開いたタブだけ起こす**・落ちたらそのタブだけ)・宛先ごとの振り分け・**画面の部品(CSS/JS/画像)を直接返す**・Host/Origin の付け替え・台本の差し込み・別窓・保存/選択ダイアログ・既定のブラウザ・多重起動とブラウザ版との同時起動の防止・まとめた終了の確認 | OS の窓・プロセス・錠・ダイアログ・ファイルを直接扱える。部品を Python に渡さないので画面が軽い(日報は画面1枚で部品が 30 本近い) |
| **Python**(各ツール) | 業務のすべて(今までどおり) | VBA と同じ結果を守る試験 5,601 件がこの形で書かれている。重い計算は無く、待ちは共有フォルダ・Access・Excel。書き直しても速くならず、危険だけがある |
| **Python**(入口 `portal/`) | 大きなタブに何を出すか(タブ表示権限)・大設定の画面・管理者パスワード・ブラウザ版の入口(各ツールのブラウザ版を起こして並べる) | DB(共有の sqlite3)を読むのは Python の標準ライブラリだけで足りる。ブラウザ版(予備)と同じものを1つだけ持てる |
| **VBScript** | Access(日報)・Excel(点検表)の操作 | 今までどおり |
| **JS** | 画面の操作(今までどおり)。大きなタブの画面は小さな JS 1本 | ― |

## ポートを使わない仕組み

```
統合ツール.exe(Rust / Tauri)                         … src-tauri/
 ├─ 1つの窓(WebView2)。上に大きなタブ、下に各ツールの画面(iframe)
 ├─ 宛先ごとに受ける(ネットワークを通らない)
 │    portal://localhost(大きなタブ・大設定)   → 入口の Python(bridge.py)
 │    nippou:// kanban:// calendar:// inspection:// → それぞれのツールの Python(tools/<名前>/bridge.py)
 │    (Windows は http://<名前>.localhost)
 ├─ /static/… /sv/…(部品)は exe が自分で返す。それ以外は Python の標準入力へ
 └─ 頼みごと(別窓・保存・選択・立て直し)は、iframe → 大きなタブの画面 → exe の順に渡る
        │ 標準入出力(1件 = 見出し1行 + 本文)× ツールの数
        ▼
各ツールの bridge.py(Python)… Flask アプリを WSGI として呼ぶだけ(待ち受けない)
```

## 同時に動かさない(どちらを後から開いても止まる)

| 先に動いているもの | 後から開いたもの | 動き |
|---|---|---|
| ブラウザ版(Start.vbs / start.bat) | デスクトップ版(exe) | 「ブラウザ版が動いています。ブラウザの『終了』で閉じてから開いてください」と出して終わる(Python も起こさない) |
| デスクトップ版 | ブラウザ版 | 「デスクトップ版が動いています」と出して終わる。デスクトップ版の窓を前に出す |
| デスクトップ版 | デスクトップ版 | 開かず、開いている窓を前に出す |
| ブラウザ版 | ブラウザ版 | 開いているものにブラウザでつなぐ |

錠は名前付きミューテックス `Local\nlm.all-tools.instance`(目印 `.desktop` / `.browser`)。
Python 側(`portal/instance_guard.py`)と Rust 側(`src-tauri/src/instance.rs`)は同じ名前・同じ手順で、試験で突き合わせる。
各ツールの単体の起動ファイル(`tools/<名前>/Start.vbs`)で開かれたブラウザ版とも、ツールごとの錠で止め合う。

## 大設定(タブ表示権限)

- 置き場所: python-web-tools と**同じ共有の DB**(既定 `\\nlmfangyshrd\各課共有\0130_日軽稲沢\梱包課\AIM\【■】_参照用ファイル\梱包資材マスタ.sqlite3`)に、
  **別の表** `タブ表示権限` を作る(アクセス権限の表には混ぜない)。置き場所は大設定・配布設定・環境変数で変えられる
- 列: `管理番号` `ログインID` `PC名` `表示タブ`(例 `日報, 看板`。`すべて` も可)`既定タブ` `有効` `備考`
- 決め方(アクセス権限と同じ): 空欄は「問わない」/ 大文字小文字を区別しない / 両方空欄の行は効かない /
  当てはまる行の表示タブを**全部足す** / `有効=0` の行は飛ばす
- 当てはまる行が無い PC: ツールのタブは出さず、大設定に「この PC(ログインID・PC名)が登録されていません」と写せる形で出す
- 表がまだ無い・共有に届かない(手元の写しも無い): すべてのタブを出し、大設定に理由を出す(ラインを止めない)
- 共有に届かないときは、前回読めた手元の写しで決める
- 書き換え: 大設定の画面で(管理者パスワード。既定は他ツールと同じ)。共有の DB へ直接書き、手元の写しも読み直す

## Windows の実機で人が見ること(この開発環境では確かめられない)

- iframe の中から出す `confirm()` の確認ダイアログ(WebView2)
- 帳票の「印刷する」から紙が出ること・Ctrl+P
- ドラッグ&ドロップ(看板の中身の入れ替え・日報の取り込み)
- 保存ダイアログ・フォルダ選択(共有フォルダを辿れること)
- 音(日報の音声通知)・クリップボード
- **Microsoft Store 版の Python で、ブラウザ版とデスクトップ版が互いに止め合うこと**
- Access(cscript)・Excel の実物での反映・印刷
