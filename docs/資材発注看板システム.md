# 資材発注看板システム(VER3.5.10)

資材の看板を画面で見て、ライン(現場)は足りない資材に「欲しい」(赤)を出し、倉庫は「発送」(緑)や「注文中」(黄)を付けます。物が届いたら現場が確認して、看板を元に戻します。
もとは Excel マクロ(VBA)と Access で作られていたツールを、Python とブラウザの画面で置き換えたものです。日報複合ツールの大きなタブ「看板」から開きます。

## 仕様

### 必要なもの

Python 3.9 以上と Flask(ブラウザ版で動かすときは waitress も)。配布フォルダには同梱せず、各 PC に入っているものを使います。一覧は [日報複合ツール.md](日報複合ツール.md) の「必要なもの」にあります。共有の看板マスタは標準ライブラリの sqlite3 で読み書きします(DB ドライバは要りません)。

### 画面の一覧

| 画面 | 何をするところか | 開き方 |
| --- | --- | --- |
| 看板の画面(現場モード) | 担当ラインの看板だけを見る。サイズのボタンで発注・取り消し・届いた確認。注文票の印刷 | 日報複合ツールの大きなタブ「看板」 |
| 看板の画面(倉庫モード) | 全ラインの看板をタブで切り替えて見る。発送・注文中を付ける。一括発送。発送明細・非常設品リストの印刷 | 同上(この端末のモードが倉庫のとき) |
| 看板の画面(倉庫参照モード) | 見るだけ。押しても何も変わらない | 同上(この端末のモードが倉庫参照のとき) |
| コメント(💬) | 看板ごとに倉庫と現場がやり取りする。1 件 200 文字まで | 看板の右端の 💬、または「新しいコメント」の帯の「開く」 |
| 印刷前の確認画面 | 注文票・発送明細・非常設品リストを、刷る前に紙の上だけ直す | 🖨 のボタン(別の画面で開く) |
| 設定 | 9 つのタブ(下の表) | 左の並びの「設定」、またはモードの札 |
| 起動待機画面 | 「起動しています」と出し、取り込みが済むと看板の画面になる | 開いたとき |
| 「この画面では操作できません」 | 同じパソコンで看板を 2 つ開いたとき、押せるのは 1 つだけにする覆い | 自動で出る |

設定のタブは次の 9 つです。

| タブ | 何をするところか | パスワード |
| --- | --- | --- |
| この端末 | モードと担当ラインを変える。この端末の権限(ログインID・PC名・使えるモード)を見る | 担当ラインを変えるときは要る |
| 接続先 | 共有DB・看板履歴・アクセス権限の置き場所、CSV の書き出し先、取り込み・書き戻しの間隔、自動印刷 | 要る |
| マスタ管理 | 看板を増やす・減らす・資材名やサイズを直す。アクセス権限の行を足す・直す | 直すときは要る(見るだけなら要らない) |
| 看板集計 | 出した回数・届くまでの日数・提出率などを出す。CSV に書き出す | 要らない |
| 取り込みの状態 | 「↻ いま取り込む」。まだ送れていない操作の一覧を見る | 片付けるときは要る |
| 記録 | エラー・断った操作を探す。なぜなぜ分析シートを作る | 要らない |
| ファイルの場所 | 共有するファイルと、この PC だけのファイルの場所を見る | 要らない |
| パスワード認証 | 管理者パスワードで認証する・決める・変える | — |
| 配布設定 | 1 台で決めた設定を書き出して、ほかのパソコンへ配る | 要る |

### 看板の状態

看板 1 枚は、共有DBの表 `看板_<ライン>` の 1 行(資材 × サイズ)です。状態は次の列の組み合わせで決まります。

| 見え方 | 状態 | 共有DBの列 | 付ける人・ボタン | 外す人・ボタン |
| --- | --- | --- | --- | --- |
| 灰色(何も出ていない) | まだ発注していない | 不 = 〇 | — | — |
| 赤 | 発注中(欲しい) | 欲 = 〇、更新日 = 押した日時 | 現場がサイズのボタンを押す | 現場が赤をもう一度押す(発送前・注文中でないときだけ) |
| 赤 + 緑の「発送」 | 発送済み | 発送 = 〇、倉庫確認日時 | 倉庫が「発送」、または一括発送 | 倉庫が緑の「発送」をもう一度押す(緑だけ外れる)。現場が「届いた」を確認すると赤と緑の両方が消える |
| 🔒 赤 + 黄の「注文中」 | 注文中(倉庫に在庫が無く、仕入れ先へ注文した) | 保留 = 〇、注文中日時 | 倉庫が「注文中」を押す(赤がある看板だけ) | 倉庫が黄をもう一度押す。発送すると自動で外れる |
| 赤なし + 緑 | 発送処理中に注文が取り消された | 欲 = 空、発送 = 〇 | (倉庫の発送と入れ違いに現場が赤を消すと起きる) | 現場が帯の「確認した」を押すと緑が消える。倉庫が発送を外しても片付く |
| 青い斜めの字 | 非常設品(いつも置いていない資材) | 常設品 = × | マスタ管理で設定 | 押し方はほかと同じ |

決まりごと(VBA 版と同じものと、Python 版で足したもの):

- 注文中(🔒)の看板は、現場はサイズのボタンを押しても何も変わりません。倉庫が発送するか、注文中を外すまで待ちます。
- 赤が付いていない看板は、発送も注文中もできません(「注文がありません。」と断られます)。注文中を**外す**ほうは、いつでもできます。
- 注文中にすると、発送の印は外れます。現場の赤はそのままです。
- 一括発送でも、1 枚ずつ発送したときと同じく注文中は外れます。
- 「赤なし + 緑」の看板は、現場が確認するまで出し直せません。
- 色の意味は、前の Excel の看板と同じです。
- 現場モード・倉庫モードのボタンにマウスを乗せると、発注した時刻・発送した時刻・注文中にした時刻が出ます。

### データの置き場所

| 置き場所 | 中身 | だれと使うか |
| --- | --- | --- |
| `看板マスタ.sqlite3`(共有フォルダ) | 看板の表 `看板_<ライン>`、`Form状態管理`(開いている端末)、`看板コメント` | 全端末で共有。**正式なデータ** |
| `看板履歴.sqlite3`(既定は看板マスタと同じフォルダ) | 出した・発送・届いたなどの記録(看板集計が読む) | 全端末で共有。全端末で同じ場所を指す |
| `梱包資材マスタ.sqlite3`(既定は看板マスタと同じフォルダ) | アクセス権限の表(梱包資材総合ツールと共有) | 全端末で共有 |
| この端末の作業用DB(手元の SQLite。`%LOCALAPPDATA%\KanbanSystem` の `data`) | 看板の写し、**まだ送れていない操作**、この端末のモード、送る前のコメントと記録 | この端末だけ |
| 設定ファイル(`%APPDATA%\KanbanSystem\config.json`) | 接続先・間隔・自動印刷・管理者パスワード(ハッシュ)・担当ライン | この端末だけ。新しい版に入れ替えても消えない |
| ログと記録(「設定」→「記録」の「記録(ログ)の置き場所」。既定はこの端末の `logs`) | `<置き場所>\kanban\<ライン名>\kanban_DebugLog_<日時>.txt`(動作のログ)、`<置き場所>\kanban\記録\<年月>\kanban_記録_<PC名>_<年月日>.jsonl`(エラー・断った操作の記録。「記録」タブで探す) | 共有フォルダにすると全端末の記録を 1 か所で見られる。**ツール名のフォルダ `kanban` の下に、名前が `kanban_` で始まるファイル**で書く(ほかのツールのログと混ざらない。VER3.5.10)。前の版の `KanbanSystem\…` の記録もそのまま読む |

`Form状態管理` には、各端末が「開いている」印を自分で書きます。開いている端末は 2 分ごとに書き直し、10 分途切れると、ほかの端末の帯では `HVC?` のように `?` 付きで出ます。手で直しても、次に書かれた時点で戻ります。

書き戻しと取り込みの考え方:

- ボタンを押すと、まず手元の作業用DBに保存され、すぐ画面に出ます。
- **書き戻し**(手元 → 共有DB): 押した直後と、既定 60 秒ごと。変えた**列だけ**を送ります。終わるときにも必ず 1 回送ります。
- **取り込み**(共有DB → 手元): 既定 30 秒ごと。共有DBが変わったかを 2 秒ごとに見ていて、変わればすぐ取り込みます。
- 画面は 5 秒ごとに手元を見に行きます。ほかの端末の操作が出るまでは、ふつう数秒〜30 秒ほどです。
- 共有DBに届かないあいだ、押したものは手元に預かったままです。帯に「⚠ N 件がまだ共有に届いていません」(いつから・なぜ)が出て、共有DBが見えたら 5 秒以内に送り直します。押し直しは要りません。
- 5 回送っても届かないものは「要確認」になり、自動では送りません(設定 →「取り込みの状態」で理由が見られます)。
- 取り込めない時間が長くなると、帯に「⚠ 取り込めていません ○分前」が出ます。順調なときは何も出ません。

### マスタ管理(看板の追加・削除・直す)の決まり

マスタ管理は、Access を開いて直していた作業の代わりです。設定 →「マスタ管理」で開きます。

- **見るだけならパスワードは要りません。** 足す・直す・消すは管理者パスワードが要ります。
- 直せるのは看板の表 `看板_<ライン>` と、アクセス権限の表です。ほかの表は中身を見るだけで、直せない理由が表の上に出ます。
- 直せる欄は `資材` `サイズ` `常設品` です。看板の状態の欄(欲・不・更新日・発送・倉庫確認日時・保留・注文中日時)は読むだけです。状態は看板の画面のボタンで変えます。
- `管理番号` は直せません。打ち間違えたときは、消して足し直します。
- 看板を足すと、状態は「まだ発注していない」(不 = 〇)で入ります。`常設品` は 〇(常設)が入った状態で出るので、非常設品なら × に直します。足した看板は次の取り込みで各端末に出ます。
- 次のものは足せません・直せません: 管理番号が空、すでにある管理番号、資材かサイズが空、同じ資材・同じサイズの看板がもうある、常設品が 〇 × 空欄 以外。
- **発注中(赤)・発送済み(緑)・注文中(黄)の看板は消せません。** 先に看板の画面で片付けて(届いたら赤を消す・倉庫は発送や注文中を外す)から消します。
- **この端末にまだ送っていない操作がある看板は消せません。** 「未反映」が 0 になってから消します。
- 消す画面を開いたあとに発注などが届いていたら、消さずに「画面を開き直してください」と出ます。
- 消して同じ番号で足し直しても、前の看板の状態は引き継ぎません。
- **行き違い(VER3.5.6)**: ほかの端末がまだ送っていない発注があるうちに看板が消されると、その発注は届きません。その現場の看板の画面に「⚠ マスタ管理で消された看板への操作は届きませんでした: …」の帯を出します(「わかった」で消えます)。前の版はログに書くだけでした。

### 印刷

印刷前の確認画面では、マスを押して数や資材名を直したり、左のチェックで行を外したりできます。**直るのは紙だけで、看板の内容は変わりません。** 印刷の画面の「余白」は「既定」のままにします。印刷するものが無いときは「印刷する明細はありません。」と出ます。

| 帳票 | だれが | 載るもの |
| --- | --- | --- |
| 注文票 | 現場 | まだ発送されていない「欲しい」(赤だけ。注文中は載らない) |
| 発送明細 | 倉庫 | 発送した物(赤と緑。注文中は載らない) |
| 非常設品リスト | 倉庫 | 「欲しい」が出ている非常設品と、いまの状態(赤だけ = 受付、緑 = 発送、黄 = 注文中) |

### 看板集計

設定 →「看板集計」で、看板をいつ出して、何日で届いて、次に出すまで何日空いたかを数えます。読むだけなのでパスワードは要りません。記録は `看板履歴.sqlite3` に集まります(記録はこの仕組みを入れた版から始まり、それより前の分はありません)。

- 期間(月から月)とライン(全部 / 1 本)を選んで「集計する」。
- 出すもの: 届くまでの日数(平均・最短・最長)、ライン × 月のグラフ(提出率・出した回数・届くまでの平均日数)、ラインごとの要約、注文中の回数と日数、よく切れる資材、使用量、看板ごとの届くまでの日数。
- **提出率** = その月に 1 回以上出した看板の枚数 ÷ そのラインの看板の枚数。同じ看板を月に 2 回出しても 1 枚です。
- 押し間違い: 発送前に赤を消したもの(取消)は回数に数えません。注文中をすぐ外した、発送の無いライン(NS1 など)で赤をすぐ消した、は既定 5 分以内なら数えません(「押し間違いとみなす時間」で変えられます)。
- CSV に書き出せます(明細・週ごと・月ごと・提出率など)。BOM 付き UTF-8 で、Excel でそのまま開けます。

## 操作説明

### 現場モード

**欲しい資材を発注する**

1. 日報複合ツールの大きなタブ「看板」を押します。担当ラインの看板が出ます。
2. 足りなくなった資材の枠で、サイズのボタン(例: 段ボールの「大」)を 1 回押します。
3. ボタンが赤になれば出せています。倉庫の画面にも数秒で赤が出ます。

**間違えて押したときに取り消す**

1. 赤いボタンをもう 1 回押します(倉庫が発送する前だけ)。
2. 🔒(注文中)の付いた看板は取り消せません。倉庫に声をかけるか、💬 で知らせます。

**届いたら確認する(1 枚ずつ)**

1. 物が届いているのを確かめます。
2. 赤と緑が付いている看板のサイズのボタン(赤)を押します。
3. 「この資材は届いていますか？」と出たら「OK」を押します。赤と緑が消えて灰色に戻ります。
4. まだ届いていないときは「キャンセル」を押します。何も変わりません。物が届く前に OK を押さないでください。

**届いたものをまとめて確認する(一括確認)**

1. 赤と緑が付いている物が全部届いていることを確かめます。
2. 上の「届いた資材を一括確認」を押します(数字は対象の枚数。0 のときは押せません)。
3. 「○ 件の資材到着を確認し、表示を元に戻しますか？」で「OK」を押します。

**「発送処理中に注文が取り消されました」の赤い帯が出たとき**

1. 資材が届いているかを確かめます。
2. 帯の「確認した」を押します。緑が消えます。
3. まだ必要なら、そのあとで出し直します。

**コメント**

1. 倉庫からコメントが来ると「💬 新しいコメント N 件」の帯が出て、その看板の 💬 に赤い点が付きます。
2. 帯の「開く」か、看板の 💬 を押して読みます。読んだら「閉じる」。
3. 現場が書けるのは、赤を付けたあと、倉庫がまだ黄・緑を付けていないあいだです。書いたら「送る(現場として)」(Ctrl+Enter でも送れます)。
4. 相手のコメントを読まないまま看板を押すと、先に「💬 相手からのコメントがあります」が出ます。読んで「確認して進める」を押します。やめるときは「やめる」。

**注文票を印刷する**

1. 上の右の「🖨 注文票」を押します。印刷前の確認画面が出ます。
2. 必要ならマスを直す・チェックを外します。
3. 「🖨 印刷する」を押して、プリンターを選びます。

### 倉庫モード

**発送する**

1. 日報複合ツールの大きなタブ「看板」を押します。倉庫モードの画面が出ます。
2. 上のラインのタブ(例: L-1)を押します。赤いサイズが「欲しい」です。
3. 資材を用意して出したら、その看板の「発送」を押します。緑になります。
4. 間違えたときは、緑の「発送」をもう 1 回押すと外れます。

**一括発送**

1. 選んだラインの「欲しい」を全部出したら、「表示中のラインを全て発送済みに」を押します。
2. 「このラインの未発送品 ○ 件を、まとめて発送済みにしますか？」で「OK」を押します。
3. 訊かれたあとに変わった・増えた看板は動かさず、「飛ばした」と知らせます。

**在庫が無いとき(注文中にする)**

1. 仕入れ先へ注文したら、その看板の「注文中」を押します。黄になります(赤が付いている看板だけ押せます)。
2. 💬 を押して入る見込みを書き、「送る(倉庫として)」を押すとラインに伝わります。
3. 物が入ったら、いつもどおり「発送」を押します。注文中は自動で外れます。
4. 注文中をやめるときは、黄の「注文中」をもう 1 回押します。

**印刷する**

1. 「🖨 発送明細」(発送した物)か「🖨 非常設品リスト」を押します。右の数は押すたびに読み直します。
2. 印刷前の確認画面で、必要なら直します。
3. 「🖨 印刷する」を押します。発送明細は資材と一緒に渡します。

倉庫が書けるコメントは、黄か緑を付けたあと、現場が赤を消すまでです。赤だけのあいだは、現場のコメントへの返事だけ書けます。

### 設定・マスタ管理(班長・管理者)

**モードを変える**

1. 設定 →「この端末」の「モード」で使うモードを選びます(使えないモードには「(権限なし)」と出ます)。
2. 「いま切り替えますか？」で「OK」。書き戻しを済ませてから、そのモードで開き直します。

**看板を 1 枚増やす**

1. 設定 →「マスタ管理」で `看板_<ライン>` を選んで開きます。
2. 「+ 行を追加」を押します。管理番号には次の番号が入っています。
3. `資材` と `サイズ` を入れます。非常設品なら `常設品` を × に直します。
4. 「足す」を押し、管理者パスワードを入れます(認証済みなら訊かれません)。

**看板を消す**

1. 消したい看板が灰色(発注・発送・注文中のどれでもない)で、「未反映」が 0 なのを確かめます。
2. その行の右端の「削除」を押します。断られたら、出た理由のとおりに片付けてから消します。

**未反映が減らないとき**

1. 設定 →「取り込みの状態」→「↻ いま取り込む」を押します。
2. それでも減らなければ、一覧の理由を見て管理者に知らせます。

## 思想(設計の考え方)

資料に書かれている考え方を、短くまとめます。

- **正式なデータは 1 か所。** 共有の `看板マスタ.sqlite3` が正式なデータで、手元の SQLite は「その端末専用の作業用の写し + 送信待ちの一時置き場」です。写しを挟むのは「操作のたびに共有フォルダへ問い合わせると遅い」ためです。
- **手元に預かって、あとで送る。押し直さなくてよい。** 共有フォルダが見えないあいだに押したものは端末に預かり、見えたら送り直します。「押し直しは要らない」。続けて押しても捨てずに順番に送ります。
- **相手を上書きしない。** 書き戻しは行ではなく列単位です。現場が発注列を、倉庫が発送列を、同じ行に同時に書いても互いを上書きしません。
- **黙って捨てない・黙らない。** 届かない操作は帯で知らせ(「送りようの無い変更を、溜めたまま黙らない」)、取り消された発送は確認するまで出し直させません(「黙って出し直すと、倉庫が発送した物の行方が分からなくなる」)。消された看板への操作が届かなかったことも、帯で伝えます(VER3.5.6)。
- **動いている看板は消さない。** 発注中・発送済み・注文中の看板を消すと「その注文の行き場が無くなります」。
- **共有DBの書き方(型)を変えない。** 管理番号が数で入っていれば数のまま書きます(「管理番号の書き方は変えません」)。中身の入れ替えでも、表の定義(列・索引)は変えません。
- **判断はサーバ。** 「操作可否はサーバが決めます」。画面はボタンを出すだけで、押された側でも同じ判断をし直して確かめます。
- **状態の決まりは 1 か所で決める。** 状態の列と「発注中・発送済み・注文中か」は 1 つのファイルにまとめ、画面にも列名を書き写しません。
- **できないときは理由を出す。** 直せない表も隠さず「出さないのではなく、理由を出す」。
- **止まったら見えるようにする。** 「自動更新は、動かなくなったことが見えて初めて信用できます」。ただし「順調なときは何も出しません」。
- **押せる画面は 1 つだけ。** 2 つとも押せると、同じ看板を 2 画面で取り合い、片方が古い盤のまま押してしまうためです。
- **紙を直しても、データは動かさない。** 印刷前の直しは「共有 DB へは一切書きません」。
- **業務ルールは VBA 版のまま。** 変えた点(注文中は赤がある看板だけ、一括発送でも注文中を外す など)は、理由と一緒に移行仕様に書いてあります。

## モード説明

どのモードで開くかは、その端末に覚えさせます。使えるモードは、梱包資材マスタの「アクセス権限」の表(Windows のログインID と PC名)で決まります。画面の右上の札で、いまのモードが分かります。

| モード | なれる人・なり方 | できること | できないこと |
| --- | --- | --- | --- |
| 現場モード(赤い札) | 権限 `mode:field` の行がある人・PC。表に当てはまる行が無い端末は現場モードだけ。はじめて開いたときも現場モード | 担当ラインの看板を見る。発注・取り消し・届いた確認・一括確認。注文票の印刷。コメント | 発送・注文中を付ける。ほかのラインを見る |
| 倉庫モード(緑の札) | 権限 `mode:material` の行がある人・PC | 全ラインの看板をタブで見る(NS1 は出ない)。発送・注文中・一括発送。発送明細・非常設品リストの印刷。コメント | サイズのボタンで発注する |
| 倉庫参照モード(灰色の札、見るだけ) | だれでも(権限は要らない)。設定 →「この端末」で選ぶ | 看板を見る。コメントを読む | 押しても何も変わらない。コメントを書けない。「開いている端末」に名乗らない |
| 両方の権限がある端末 | 権限 `Administrator`、または `mode:field` と `mode:material` の両方 | 看板の画面の右上「⇄ 倉庫モードへ / ⇄ 現場モードへ」で、閉じずに切り替える(書き戻しを済ませてから開き直す。ブラウザ版は次に開いたときから) | — |
| 管理者(パスワード認証) | 管理者パスワードを知っている人。設定 →「パスワード認証」で認証する | 担当ライン・接続先の変更、マスタの編集、未反映の片付け、配布設定。認証すると、解除する・30 分さわらない・閉じる まで訊かれない | パスワードでモードは変えられない(モードはアクセス権限で決まる) |

- 当てはまる行が 1 つでもあると、その行のモードだけになります(`mode:material` だけ足すと現場モードは使えません)。倉庫の人が現場モードも使うなら `mode:field` の行も足します。
- 担当ラインは、`権限` の欄に書いたライン名(L-1・LVC・HVC・機側・AIM・コイル・トット・バランサー・NS1)で決まります。表の名前の `L1` `LS` `大板小板` は読みません。
- 権限の無いモードで開こうとすると、使えるモードで開き、画面の上に「なぜ・何を足せばよいか」を出します。
- 管理者パスワードを決めないまま置いておかないでください。最初に設定を変えようとした人が決められてしまいます。

## 用語

| 用語 | 意味 |
| --- | --- |
| 看板 | 資材 × サイズの 1 枚。共有DBの `看板_<ライン>` の 1 行 |
| 管理番号 | 看板を見分ける番号(キー)。マスタ管理では直せない |
| 欲 | 発注中(欲しい)の印。〇 なら赤 |
| 不 | 発注していない印。〇 なら灰色(新しい看板もこの形) |
| 更新日 | 現場が発注した日時 |
| 発送 | 倉庫が発送した印。〇 なら緑 |
| 倉庫確認日時 | 倉庫が発送にした日時 |
| 保留 / 注文中 | 倉庫に在庫が無く、仕入れ先へ注文した印。黄。列の名前は旧称の「保留」のまま |
| 注文中日時 | 注文中にした日時(自動で入る) |
| 常設品 / 非常設品 | いつも置いている資材 / いつも置いていない資材。常設品の欄が × なら非常設品で、青い斜めの字 |
| 担当ライン | 現場モードで見るライン。アクセス権限の表で決まる |
| 発送処理中に注文が取り消されました(取り消された発送) | 倉庫の発送と入れ違いに現場が赤を消し、「赤なし・緑あり」になった看板。現場が「確認した」を押すまで出し直せない |
| 一括確認 | 赤と緑が両方付いた看板を、まとめて元に戻す(現場) |
| 一括発送 | 選んだラインの未発送の「欲しい」を、まとめて発送済みにする(倉庫) |
| 共有DB | 共有フォルダの `看板マスタ.sqlite3`。正式なデータ |
| 作業用DB(手元の SQLite) | この端末だけの写しと、まだ送れていない操作の置き場 |
| 書き戻し | 手元の操作を共有DBへ送ること(押した直後と 60 秒ごと) |
| 取り込み | 共有DBの最新を手元へ写すこと(30 秒ごと。変わったらすぐにも) |
| 未反映 | まだ共有DBへ届いていない操作の数。ふつうは数秒で 0 に戻る |
| 要確認 | 5 回送っても届かず、自動では送らなくなった操作。待っても減らない |
| Form状態管理 | 各端末が「開いている」印を書く表。帯の「開いている端末」に出る |
| 開いている端末(`?` 付き) | `?` は、開いた印が残ったまま 10 分以上更新が無い端末(正しく閉じられなかった印) |
| 看板コメント | 💬 で書いたやり取り。共有DBの表に入る |
| 既読 | 相手が読んだ印。倉庫どうし・そのラインの現場どうしで共有する |
| 看板履歴 | 出した・発送・届いた などの記録。`看板履歴.sqlite3` に集まり、看板集計が読む |
| 提出率 | その月に 1 回以上出した看板の枚数 ÷ そのラインの看板の枚数 |
| 発送の無いライン(NS1) | 倉庫の画面に出ないライン。赤を消すと「届いた」として数える |
| アクセス権限 | 梱包資材マスタの表。ログインID・PC名ごとに使えるモードと担当ラインを決める |
| 配布設定 | 1 台で決めた設定を書き出して、ほかのパソコンへ配るしくみ |
