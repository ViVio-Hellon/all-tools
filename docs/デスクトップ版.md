# デスクトップ版(統合ツール.exe)の作り

4つのツールを1つの窓(Rust/Tauri)に大きなタブで並べる。**ポートを使わない。** 作りは python-web-tools
(梱包資材総合ツール VER4.0.0〜)と、看板・カレンダー・点検表の単体のデスクトップ版にそろえ、
「1つの窓に4つ」のための取り決めを足した。移行前の確認は [統合_事前確認.md](統合_事前確認.md)。

## 全体

```
統合ツール.exe(Rust/Tauri、src-tauri/)
 │  窓は1つ(1440×920)。画面は portal://localhost/(Windows は http://portal.localhost/)
 │
 ├─ 大きなタブの画面(portal/templates/shell.html + static/js/shell.js)
 │    ├─ 大きなタブ: /api/tabs(タブ表示権限で決まったもの)+ 大設定
 │    └─ 各ツールの画面 = iframe(nippou://localhost/ など)。ほかのタブの画面は消さずに隠す
 │
 ├─ 宛先ごとに受ける(register_asynchronous_uri_scheme_protocol。要求ごとに別のスレッド)
 │    portal     → 入口の Python   bridge.py(一式の直下)
 │    nippou     → 日報の Python   tools/nippou/bridge.py
 │    kanban     → 看板の Python   tools/kanban/bridge.py
 │    calendar   → カレンダー       tools/calendar/bridge.py
 │    inspection → 点検表           tools/inspection/bridge.py
 │
 └─ Python とは標準入出力(1件 = 見出し1行の JSON + 本文)。ソケットは1つも開かない
```

宛先をツールごとに分けるのは、各ツールの画面が `/api/…` `/static/…` のような**根元からの経路**で
書かれているため(1つの宛先の下に並べると経路がぶつかる)。宛先が分かれていれば、localStorage
(テーマ・タブの記憶)もツールごとに分かれる。

## 外枠(Rust)がすること

| ファイル | すること |
|---|---|
| `main.rs` | 窓・宛先の登録・同時起動の錠・閉じるときの確認・終わるときに全 Python を終える |
| `catalog.rs` | `config/tools.json`(入口と同じファイル)を読む。宛先の頭(`<名前>://localhost` / `http://<名前>.localhost`) |
| `bridge.rs` | Python の起動と監視。**開いたタブのツールだけ起こす**。Python は `<頭>_PYTHON` → `ALLTOOLS_PYTHON` → `python`/`py -3`(Windows)。起動できない理由(fatal)・知らせずに落ちた(最後の出力)を覚える |
| `relay.rs` | 要求1件を受ける。部品(`/static/…`・日報の `/sv/<版>/…`)は自分で返す。それ以外はそのツールの Python へ。Host・Origin・Referer を**単体のデスクトップ版と同じ形**(`app.localhost`)に直す。画面の移り先(302)は自分で移るページにする。ツールの画面(HTML)に台本(`embed.js`)を差し込み、はめ込みの守り(X-Frame-Options・CSP frame-ancestors)を外す |
| `pages.rs` | 外枠が出す画面: 起動しています / 理由の画面(理由・次の一手・使った Python・最後の出力・ログの場所・「もう一度開く」)/ 終了しました |
| `services.rs` | 画面からの頼みごと(下の表)・別窓・保存/選択のダイアログ・既定のブラウザ |
| `shell.rs` | 全ツールの Python・窓・状態(タブの印)・立て直し |
| `closing.rs` | 終わり方(下) |
| `instance.rs` | 同時起動の錠(Python の `portal/instance_guard.py` と同じ名前・同じ手順) |
| `statics.rs` | 部品をファイルから返す(版付きは長く控える) |
| `places.rs` | 一式のフォルダ(exe の上へたどって `bridge.py` と `config/tools.json` がある所)・手元の領域・外枠の記録 |

### 画面からの頼みごと

ツールの画面の `desktop.js` は今までどおり `window.__TAURI__.core.invoke("open_window", …)` を呼ぶ。
大きなタブの中(iframe)には Tauri の口が無い(OS で振る舞いも違う)ので、外枠が差し込む台本
(`portal/static/js/embed.js`)が `window.__TAURI__` の代わりになり、頼みごとを **大きなタブの画面へ
`postMessage`** で渡す。大きなタブの画面は**送り元の枠と宛先を確かめてから**外枠へ取り次ぐ
(`tool_invoke` / 本文がバイト列なら `tool_invoke_raw`)。別窓(帳票など)からは直に頼む。
**各ツールの `desktop.js` は書き換えていない。**

| 頼みごと | すること | 使うツール |
|---|---|---|
| `open_window` / `close_window` | そのツールの宛先の別窓(帳票・印刷・VC 早見表)。窓の名前は `report-<ツール>-…` | 日報・看板・カレンダー |
| `open_external` | アプリの外のページを既定のブラウザで | 全部 |
| `save_file` / `save_text_file` / `save_url` | 「名前を付けて保存」で保存(CSV・なぜなぜの材料など) | 看板・カレンダー |
| `pick_path` / `pick_folder` | OS の標準のフォルダ/ファイル選択 | 日報・看板・点検表 |
| `restart_app` | **そのツールの Python とタブだけ**立て直す(看板のモード切替) | 看板 |

台本はあわせて、1つの窓に並べたための手当てをする: **F5 / Ctrl+R はそのタブだけ**読み直す・
Ctrl+P はそのタブの画面を印刷・Alt+1〜9 で大きなタブを切り替え・アプリの外へのリンクは既定のブラウザ・
「画面が出た」(題名)を大きなタブの画面へ知らせる(入口のログに残る。起動確認に使う)。

## 終わり方(全ツールに訊いてから、まとめて終える)

1. 右上の「終了」・窓の ×・あるツールの画面の「終了」のどれでも、同じ道を通る
2. 動いている全ツール(と入口)に **訊くだけ** の問い合わせ(`/api/shutdown {"check": true}`)。まだ誰も止めない
3. 途中の処理(書き戻し・印刷・取り込み)があるツールがあれば、**1つの確認**にまとめて出す。やめたら何も止めない。
   **10秒待っても返事が無いツールも、ここに並べる**(「返事がありません(処理の途中かもしれません)」)。
   黙って「終わってよい」とはみなさない
4. 全ツールに終わってもらう(途中の処理があったときは `force`)。**訊いたあとで処理を始めたツール**
   (止める頼みに 409 と答えた)があれば、もう1度訊く。「終了する」でそのツールも `force`、「やめる」なら
   そのツールは動いたまま(終えたほかのタブには「終了しました / もう一度開く」)。各ツールが送り残しを
   送り終えて「終了してよい」を知らせてくるのを待つ(上限はツールごと: `config/tools.json` の `quit_wait_sec`)
5. 窓を閉じ、標準入力を閉じて Python に終わってもらう(並べて待つ。上限 `exit_grace_sec`。過ぎたら止める)

### 画面の確認ダイアログ(`confirm()`)はブラウザのもの

tauri-plugin-dialog は、画面の `window.confirm` / `alert` を**答えを待たない版**(Promise を返す)に
置き換える。すると `if (!confirm("消しますか?")) return;` は Promise を「はい」とみなし、**訊かずに進む**
(大設定の行を消す・看板の到着確認・日報の削除・各ツールの「終了」…)。しかも Windows の WebView2 は
初期化の台本を**全部の枠(各ツールの画面)**に入れる。外枠は `src-tauri/src/native_dialogs.js` を
**dialog より先に**全部の枠で走らせ、ブラウザのもの(答えを待つ)を書き換えられないように固定する。
各画面は「画面が出た」の知らせに `[確認ダイアログ: native]` を添え、起動確認がそれを見る
(`replaced` なら NG)。

あるツールが落ちたら、**そのタブだけ**理由の画面になる(ほかのタブはそのまま)。「もう一度開く」で
そのツールの Python だけ起こし直す。大設定の「ツール」にも状態と「もう一度開く」が出る。

## 同時に動かさない

| 錠 | 誰が持つ | 何を止める |
|---|---|---|
| 名前付きミューテックス `Local\nlm.all-tools.instance`(目印 `.desktop` / `.browser`) | 統合ツールの exe(Rust)/ ブラウザ版の入口(Python) | 統合のデスクトップ版 ⇔ 統合のブラウザ版(後から開いたほうが止まる)。exe 同士は窓を前に出す |
| 日報 `NippouTool\runtime\desktop.lock` | 日報の Python(デスクトップ版のとき) | 日報の単体のブラウザ版(`nippou.lock` を見る) |
| 看板 `KanbanSystem\runtime\desktop.lock` | 看板の Python | 看板の単体のブラウザ版(`<モード>.lock` を見る) |
| カレンダー `LineCalendar\runtime\desktop.lock` | カレンダーの Python | カレンダーの単体のブラウザ版(`instance.lock` を見る) |
| 点検表 `Local\nlm.inspection-sheet-print.*` | 点検表の Python | 点検表の単体のブラウザ版 |

どれも **自分の錠を取ってから相手を見る**ので、同時に開いても少なくとも一方が気づく。プロセスが終われば
OS が錠を外す(残った錠で起動できなくなることは無い)。名前付きミューテックスは、Microsoft Store 版の
Python のファイルの振り替えにも左右されない。

## 記録(なぜ動かないかを後から追う)

| 何 | どこ |
|---|---|
| 外枠の記録(Python が見つからない・起動できない・知らせずに落ちた・同時起動を止めた・終了) | `%LOCALAPPDATA%\AllTools\logs\desktop_shell.log` |
| 入口のログ(タブ表示権限・大設定の書き換え・画面のエラー・各タブの画面が出た) | `%LOCALAPPDATA%\AllTools\logs\portal_YYYYMMDD.log` |
| 各ツールのログ | 今までどおり(各ツールの手元の領域。大設定の「ツール」に場所が出る) |

## 作り方

GitHub Actions の「デスクトップ版(Windows)」(`.github/workflows/desktop-windows.yml`)が、push のたびに
入口と4ツールの試験・Rust の試験・exe を作る・**作った exe を起動して確かめる**(`scripts/desktop_smoke.py`)
までを流し、成果物 **AllTools-windows** に `AllTools.exe` を置く。手元で作るときは:

```
cd src-tauri
cargo test
cargo build --release        → src-tauri\target\release\AllTools.exe
```

開発中は exe を `src-tauri\target\…` から動かしてよい(上へたどって一式のフォルダを見つける。
`ALLTOOLS_ROOT` で指定もできる)。`--demo` を付けると点検表が模擬の点検表で動く。

### 起動確認(`scripts/desktop_smoke.py`)が確かめること

1. 大きなタブの画面が入口の Python から届き、画面の JS が動く
2. 4つのツールの**本体の画面**が、それぞれの Python から大きなタブの枠の中に届く
3. 入口と4つのツールの Python が動いていて、**どのプロセスもポートで待ち受けていない**
4. 統合のブラウザ版・各ツールのブラウザ版が、後から開けば止まる
5. exe を止めると Python も終わる
6. 大きなタブと各ツールの画面の確認ダイアログ(`confirm` など)が、ブラウザのもの(答えを待つ)のまま

### Linux(開発機)で動かすとき

WebKitGTK では、窓の `on_navigation` に**枠(iframe)の中の移動も来る**(Windows の WebView2 は窓そのものの
移動だけ)。外枠は Linux では各ツールの宛先を通す(Windows では窓そのものがツールの宛先へ移らないよう通さない)。
`xvfb-run -a python scripts/desktop_smoke.py --exe src-tauri/target/debug/AllTools` で確かめられる。

## Windows の実機で人が見ること(この開発環境では確かめられない)

- iframe の中から出す確認のダイアログ(`confirm()`)・クリップボード・音(日報)
- 帳票の「印刷する」から紙が出ること・Ctrl+P
- ドラッグ&ドロップ(看板の中身の入れ替え・日報の取り込み)
- 保存ダイアログ・フォルダ選択(共有フォルダを辿れること)
- **Microsoft Store 版の Python で、ブラウザ版とデスクトップ版が互いに止め合うこと**
- Access(cscript)・Excel の実物での反映・印刷
