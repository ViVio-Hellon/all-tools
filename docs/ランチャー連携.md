# ランチャー連携 — 統合ツール側の取り決め

業務ツール統合ランチャー([python-business-tools-launcher](https://github.com/ViVio-Hellon/python-business-tools-launcher))
から、統合ツールを **1つのツールとして** 起動・終了するための、統合ツール側の取り決めです
(ランチャー連携 要件定義の「3. 各ツール側への依頼」)。

- 日報・看板・カレンダー・点検表は **統合ツールの中**(大きなタブ)で動きます。ランチャーには
  統合ツールだけを登録します
- ランチャーは統合ツールの中身(exe → Python → 各ツール)を知る必要がありません。下の起動ファイルを
  実行し、下の方法で起動を確かめ、下の方法で止めるだけです
- 確かめたランチャーの版: 1.6.4(`621a7fe`)

## 1. 起動ファイル(要件 3.1・3.3)

| 起動ファイル | 中身 | 画面 | 使うとき |
|---|---|---|---|
| **`統合ツール.exe`** | デスクトップ版(Rust/Tauri の窓)。入口と各ツールの Python を自分で起こす。**ポートを使わない** | 統合ツール自身の窓 | **ふだんはこれ** |
| `Start.vbs` | ブラウザ版(予備)。`pythonw start_app.py` を起こして**すぐ戻る**(引数は渡さない) | ふだんのブラウザーに統合ツールが開く | exe が使えない PC |
| `start.bat` | ブラウザ版の診断用の入口。`python start_app.py %*`(止まるまで戻らない。最後の `pause` はランチャーから呼べば素通り) | `--no-browser` を渡せばランチャーが開く | 下の「start.bat を勧めない理由」を参照 |

どれも、ダブルクリックでも、ランチャーから直接実行しても同じように起動します。exe から先
(Python の起動・各ツールの起動・ブラウザを開く)は統合ツールが受け持ちます。

**ランチャーに登録しないもの**

- `tools\<ツール>\Start.vbs` などの、統合ツールの中の各ツールの起動ファイル(統合ツールが自分で起こす)
- 同じ PC の、単体の日報・カレンダー・看板(`vba-*-python-migration`)。アプリID と手元の領域
  (`%LOCALAPPDATA%\NippouTool` など)が統合ツールの中のものと同じで、互いを「古い版」とみなして
  止め合います

## 2. 起動の確かめ方(要件 3.2・10)

| 起動ファイル | 起動したとみなす合図 |
|---|---|
| `統合ツール.exe` | **統合ツールの窓が出たこと**(待ち受けるポートは無い) |
| `Start.vbs` / `start.bat` | `GET http://127.0.0.1:<port>/api/health` が `app_id: "nlm.all-tools"` と `ready: true` を返すこと |

ブラウザ版の `/api/health`(起動トークン不要):

```json
{"app_id": "nlm.all-tools", "display_name": "統合ツール", "version": "1.2.0",
 "edition": "browser", "app_root": "C:\\業務ツール\\統合ツール", "pid": 1234, "ready": true}
```

- ポートは `config\app.json` の `server.port`(8700)から空いている番号(8700〜8709)
- 実際の番号と停止用のトークンは `%LOCALAPPDATA%\AllTools\runtime\portal.lock`(JSON: `port` `token` `pid` `url`)
- `app_root` はランチャーが止める前に「本当に統合ツールか」を照合するのに使います

## 3. 止め方(要件 3.5・3.6)

**ランチャー側に個別の止め方は要りません。** 専用の `launcher_stop.bat` も作っていません ──
exe は窓の ×、ブラウザ版は今ある `stop.bat` / `POST /api/shutdown` が、そのまま停止の入口です。

| 起動ファイル | 止める入口 | 中で起きること |
|---|---|---|
| `統合ツール.exe` | **窓に「閉じて」と頼む**(× と同じ `WM_CLOSE`) | 各ツールの画面に打ちかけを置いてもらう → 全ツールに「終わってよいか」を訊く → 途中の処理があれば1つの確認 → 全ツールを終えて窓を閉じる |
| `Start.vbs` / `start.bat` | `stop.bat`(→ `process_manager.py`)または `POST /api/shutdown` | **開いている画面に打ちかけを置いてもらう**(下)→ 途中の処理が無ければ入口と各ツールのブラウザ版を止める |

`POST /api/shutdown`(ヘッダ `X-Tool-Token: <portal.lock の token>`、本文 `{"force": false}`)の答え:

| 答え | 意味 |
|---|---|
| 200 `{"stopped": true}` | 止めます(0.4 秒後) |
| 409 `{"reason": "asking", "running": [...]}` | 開いている画面に「打ちかけを置いてから閉じて」と頼みました。**置けたら統合ツールが自分で終わります**。画面に確認が出ていれば本人が答えます |
| 409 `{"reason": "refused", "running": [...]}` | 画面で本人が「閉じない」を選びました(保存していない入力がある)。止めません |
| 409 `{"reason": "busy", "running": [...]}` | 途中の処理(書き戻し・印刷・取り込み)があります。止めません |
| `{"force": true}` | 画面にも途中の処理にも訊かずに止めます(本人が強制終了を選んだときだけ) |

`stop.bat` の戻り値: 0 = 止まった / 2 = 止めなかった(上の 409。「頼みました」のときは 15 秒まで
終わるのを待ってから返す)/ 1 = デスクトップ版が動いている(`stop.bat` はデスクトップ版を止めない。窓を前に出す)。

**ほかの Python・exe・VBS は止めません。** 止めるのは `portal.lock` の入口と、入口が起こした各ツールの
ブラウザ版だけ(それぞれ自分の止め方で)。

### ブラウザ版の画面の打ちかけ(今回足したもの)

以前は、外から(ランチャー・`stop.bat`)止められると、**開いたままの画面の打ちかけが消えました**
(日報の打ちかけの行・看板のコメント・大設定の入力)。画面の「終了」ボタンだけが、止める前に各ツールの
画面へ「打ちかけを置いて」と頼んでいたためです。

いまは外からの停止でも、同じ頼みを通ります。

1. 入口は、開いている画面(毎秒「頼まれていないか」をたずねに来る)に頼みを出し、3 秒だけ返事を待つ
2. 画面は「置いています」と返し、各ツールの画面に打ちかけを置いてもらう(置けなければツールが
   「続けますか?」と訊く)。大設定の打ちかけも訊く
3. 全部置けた → 止める。本人が「閉じない」を選んだ → 止めない。3 秒で済まなかった → 409 `asking` を返し、
   置けたところで入口が自分で止まる(頼みは 2 分で取り下げ)
4. 画面が無い(閉じた・開いていない)ときは、待たずに止める

## 4. ランチャーの設定の勧め

| 起動ファイル | 画面 | ポート | 起動引数 | 止め方 |
|---|---|---|---|---|
| `統合ツール.exe` | アプリの窓(exe を選ぶと自動で決まる) | **空にする** | 空 | 自動 |
| `Start.vbs` | ブラウザー(自動) | 8700(app.json から入る) | 空(渡せない) | 自動(`stop.bat`) |

- **exe の行はポートを空にしてください。** ランチャーは exe の隣の `config\app.json` からブラウザ版の
  ポート 8700 を読み取ります。デスクトップ版は待ち受けないので、そのままだと 90 秒後に「起動確認に
  答えません」と知らせが1回出ます(動きは正しい)。exe とブラウザ版が同じ `config\app.json` を使うため、
  統合ツール側では分けられません
- 1台の PC には **exe か Start.vbs のどちらか1つ** を登録します(同じアプリID は2行にできません。
  デスクトップ版とブラウザ版は同時には動きません)。PC ごとに配布先設定で選びます

### start.bat を勧めない理由

`start.bat` を登録すると、ランチャーは `--no-browser` を渡して自分の専用画面を開き、止めるときに
**その画面を先に閉じてから** 統合ツールを止めます。画面が閉じられる瞬間の保存は各ツールの
「閉じ際の保存」(日報は `pagehide` で打ちかけを送る、看板・カレンダーは下書きを残す)頼みになり、
ブラウザーが閉じきれずに強制終了されると、日報の最後の自動保存からあとの打ちかけが残らないことが
あります。`Start.vbs` なら画面は閉じられず、上の「打ちかけを置いてもらう」頼みを必ず通ります
(止めたあとの画面には「終了しました」が出るので、タブは手で閉じます)。

## 5. 確かめたこと

ランチャーの実物のコード(`launcher.health`・`process_manager.stop`)で、統合ツールのブラウザ版
(実物の入口と4ツール)を起動・停止しました(Linux・Chromium)。

| 場面 | 結果 |
|---|---|
| 起動の確かめ(`/api/health` の `app_id` 照合) | 1.0 秒で確認 |
| 停止用トークンの読み取り(`portal.lock`) | 読めた |
| 打ちかけなしで停止(停止方法 自動) | 4つのツールの画面すべてが「閉じる前の頼み」に答えてから止まった(3.1 秒)。各ツールのブラウザ版も残らない |
| 大設定に打ちかけ → 画面で「閉じない」 | 止めない(409)。次の停止で訊き直す |
| 画面を閉じたあとに停止 | 待たずに止まる(0.9 秒) |
| `stop.bat`(`process_manager.py`)で停止 | 画面に頼んでから止まる(1.1〜3 秒) |

デスクトップ版(exe)を窓の × で閉じる流れは、これまでの試験と Windows の CI の起動確認
(`scripts/desktop_smoke.py`)で確かめています。ランチャーが `WM_CLOSE` を送る経路は × と同じです。
Windows の実機では、ランチャーから exe を起動・停止して、窓の打ちかけの確認が出ることを見てください。
