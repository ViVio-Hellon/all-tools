# ランチャー連携 — 日報複合ツール側の取り決め

業務ツール統合ランチャー([python-business-tools-launcher](https://github.com/ViVio-Hellon/python-business-tools-launcher))
から、日報複合ツールを **1つのツールとして** 起動・終了するための、日報複合ツール側の取り決めです
(ランチャー連携 要件定義の「3. 各ツール側への依頼」)。

- 日報・看板・カレンダー・点検表は **日報複合ツールの中**(大きなタブ)で動きます。ランチャーには
  日報複合ツールだけを登録します
- ランチャーは日報複合ツールの中身(exe → Python → 各ツール)を知る必要がありません。下の起動ファイルを
  実行し、**日報複合ツールが用意した入口**(`launcher_check.bat`・`launcher_stop.bat`)で起動を確かめ・止めるだけです
- 確かめたランチャーの版: **1.7.1**(`0778df1`。ツール側の入口を、ランチャーの推測より優先して使う版)。
  1.6 系(入口を使わない版)でも動きます(下の 2・3 の「入口が無いとき」)

```
日報複合ツール\
├─ 日報複合ツール.exe        起動ファイル(PC ごとに［設定］でどちらかを選ぶ)
├─ Start.vbs             起動ファイル
├─ launcher_check.bat    起動確認の入口(1.3.0 から)
└─ launcher_stop.bat     終了の入口(1.3.0 から)
```

exe と Start.vbs のどちらを選んだ PC でも、同じフォルダーの入口が使われます。入口は
デスクトップ版・ブラウザ版のどちらが動いていても、自分で見分けて答えます。

> 1.4.0 で名前を「統合ツール」から「日報複合ツール」に変えました。ランチャーに `統合ツール.exe` を登録している PC は
> `日報複合ツール.exe` に差し替えてください(`launcher_check.bat`・`launcher_stop.bat` は名前が変わらないので、そのまま使えます)。

## 1. 起動ファイル(要件 3.1・3.3)

| 起動ファイル | 中身 | 画面 | 使うとき |
|---|---|---|---|
| **`日報複合ツール.exe`** | デスクトップ版(Rust/Tauri の窓)。入口と各ツールの Python を自分で起こす。**ポートを使わない** | 日報複合ツール自身の窓 | **ふだんはこれ** |
| `Start.vbs` | ブラウザ版(予備)。`pythonw start_app.py` を起こして**すぐ戻る**(引数は渡さない) | ふだんのブラウザーに日報複合ツールが開く | exe が使えない PC |
| `start.bat` | ブラウザ版の診断用の入口。`python start_app.py %*`(止まるまで戻らない。最後の `pause` はランチャーから呼べば素通り) | `--no-browser` を渡せばランチャーが開く | 下の「start.bat を勧めない理由」を参照 |

どれも、ダブルクリックでも、ランチャーから直接実行しても同じように起動します。exe から先
(Python の起動・各ツールの起動・ブラウザを開く)は日報複合ツールが受け持ちます。

**ランチャーに登録しないもの**

- `tools\<ツール>\Start.vbs` などの、日報複合ツールの中の各ツールの起動ファイル(日報複合ツールが自分で起こす)
- 同じ PC の、単体の日報・カレンダー・看板(`vba-*-python-migration`)。アプリID と手元の領域
  (`%LOCALAPPDATA%\NippouTool` など)が日報複合ツールの中のものと同じで、互いを「古い版」とみなして
  止め合います

## 2. 起動の確かめ方(要件 3.2・10)

**`launcher_check.bat`**(`python process_manager.py --check`)。ランチャーが繰り返し呼びます。

| 終了コード | 意味 | 見ているもの |
|---|---|---|
| `0` | 使える | デスクトップ版: 錠(`Local\nlm.all-tools.desktop`)と大きなタブの窓が出ている / ブラウザ版: `/api/health` が `app_id: "nlm.all-tools"`・`ready: true` |
| `2` | 準備中 | デスクトップ版: 錠はあるが窓がまだ / ブラウザ版: 起動中(錠・`portal.lock` はあるが答えない) |
| `1` | 動いていない | どちらの錠も無い |

最後の1行(「デスクトップ版が動いています」など)が、ランチャーの起動中の窓に出ます。
`pause` は置いていません。数秒で終わります(Python の起動と、ブラウザ版なら `/api/health` を1回)。

入口を使わないランチャー(1.6 系)では、デスクトップ版は**窓が出たこと**、ブラウザ版は
`GET http://127.0.0.1:<port>/api/health` で確かめます。ブラウザ版の `/api/health`(起動トークン不要):

```json
{"app_id": "nlm.all-tools", "display_name": "日報複合ツール", "version": "1.3.0",
 "edition": "browser", "app_root": "C:\\業務ツール\\日報複合ツール", "pid": 1234, "ready": true}
```

- ポートは `config\app.json` の `server.port`(8700)から空いている番号(8700〜8709)
- 実際の番号と停止用のトークンは `%LOCALAPPDATA%\AllTools\runtime\portal.lock`(JSON: `port` `token` `pid` `url`)
- `app_root` はランチャーが止める前に「本当に日報複合ツールか」を照合するのに使います

## 3. 止め方(要件 3.5・3.6)

**`launcher_stop.bat`**(`python process_manager.py --launcher`)。**ランチャー側に個別の止め方は要りません。**

| 動いているもの | `launcher_stop.bat` がすること | 終了コード |
|---|---|---|
| デスクトップ版 | **大きなタブの窓に「閉じて」と頼む**(`WM_CLOSE`。窓の × と同じ流れ: 各ツールの画面に打ちかけを置いてもらう → 全ツールに「終わってよいか」を訊く → 途中の処理があれば1つの確認 → 全ツールを終えて窓を閉じる)。**プロセスは落とさない**。16 秒まで閉じるのを待つ | 閉じた → `0` / 確認に答えていない → `3`「日報複合ツールの窓で、閉じてよいかの確認をしています(窓を見て答えてください)」 / 窓が見つからない → `1` |
| ブラウザ版 | `stop.bat` と同じ: **開いている画面に打ちかけを置いてもらう**(下)→ 途中の処理が無ければ入口と各ツールのブラウザ版を止め、**プロセスが居なくなったのを確かめる** | 止めた → `0` / 処理中・画面で確認中・「閉じない」 → `3` / そのほか → `1` |
| どちらも動いていない | 何もしない | `0`「日報複合ツールは動いていません」 |

- **標準出力は理由の1行だけ**(1.8.9 は1行目、1.7 は最後の1行を理由として見せる。1行なのでどちらにも合う)。
  途中の経過は標準エラーへ出します。例: `実行中の処理があります: 日報(標準作業時間の取り込み)、看板(共有DBへ未反映の操作が 3 件あります)`
- `0` 以外が返ると、ランチャーは理由を添えて「強制終了しますか」を利用者に訊き(1.8.9 の「更新のため全 PC で止める」では
  利用者に「保存してから終了してください」と知らせて 1 分ごとに止め直し、管理者が PC ごとに強制終了を頼める)、
  強制終了なら `launcher_stop.bat --force` で呼び直します。
  - ブラウザ版: 画面にも途中の処理にも訊かずに止める(入口・ツールが 6 秒で終わらなければ子ごと止める)
  - デスクトップ版: 窓に「閉じて」と頼み、6 秒で閉じなければ **exe を子ごと止めます**(`taskkill /T /F`。
    外枠・入口・4ツールの Python すべて。途中の処理は捨てる)。外枠には外から「確認なしで閉じて」と頼む道が
    無い(ポートを使わない)ためです。止めるのはこの利用者のログオンの `日報複合ツール.exe` だけ。
    以前(1.3.0〜)は `1`(「ランチャーの止め方で続けます」)を返してランチャーに任せていました
  - PID で止めたときは、点検表が起こした Excel の残り(記録した PID だけ)も片付けます
    (`tools\inspection\process_manager.py --cleanup-excel`)
- `stop.bat` は今までどおり**デスクトップ版の窓を閉じません**(窓を前に出して `1`)。`stop.bat --force` のときだけ、
  上と同じように止めます
- 入口を使わないランチャー(1.6 系)は、exe なら窓に「閉じて」と頼み、ブラウザ版なら `stop.bat` →
  `POST /api/shutdown` で止めます(中で起きることは上と同じ)

`POST /api/shutdown`(ヘッダ `X-Tool-Token: <portal.lock の token>`、本文 `{"force": false}`)の答え:

| 答え | 意味 |
|---|---|
| 200 `{"stopped": true}` | 止めます(0.4 秒後) |
| 409 `{"reason": "asking", "running": [...]}` | 開いている画面に「打ちかけを置いてから閉じて」と頼みました。**置けたら日報複合ツールが自分で終わります**。画面に確認が出ていれば本人が答えます |
| 409 `{"reason": "refused", "running": [...]}` | 画面で本人が「閉じない」を選びました(保存していない入力がある)。止めません |
| 409 `{"reason": "busy", "running": [...], "tools": [...], "line": "..."}` | 途中の処理(書き戻し・印刷・取り込み)があります。止めません。`tools` はツールごとの `title`・`reason`(何をしているかの短い1行)・`message`、`line` は止める入口の1行目 |
| `{"force": true}` | 画面にも途中の処理にも訊かずに止めます(本人が強制終了を選んだときだけ) |

`stop.bat` の戻り値(`process_manager.py` の戻り値をそのまま返す):
0 = 止めた・動いていない / 3 = 処理中なので止めなかった(上の 409。「頼みました」のときは 15 秒まで終わるのを
待ってから返す。受け付けたのに入口・ツールが終わりきらないときも)/ 1 = そのほか(デスクトップ版が動いている・
Python が見つからない・入口が答えない)。1.3.0〜1.5.84 は 0 / 1 デスクトップ版 / 2 止めなかった / 3 Python が無い でした。

**ほかの Python・exe・VBS は止めません。** 止めるのは `portal.lock` の入口と、入口が起こした各ツールの
ブラウザ版だけ(それぞれ自分の止め方で)。

**残っていた印の片付け(PID の使い回し)。** 印(`portal.lock`・各ツールの `runtime\*.lock`)には PID と、
そのプロセスの**起動した時刻**(`process_started`。Windows は `GetProcessTimes` の作成時刻)を書きます。
PID と起動時刻の両方が合うときだけ「動いている」とみなします。動いたまま PC を終了・再起動すると印が残り、
再起動のあとで**別のプログラムが同じ PID を持つ**ことがあります(Windows は PID を使い回す)。以前はそれを
「動いている」と見て、`stop.bat` が「入口が停止の頼みに答えません」(`1`)で終わり、印も消しませんでした
(`--force` ならその別のプログラムを止めていました)。

- 印の PID が居ない・別のプログラム → 印だけ片付けて `0`(1行目「日報複合ツールは動いていません(残っていた
  前回の印を片付けました)」)。ログと標準エラーに「片付けました。Start.vbs で起動できます」
- 前の版が書いた印(起動時刻が無い)は、「印を書いた時刻(ファイルの更新時刻)より後に起動したプロセスは、
  書いた本人ではない」とみなします
- 印の本人(起動時刻まで合う)に接続できず、5 秒たっても答えない → **本人だけ**を止めて印を片付け、`0`
  (同じログ)。関係のないプログラムは止めません
- 読めない印(書きかけ・掴まれている)は消しません
- 起動(`Start.vbs`・各ツールの起動)も同じ: 前回の印なら片付けて普通に起動し、答えない本人は 5 秒で止めてから
  起動し直します(`portal/proc_identity.py`・各ツールの `launch_guard.py` の `lock_owner`)

### ブラウザ版の画面の打ちかけ(今回足したもの)

以前は、外から(ランチャー・`stop.bat`)止められると、**開いたままの画面の打ちかけが消えました**
(日報の打ちかけの行・看板のコメント・大設定の入力)。画面の「終了」ボタンだけが、止める前に各ツールの
画面へ「打ちかけを置いて」と頼んでいたためです。

いまは外からの停止でも、同じ頼みを通ります。

1. 入口は、開いている画面(毎秒「頼まれていないか」をたずねに来る)に頼みを出し、3 秒だけ返事を待つ
2. 画面は「置いています」と返し、各ツールの画面に打ちかけを置いてもらう(置けなければツールが
   「続けますか?」と訊く)。大設定の打ちかけも訊く
3. 全部置けた → 止める。本人が「閉じない」を選んだ → 止めない。3 秒で済まなかった → 409 `asking` を返し、
   置けたところで入口が自分で止まる(頼みは 2 分で取り下げ)
4. 画面が無い(閉じた・開いていない)ときは、待たずに止める

## 4. ランチャーの設定の勧め

［設定］で選ぶのは**起動ファイルだけ**です。ほかは選んだときに自動で入ります。

| 起動ファイル | 画面 | ポート | 起動引数 | 止め方 |
|---|---|---|---|---|
| `日報複合ツール.exe` | アプリの窓(自動) | 空(1.7.1 は exe を選ぶと空のまま) | 空 | 入口(`launcher_stop.bat`) |
| `Start.vbs` | ブラウザー(自動) | 8700(app.json から入る) | 空(渡せない) | 入口(`launcher_stop.bat`) |

- ［設定］の行に「ツールの入口: 起動確認 launcher_check.bat・終了 launcher_stop.bat」と出れば、
  ランチャーは入口を見つけています
- 1.6 系のランチャーで exe を登録したときは、ポートを手で空にしてください(ブラウザ版のポート 8700 が
  入り、90 秒後に「起動確認に答えません」と知らせが1回出ます)
- 1台の PC には **exe か Start.vbs のどちらか1つ** を登録します(同じアプリID は2行にできません。
  デスクトップ版とブラウザ版は同時には動きません)。PC ごとに配布先設定で選びます

### start.bat を勧めない理由

`start.bat` を登録すると、ランチャーは `--no-browser` を渡して自分の専用画面を開き、止めるときに
**その画面を先に閉じてから** 日報複合ツールを止めます。画面が閉じられる瞬間の保存は各ツールの
「閉じ際の保存」(日報は `pagehide` で打ちかけを送る、看板・カレンダーは下書きを残す)頼みになり、
ブラウザーが閉じきれずに強制終了されると、日報の最後の自動保存からあとの打ちかけが残らないことが
あります。`Start.vbs` なら画面は閉じられず、上の「打ちかけを置いてもらう」頼みを必ず通ります
(止めたあとの画面には「終了しました」が出るので、タブは手で閉じます)。

## 5. 確かめたこと

ランチャーの実物のコード(1.7.1 の `launcher.tool_entries`・`process_manager.stop`、1.6.4 の
`launcher.health`)で、日報複合ツールのブラウザ版(実物の入口と4ツール)を起動・停止しました(Linux・Chromium)。

**入口を使う(1.7.1)**

| 場面 | 結果 |
|---|---|
| exe を選んだときの登録 | ポートは空、画面はアプリの窓 |
| 起動前の起動確認 | `1`「動いていません」 |
| 起動したあとの起動確認 | `0`「ブラウザ版が動いています」 |
| 大設定に打ちかけ → 画面で「閉じない」 | `launcher_stop.bat` が `1`。ランチャーに「日報複合ツールの画面で「閉じない」が選ばれました(保存していない入力があります)」が渡る。止めない |
| 打ちかけなし | `launcher_stop.bat` で止まり(3.7 秒)、起動確認が `1` に戻る |
| デスクトップ版 | Windows の CI(`scripts/desktop_smoke.py`)で、起動確認 `0` → `launcher_stop.bat` と同じ処理で窓が閉じる → 起動確認 `1` を確かめる |

**入口を使わない(1.6.4)**

| 場面 | 結果 |
|---|---|
| 起動の確かめ(`/api/health` の `app_id` 照合) | 1.0 秒で確認 |
| 停止用トークンの読み取り(`portal.lock`) | 読めた |
| 打ちかけなしで停止(停止方法 自動) | 4つのツールの画面すべてが「閉じる前の頼み」に答えてから止まった(3.1 秒)。各ツールのブラウザ版も残らない |
| 大設定に打ちかけ → 画面で「閉じない」 | 止めない(409)。次の停止で訊き直す |
| 画面を閉じたあとに停止 | 待たずに止まる(0.9 秒) |
| `stop.bat`(`process_manager.py`)で停止 | 画面に頼んでから止まる(1.1〜3 秒) |

Windows の実機では、ランチャーから exe を起動・停止して、打ちかけがあるとき窓に確認が出て、
答えるまで閉じないことを見てください。

## 6. 更新でフォルダーを丸ごと上書きされても残るもの(ランチャー 1.8.9 の 2・3・5)

ランチャー 1.8.9 は「更新のため全 PC で止める」で全 PC のツールを止めてから、共有サーバーの一式のフォルダーを
**丸ごと上書き**します。日報複合ツールと4ツールは、**動いているあいだ一式のフォルダーに何も書きません**
(管理者がわざと書き出す「配布設定」だけが例外。下)。

| 物 | 置き場所 | 一式の中/外 |
|---|---|---|
| 作業用DB(日報 `nippou_local.sqlite3`・看板 `kanban.sqlite3`・カレンダー `calendar.db`) | `%LOCALAPPDATA%\<ツール>\data\` | 外(PC ごと) |
| この端末の設定(大設定 `user_settings.json`・日報 `user_config.json`・カレンダー `settings.json`・点検表 `user_settings.json`) | `%LOCALAPPDATA%\<ツール>\` の下 | 外(PC ごと) |
| 看板のこの端末の設定 | `%APPDATA%\KanbanSystem\config.json` | 外(PC ごと) |
| ログ・起動の記録・錠/PID・写し(cache)・一時ファイル・控え(backup) | `%LOCALAPPDATA%\<ツール>\logs` `runtime` `cache` `work` `backup` | 外(PC ごと) |
| Python の .py の写し(`__pycache__`) | `%LOCALAPPDATA%\<ツール>\pycache\`(入口が `sys.pycache_prefix` を向ける) | 外(PC ごと) |
| 共有の DB・ログの出力パス・CSV の出力先 | 大設定・各ツールの設定で決めた場所 | 外(共有・利用者が選んだ場所) |
| 印刷用の HTML・書き出したファイル(CSV・名前を付けて保存) | 利用者が選んだ場所・`%LOCALAPPDATA%\<ツール>\` の下(work・export・data\print)・`%TEMP%` | 外 |
| 既定値(`config\app.json`・`config\tools.json`・点検表 `config\inspection.json`) | 一式の中 | 中(読むだけ。版と一緒に変わる) |
| 配布設定(`配布設定\`・`tools\<ツール>\配布設定\`) | 一式の中 | 中(管理者が書き出す) |

`<ツール>` は `AllTools`(入口)・`NippouTool`・`KanbanSystem`・`LineCalendar`・`InspectionSheetPrint`
(各 `config\app.json` の `local_dir_name`)。Microsoft Store 版の Python では `%LOCALAPPDATA%\Packages\PythonSoftwareFoundation.Python…\LocalCache\Local\` の下になります。

- **既定値と現場で変えた値は分かれています。** 既定は一式の中(版と一緒に更新)、現場で変えた値は外。
  外に値があればそれ、無ければ中の既定が効きます(点検表の点検表フォルダなど)
- **`__pycache__`**: 以前は入口(`start_app.py`・`bridge.py`)・日報・`launcher_check.bat` などが、一式のフォルダーの
  `__pycache__` に書いていました(共有に置くと全部の PC が同じ所へ書き、書きかけの .pyc が上書きを止める)。
  いまは起動の入口が手元の `pycache` へ向け、止める・確かめるだけの短い入口(`process_manager.py`・
  `export_distribution.py`)は書きません。前の版が作った `__pycache__` は、更新の上書きで消して構いません
  (中身は .py から作り直せる写しです)
- 看板の一時期の版がアプリのフォルダーに置いた `data\config.json` は、初回の起動で `%APPDATA%` の設定へ
  引き継ぎます(読めない回は引き継がず、印も付けない)
- 日報・カレンダーの設定画面で**相対の道**(`logs` `出力\集計` など)を書くと、一式のフォルダーからたどります。
  ログ・CSV の出力先などの**書く先**は、絶対の道(`\\サーバ\共有\…`・`C:\…`)で決めてください(相対だと一式の中に書き、更新で消えます)
- `.venv` は作りません(Python は PC に入っているものを使い、足りないパッケージは `pip install` で PC に入れる)
- 試験: 各ツールの `tests/test_update_overwrite.py`(一式の写しを作り、本物の入口を動かして一式のフォルダーに
  何も増えないこと・設定と作業用DBを作ってから一式を消して置き直しても残ること)

**配布設定**は、大設定の「まとめて書き出す」が一式の直下の `配布設定\`、各ツールの設定画面が
`tools\<ツール>\配布設定\` に書きます。配るために**わざと一式に入れる**物なので、更新に使う一式(更新元)にも
入れておいてください。更新元に無いと、丸ごと上書きしたときに消えます(すでに読み込んだ PC の値は残ります)。

## 7. 止める入口の決まり(ランチャー 1.8.9 の 1・4・5)

ランチャー 1.8.9 の「更新のため全 PC で止める」は、ふだんの［ツール停止］と同じ手順で止めます。日報複合ツールでは
**`launcher_stop.bat`**(ランチャー 1.7 以降は、ツールの入口をランチャーの推測より先に使う)。
単体で起動した4ツール(`tools\<ツール>\Start.vbs`)は、それぞれの `stop.bat` です。

| 入口 | 止めた・動いていない | 処理中で止めない(1行目が理由) | そのほか | `--force` | pause |
|---|---|---|---|---|---|
| `launcher_stop.bat` | `0` | `3` | `1` | 4ツール・入口・外枠(exe)すべて | 置かない |
| `stop.bat`(直下) | `0` | `3`(どのツールの何の処理か) | `1`(デスクトップ版の窓は閉じない) | 同上 | 失敗したときだけ。`/nopause`・`STOP_NOPAUSE=1` で飛ばす |
| `tools\<ツール>\stop.bat` | `0` | `3`(例「実行中の処理があります: 印刷」) | `1` | そのツールを処理中でも止める | 同上 |

- **管理者以外停止モード中**(下の 8)は、動いていれば止めずに `3`、1行目「止めませんでした: 管理者以外停止モード中のため、
  stop.bat(ランチャーの「全 PC で止める」)では止めません。…」(`--force` でも。動いていなければいつもどおり `0`)。
  **お願いを出した PC では断らない**(その PC は止めないので、管理者が自分の PC をふつうに止めて更新する)
- 1行目の理由は、各ツールの「処理中」の答え(`/api/shutdown` の 409 の `running`、看板は未反映の件数)を1行にしたもの:
  日報「標準作業時間の取り込み」など、看板「共有DBへ未反映の操作が 3 件あります」、カレンダー「取り込み元との同期」、
  点検表「印刷」「プレビューの作成」。看板は停止の頼みに答えないときも、書き戻しの途中かもしれないので止めずに `3`
  (「停止の頼みに答えません(処理の途中かもしれません)」)
- **cp932 の窓でも化けない**: .bat は `chcp 932`。Python はパイプ(ランチャーが受け取る)へ書くとき、窓の文字コード
  (`GetConsoleOutputCP`、無ければ cp932)に合わせ、書けない字は「?」にします(Python の UTF-8 モードでも化けない)。
  `PYTHONIOENCODING` を決めてあればそれに従います
- **道**: `pushd "%~dp0"` で一式のフォルダーへ移ってから `python process_manager.py %*`(起動の `start.bat` と同じ。
  共有フォルダー(UNC)でも、空白・全角の空白・括弧があるフォルダー名でも動く)。`%~dp0` を書く所は全部 `"` で囲む
- **起動ファイルの名前・置き場所は変えていません**(`日報複合ツール.exe`・`Start.vbs`・`start.bat`・`stop.bat`・
  `launcher_check.bat`・`launcher_stop.bat`、各ツールの `Start.vbs`・`start.bat`・`stop.bat`)
- **掴んだまま「止めた」と言わない**: 入口・各ツールの Python・exe が居なくなったのを確かめてから `0` を返します
  (以前は、入口が 30 秒で終わらなくても「終わってもらいました」と言っていた)。exe・Python が終われば、
  開いていた DB・ログ・exe のファイルは OS が放します
- 試験: `tests/test_stop_entries.py`(.bat の中身の決まりと、入口の答えごとの終了コード・1行目・`--force`)、
  `tests/test_launcher_entries.py`、各ツールの `tests/test_stop_contract.py`

### Windows で確かめる(ここ(Linux)では .bat を動かせない)

コマンド プロンプト(cmd)で、一式を**全角の空白と括弧が入ったフォルダー**に置いて確かめます
(例 `C:\業務 ツール\日報複合ツール (試験)\`。`業務` と `ツール` の間は全角の空白)。

1. 動いていないとき: `"C:\業務 ツール\日報複合ツール (試験)\stop.bat" /nopause` → `echo %errorlevel%` が `0`、
   1行目が「日報複合ツールは動いていません」。pause で止まらない
2. ブラウザ版(`Start.vbs`)で起動し、日報の［設定］で取り込み(標準作業時間の取り込みなど)を始めた直後に
   `set STOP_NOPAUSE=1` → `stop.bat` → 終了コード `3`、1行目が「実行中の処理があります: 日報(…)」。止まっていない
3. 同じ途中で `stop.bat --force` → `0`。`launcher_check.bat` が `1`(動いていない)
4. ランチャーと同じ受け取り方(パイプ・cp932)で: `launcher_stop.bat > out.txt` → `type out.txt` が1行で化けない。
   PowerShell なら `cmd /c launcher_stop.bat; $LASTEXITCODE`
5. デスクトップ版(`日報複合ツール.exe`)で起動し、点検表で印刷を始める → `launcher_stop.bat` → 窓に確認が出て、
   16 秒で `3`「…閉じてよいかの確認をしています…」。そのまま `launcher_stop.bat --force` → 6 秒ほどで exe が終わり `0`。
   タスク マネージャーに `日報複合ツール.exe`・各ツールの `python.exe`・点検表が起こした `EXCEL.EXE` が残っていない
6. `stop.bat`(`--force` なし)をデスクトップ版の動いているときに → `1`、1行目「デスクトップ版(…)が動いています…」、窓が前に出る
7. 単体の4ツール(`tools\<ツール>\stop.bat`)も、1〜3 と同じ(処理中の例: 看板は書き戻しの途中、カレンダーは同期中、
   点検表は印刷中)
8. 止めたあと、一式のフォルダーを丸ごと上書き(または名前を変える)できること(掴んだままのファイルが無い)
9. 残っていた印(PID の使い回し): ブラウザ版を止めてから、`%LOCALAPPDATA%\AllTools\runtime\portal.lock` を
   次の中身で作る ── `pid` に**動いている別のプログラム**(メモ帳など。タスク マネージャーの「詳細」の PID)、
   `port` 8700、`process_started` 0 を消した(前の版の印)もの。ファイルの更新日時はそのプログラムを起動するより
   前にする(PowerShell `(Get-Item portal.lock).LastWriteTime = (Get-Date).AddHours(-1)`)。
   `stop.bat /nopause` → `0`、1行目「…(残っていた前回の印を片付けました)」、標準エラーと
   `%LOCALAPPDATA%\AllTools\logs` に「片付けました。Start.vbs で起動できます」、印が消えている、メモ帳は開いたまま。
   同じ印を置いて `Start.vbs` → 画面が出る(各ツールの `runtime\*.lock` でも同じ)
10. 起動時刻の値: ブラウザ版で起動し、`portal.lock` の `process_started` が、タスク マネージャーの入口の
   `python.exe`(`pythonw.exe`)の起動した時刻と合う(PowerShell
   `(Get-Process -Id <pid>).StartTime.ToUniversalTime()` と、エポック秒を UTC にしたもの)

## 8. 管理者以外停止モード(ランチャーを介さず、管理者の PC からほかの PC を止める)

現場の声:「ランチャーを介さずアクセス権限、管理者の一定条件がそろっている場合の PC から、他の PC を停止する」。
python-web-tools(梱包資材総合ツール)VER4.8.129・4.8.130 と同じ決めで、日報複合ツールと4ツールに入れました
(`portal/remote_stop.py`・`portal/stop_mode.py`。4ツールは `tools\<ツール>\remote_stop.py`。5か所とも同じ中身)。

| 決め | 中身 |
|---|---|
| やり方 | 共有のフォルダに「停止のお願い」を書く(`日報複合ツール_管理者以外停止\お願い.json`)。各 PC の各プロセスが5秒ごとに読む |
| お願いを出せる | 大設定の「管理者以外停止モード」で、管理者パスワード **かつ** この端末のアクセス権限に `Administrator`(共有の DB(梱包資材マスタ)の表「アクセス権限」の、ログインID・PC名がこの端末の行の「権限」。日報・python-web-tools と同じ表・同じ読み方)。単体の4ツールの設定画面からは出せない(受けるだけ) |
| 止める範囲 | お願いを出した PC 以外の、起動中の PC: 日報複合ツール(デスクトップ版・ブラウザ版。中の4ツールも)と、単体で起動した4ツール |
| 保存していない・処理中 | 画面の上に帯「管理者が更新のため停止を求めています」(誰が・理由・残っているもの・強制までの残り)。何も残っていなければ約30秒でまもなく止まる。残っていれば利用者に任せ、**5分たっても止まらなければ強制**で止める |
| 保存の持ち方 | 止めると決めたら、まず画面に**打ちかけを置いてもらう**(閉じる前の頼みと同じ。日報は入力中の行を作業用DBへ、看板はコメントの書きかけを下書きへ)。強制のときは、残っていたものと手元に置いたものを**その PC の手元の控え**(`%LOCALAPPDATA%\<ツール>\data\停止控え\`。共有には書かない)に書き、次の起動で画面に一度だけ知らせる(閉じるまで残る)。知らせた控えは `停止控え\戻した\` へ移す(消さない) |
| 処理中 | 共有への保存・書き戻し・同期・印刷は終わるのを待つ(5分まで) |
| 更新中 | お願いが出ているあいだ、お願いを出した PC 以外では**起動しない**(理由と、解除できないときの逃げ道を出す) |
| ランチャー | 「全 PC で止める」は据え置き。ただし**同時には使わない**: お願いが出ているあいだ、止める入口(`stop.bat`・`launcher_stop.bat`・各ツールの `stop.bat`)は、動いていれば止めずに `3` を返す(1行目が理由。`--force` でも) |

### 置き場所(どこを見るか)

- 日報複合ツール: 大設定の「共有の DB の置き場所」のフォルダ(既定は梱包資材マスタのフォルダ。配布設定で全 PC を揃える)
- 単体の4ツールも**同じフォルダ**を見る。この PC の大設定(`%LOCALAPPDATA%\AllTools\data\user_settings.json` の
  `shared_db_dir`)→ 一式の `配布設定\日報複合ツール.json` → 環境変数 `ALLTOOLS_SHARED_DB_DIR` → 既定、の順
  (`remote_stop.default_root`)。だから**大設定で出したお願いは、日報複合ツールの中の4ツールにも、単体で起動した4ツールにも効く**。
  各ツールの共有の置き場所(日報の共有の日報データ・看板の共有DB・カレンダーの保存用DB・点検表フォルダ)にはお願いを置かない
- 中身:

```
<共有DBの置き場所>\日報複合ツール_管理者以外停止\
├─ お願い.json                         管理者の PC だけが書く。{"active": true/false, "by_pc", "reason", "grace_sec", …}
└─ 稼働中\<PC>__<ID>__<アプリ>__<pid>.json   各プロセスが自分のぶんだけ書く(1分ごと・お願いを受けているあいだは答えるたび)
```

- **python-web-tools とはフォルダの名前を分ける**(既定の置き場所が同じ梱包資材マスタのフォルダ。python-web-tools は
  `管理者以外停止\` を使う)。日報複合ツールの管理者のお願いで python-web-tools は止まらず、python-web-tools の管理者の
  お願いで日報複合ツール・4ツールは止まらない(前の名前 `管理者以外停止\` のお願いは日報複合ツールでは見ない)
- 丸ごと書いてから入れ替える(書きかけを読ませない)。共有の SQLite には書かない

### 日報複合ツールの中の4ツール

大きなタブの中の4ツールは**自分では止まらない**(デスクトップ版でツールが1つ終わると、外枠が窓ごと閉じにかかるため)。
残っているもの・止めてよいかを手元(`%LOCALAPPDATA%\AllTools\runtime\管理者以外停止\`)に書き、入口(大設定のプロセス)が
それを見て大きなタブの画面の帯に並べる。全部が止めてよくなったら(か、期限 + 20秒)、入口が大きなタブの画面に頼んで
各ツールの画面の打ちかけを置いてもらい、まとめて閉じる:

- ブラウザ版: 各ツールのブラウザ版に確認なしで終わってもらい(`/api/shutdown {"force": true}`)、入口も終わる
- デスクトップ版: 入口の Python が外枠に `{"event": "remote_stop"}` を知らせ、外枠が確認を出さずに全ツールに終わってもらって
  窓を閉じる(`src-tauri/src/closing.rs` の `force_close`)。古い外枠でこの知らせが効かないときは、30秒後にふだんの終わり方で頼み直す
- 入口が閉じないまま 90 秒たったら、中のツールは自分で止まる
- 中のツールは、お願いが無いあいだも手元に「居ます」を書く。入口は、**居るのにまだこのお願いに答えていない**中のツール
  (共有をたまたま読めない・見張りが遅れている)を待つ(帯に「看板: 停止のお願いを確かめています」。期限 + 20秒で閉じる)。
  手元の領域の名前は一式の `config\app.json` の `local_dir_name` に合わせる(入口と中のツールで同じ場所を見る)

### 待つ長さ・画面の打ちかけ

- **共有へ書いている最中は、期限(5分)を過ぎても書き終わるのを待つ**(日報の共有へ保存 = Access への反映、看板の共有DBとの
  やり取り、カレンダーの取り込み元との同期、点検表の印刷)。書き終わったら止める(残っているものがあれば控えを書いて強制)。
  延ばすのは**最長さらに5分**(過ぎたら強制)。帯と管理者の一覧に「共有へ書いている最中なので、終わるのを待っています」。
  日報複合ツールの中のツールが書いている最中なら、入口も閉じずに待つ
- 待つ長さは、お願いの `grace_sec` と**この版の決め(5分)の長いほう**(手で置いた `grace_sec: 1` で、保存する間なしに強制で止めない)
- 画面の帯は、**お願いが来る前から**その画面の保存していない入力を言い添える(裏に回したタブは問い合わせが1分に1回まで
  間引かれ、お願いを受けてからでは帯を見せる間(30秒)に間に合わない)。言わなくなった画面は90秒で忘れる(閉じるときは空を言う)
- 保存していない入力に数えるもの: 日報 = 出る前の確かめを持たない画面(GW計算など)で打った欄・設定の保存していない置き場所と音
  (日報入力の打ちかけは止める前に作業用DBへ置く)/ 看板 = この端末に下書きとして残せないコメントの書きかけ・設定画面で
  保存していない欄 / カレンダー = 設定の欄・マスタの行 / 大設定 = 打ちかけ

### 読めないとき・届かないとき

- **読めないのを「お願いは無い」にしない**(`FileNotFoundError` でも、親のフォルダを一覧できて本当に無いときだけ「無い」)
- 見張り: 前の判断のまま(期限は進む)。読めない回は取り下げとも見ない
- 起動: この PC が**最後に見たお願い**(手元の `runtime\管理者以外停止_最後に見たお願い.json`。読めた回だけ書く・消す)が出ていれば
  起動しない(「解除されたかを確かめられません」)。覚えが無い・6時間より古ければ起動して記録に残す
  (共有が落ちているだけで全部の PC が永久に起動できない、にしない)
- 読めないお願いは上書きしない(出す・解除するのを断る)
- 止める入口は、読めなければ断らない(止める道を閉じない)
- 共有に書けないあいだは記録をためない(最初の1回と直ったときだけ)

### ランチャーの「全 PC で止める」と同時に使われたとき

同時には使わない決めだが、重なっても半端にならないようにしてある:

- お願いが出たあと: 止める入口は、動いていれば止めずに `3`(1行目「止めませんでした: 管理者以外停止モード中…」)。
  ランチャーは「処理中」として 1 分ごとに止め直す。管理者以外停止で止まれば、次の呼び出しは「動いていません」の `0` になり、
  ランチャーの更新はそこから進む(止めるのは管理者以外停止のほうだけ)
- お願いの前にランチャーが止め始めていた: どちらで止まっても同じ道(`/api/shutdown`・外枠の終わり方)。お願いの最中に
  止まったものは管理者の一覧に「止まりました(利用者が終了しました)」が残る
- ランチャーが起動しようとしても(更新のあとの起動など)、お願いが出ているあいだは起動しない(上の「更新中」)
- `--force` でも断る。固まった PC を強制で止めたいときは、先に解除するか、管理者以外停止の強制(5分)を待つ

### 止まらないとき・固まっているとき

- 見張りは自分の糸で動く。初期化・組み立てに失敗して理由の画面のまま残ったプロセスにも立てる
- 「残っているもの」を数える処理が 15 秒答えない(手元の DB の錠待ちなどで固まった)ときは「残っているものを確かめられません」として
  待ち、期限(5分)で強制になる
- 止める処理を呼んでから 60 秒たってもプロセスが残っていれば、確実に落とす(中のツールは入口が閉じる)
- **強制の前の控えを手元に書けないとき(ディスクがいっぱい・書けない)は、強制では止めない。** 帯と管理者の一覧に
  「手元に控えを書けないため、強制では止めません(保存・終了してください)」を出して待ち、書けるようになったら止める
- 期限は各 PC の monotonic(PC の時計のずれ・直しに左右されない)。お願いの `grace_sec` は 0 より大きく 24 時間までに揃える

### 2台の管理者がほぼ同時に出したとき

あとから書いたほうが残る。出した PC は書いてから1秒あとに読み直し、自分のお願いでなければ「ほかの管理者のお願いが先に出ています
(この PC は止めません)」と断り、**そのお願いでは自分の PC を止めない**(手元の `runtime\管理者以外停止_止めないお願い.json`。
この PC のすべてのツールが見る)。片方が解除すれば、両方の PC の分が解除される(お願いは1つ)

### お願い中に共有の置き場所を変えたとき

お願いは大設定の「共有の DB の置き場所」のフォルダに置く。**お願いを出しているあいだは、置き場所(大設定・配布設定)を変えない**
(変えると、その PC からは前のフォルダのお願いを解除できず、ほかの PC は起動できないまま。大設定の画面にも注意を出す)。
変える前に解除する。変えてしまったときは、前のフォルダの `日報複合ツール_管理者以外停止\お願い.json` を別の名前に変える。
PC によって置き場所の決めが違う(別のフォルダを指す)と、その PC にはお願いが届かない(`Z:` と UNC のように書き方が違っても、
同じフォルダを指していれば届く)

### お願いのファイルを手で書いた・古い形・壊れているとき

- `{"active": true}` だけでも効く(`id` が無ければ中身から作る。読むたびに同じなので「出し直した」と取り違えない)。
  `"active"` が `false`・`"false"`・`0` なら出ていない
- 待つ長さ・時刻がおかしな値なら既定(5分)・不明として読む(判定の途中で落ちて起動してしまわない)
- **壊れた JSON は「読めない」と同じ**(「お願いは無い」とは読まない): 見張りは前の判断のまま、起動は最後に見たお願いで決める。
  出す・解除するのは断る(上書きしない)。直すか名前を変える

### 解除できないとき

お願いを出した PC でなくても、**ほかの Administrator の PC の大設定からも解除できる**(パスワード かつ Administrator)。

お願いを出した PC で解除できない(その PC が壊れた・新しい版が起動しない)ときは、`日報複合ツール_管理者以外停止\お願い.json` を
別の名前に変えると解除できる(起動を止めた画面にもこの道を出す)。共有を読めない PC で急ぐときは、手元の
`管理者以外停止_最後に見たお願い.json` を消すと起動できる(その画面に場所を出す)。

### 各ツールで「残っているもの」と、強制の前に置くもの

| ツール | 残っているもの(待つ) | 止める前に置く・強制のときの控え |
|---|---|---|
| 日報複合ツール(入口) | 中のツールの残っているもの・大設定の打ちかけ(置き場所・行・パスワード) | 中の各ツールの画面に打ちかけを置いてもらう |
| 日報 | 走っている処理(共有へ保存・取り込みなど。`nippou/running.py`) | 打ちかけ(入力中の行)は画面が作業用DBへ自動保存する(出る前の確かめ `nav.leaving`)。まだ送っていないページは作業用DBに残り、次の「共有へ保存」で続きから送る |
| 看板 | 共有DBへまだ送っていない操作・コメント・出来事(待てば減るもの) | 送っていないものは手元の SQLite に残り、次の起動で送る。コメントの書きかけは画面が下書き(この端末)に置く |
| カレンダー | 取り込み元との同期・送信待ち・画面の保存していない入力(設定の欄・マスタの行) | 送信待ちは作業用DBに残り、次の起動で送る。画面の保存していない入力は保存できないので、利用者が保存するのを待つ(強制のときは控えで知らせる) |
| 点検表 | 印刷・プレビューの作成 | 何を印刷していたか(何枚目まで)を控えに書き、次の起動で「もう一度印刷して」と知らせる |

### Windows で確かめる

1. 2台(管理者の PC = アクセス権限に Administrator、現場の PC)で日報複合ツールを開く。現場の PC で日報に打ちかけ、看板で
   コメントを書きかけ、カレンダーの設定の欄を打ちかけにしておく
2. 管理者の PC の大設定 →「管理者以外停止モード」で管理者パスワードを入れて「ほかの PC を止める」→ 現場の PC の大きなタブの上に帯
   (カレンダーの設定の欄が「残っているもの」に出る)。カレンダーで保存 → 帯から消え、まもなく窓が閉じる(デスクトップ版は確認なし)
3. もう一度、何かを残したまま待つ → 5分で強制で閉じる。管理者の一覧が「強制で止めました」になる。解除して開き直すと、各ツールの
   画面に「…強制で止めました。そのとき残っていたもの…」が一度だけ出る。日報の打ちかけ・看板のコメントの書きかけが残っている
4. お願いが出ているあいだに現場の PC で exe・Start.vbs・各ツールの Start.vbs を開く → 理由が出て起動しない(Start.vbs は窓の知らせ、
   exe は窓に理由)。`stop.bat` / `launcher_stop.bat` → `3`、1行目「止めませんでした: 管理者以外停止モード中…」
5. 共有のフォルダを切った PC で開く → お願いを最後に見ていなければ起動する。見ていれば「解除されたかを確かめられません」
