# デスクトップ版(Rust/Tauri)

> **この文書は、このツールだけのデスクトップ版(`資材発注看板システム.exe(KanbanSystem.exe)`)の記録です。**
> いまのデスクトップ版は **日報複合ツール.exe の窓の「看板」のタブ**で、窓・Python の起動と監視・
> 別窓・保存/選択のダイアログは日報複合ツールの外枠(一式のフォルダの `src-tauri/`)が受け持ちます。
> このツールの Python 側(`bridge.py`・画面の `desktop.js`)の作りは、ここに書いたとおりです。
> 日報複合ツールのデスクトップ版の作り・作り方は [`../../../docs/デスクトップ版.md`](../../../docs/デスクトップ版.md)。

ブラウザで開く代わりに、**専用の窓(exe)**で動かせるようにします。**ポートを使いません。**
作りは python-web-tools(梱包資材総合ツール VER4.0.0〜)のデスクトップ版にそろえます。
ブラウザ版(`Start.vbs`)もそのまま残し、予備として使えます。

## 1. 移行前の確認 ── 今の機能を保てるか

移行を始める前に、今の機能を1つずつ「ポート・ブラウザに頼っているか」で見直しました。

### 1.1 結論

**今の機能はすべて保てます。** 業務の処理(Python)と画面(HTML/JS)は書き直さず、
Python は Flask を「URL を関数に振り分ける部品」としてそのまま使います
(54 の経路と 820 件余りの試験がこの形で書かれています)。
変わるのは**画面とPythonのつなぎ方**と、**ブラウザが代わりにやっていたこと**(窓・別タブ・
ダウンロード・終わり方)だけです。そこは外枠(Rust)が引き受けます。

### 1.2 そのまま保てるもの(手を入れない)

| 機能 | そのままでよい理由 |
|---|---|
| 看板の盤・出す/取消/発送/届いた/注文中・コメント・既読の共有 | Python の処理を WSGI として呼ぶだけ。経路も応答も同じ |
| 取り込み・書き戻し・状態管理(Form状態管理)・看板履歴への書き出し | Python の背景スレッドで動いている。待ち受けとは無関係 |
| 看板集計(注文中・使用量・倉庫に表示・押し間違いの扱い)・CSV | 同上(CSVの「保存」先フォルダへの書き出しも Python のまま) |
| マスタ確認・管理(並べ替え・追加・修正)・中身の入れ替え | 同上(ファイルを送る `FormData` も本文をそのまま渡せる) |
| アクセス権限によるモード・担当ラインの決定・パスワードでのライン変更 | 同上 |
| 記録(後追い・なぜなぜ)・ログ・記録番号 | 同上。画面側のエラー報告(`/api/client-log`)も同じ経路 |
| 待機画面(取り込みの進み具合)・起動トークン・画面の持ち主・書き込みの錠 | 同じ仕組みを使う。トークンは外枠が毎回付ける |
| 配布設定・設定の保存・タブの記憶(`localStorage`) | 同上。記憶は窓(WebView)ごとに残る |
| 帳票(注文票・発送明細・非常設品リスト)の中身・「印刷する」ボタン | 帳票の HTML は Python が作る。印刷はページの `window.print()` |

### 1.3 形を変えて保つもの(ポート・ブラウザに頼っていた所)

| 今の仕組み | 頼っていたもの | デスクトップ版 |
|---|---|---|
| モードごとのポート(現場 8741 / 倉庫 8751 / 倉庫参照 8761) | ポート | **ポートを使わない。** 画面は外枠の中の宛先(`app://localhost/`、Windows は `http://app.localhost/`)を読み、外枠が Python の標準入出力へ渡す |
| モードを変えたら「開き直す」 | モードとポートの結びつき | 外枠が **Python だけを立て直して** 新しいモードで開く(窓は閉じない)。最後の書き戻しは済ませてから |
| 多重起動の防止(ロックファイル+`/api/health` の照会) | ポート | 外枠が防ぐ(single-instance と OS のファイルロック)。2つ目を開くと今の窓が前に出る。**ブラウザ版とデスクトップ版の同時起動も、どちらからも止める**(同じ手元の SQLite を2つが書かないように) |
| 自動終了(心拍・タブを閉じたら終わる) | ブラウザのタブ | **窓を閉じたら終わる。** × は画面の「終了」と同じ確認を通る(未反映の操作があれば訊く)。最後の書き戻しを待ってから Python を終わらせる |
| 帳票を新しいタブで開く(`target="_blank"`) | ブラウザのタブ | 外枠が**別の窓**で開く。「印刷する」で印刷ダイアログ |
| ダウンロード(集計 CSV・記録 CSV・なぜなぜシート) | ブラウザのダウンロード | 外枠(Rust)の**「名前を付けて保存」ダイアログ**で保存する。置き場所を選べる |
| フォルダ・ファイルの「参照...」(Python がフォルダを一覧して画面に出す) | ブラウザは手元のパスを返せない | 外枠が **Windows の標準のダイアログ**を出す(ネットワークのフォルダも辿れる)。開けなかったときは今の一覧 |
| 「中身を入れ替える」へのドラッグ&ドロップ | ブラウザ | そのまま使えるよう、外枠がファイルの落下を横取りしない設定にする |
| `stop.bat` で止める | ポート(`/api/shutdown`) | デスクトップ版は窓を閉じれば止まる(外枠が終わると Python も必ず終わる)。`stop.bat` はブラウザ版用に残す |
| 起動できないとき(Python が無い等)の案内 | ブラウザで開くエラーページ | 外枠が窓に理由・次にすること・ログの場所を出す |
| Python が途中で落ちた | 画面の「接続できません」 | 外枠が見張っていて、窓に理由と最後の出力を出す |

### 1.4 変わること・気をつけること

- **Python は同梱しません**(今と同じ)。各PCの Python を使います(`python.exe` → `py.exe -3` の順に探す)。
  デスクトップ版で要るのは Flask だけです(waitress はブラウザ版用)。
- **WebView2 ランタイム**が要ります。Windows 10/11 には標準で入っています(古い Windows 10 で無いことがある)。
- exe は **GitHub Actions(Windows)**で作ります。この開発環境では Linux(WebKitGTK)の上で窓を実際に動かして確かめました。
- 次の点は**Windows の実機で人が見る**必要があります(python-web-tools と同じ):
  印刷ダイアログから紙が出ること / ドラッグ&ドロップ / 保存ダイアログ / × での確認ダイアログ / 標準のフォルダ選択。
- 複数の端末を1台で真似る試し(e2e)はポートで分けるブラウザ版で続けます(デスクトップ版は1台に1つ)。
- 窓にはアドレス欄がありません。画面の URL を他の人へ渡す使い方はできません(もともと起動ごとにトークンが変わるので使えませんでした)。

### 1.5 各言語に持たせること

| 担当 | 持たせること | 理由 |
|---|---|---|
| **Rust(外枠 `src-tauri/`)** | 窓・帳票の窓・Python の起動と見張り・多重起動の防止(OS のロック)・終了の確認・モード切替での立て直し・保存/選択の標準ダイアログとファイルへの書き込み・社内サイトを既定のブラウザで開く | OS の窓・プロセス・ダイアログ・ファイルロックを直接扱える。exe 1つで配れる |
| **Python(`bridge.py` 以下)** | 業務の処理すべて(取り込み・書き戻し・共有 SQLite の読み書き・集計・権限・記録・画面の組み立て) | VBA と同じ結果を守る試験がこの形で書かれている。重い計算は無く、書き直す利点が無い |
| **JS(`app/static/js`)** | 画面の操作。デスクトップ版のときだけ、窓・保存・選択・立て直しを外枠に頼む(`desktop.js`) | 今までどおり。ブラウザ版と同じファイルで両方に対応する |

## 2. 作り

```
資材発注看板システム.exe(Rust / Tauri)          … src-tauri/
 ├─ 窓(WebView2)・帳票の窓・終了の確認・多重起動の防止
 ├─ 保存/選択の標準ダイアログ・社内サイトを既定のブラウザで
 ├─ Python を子として起動・監視(落ちたら理由の画面・モード切替で立て直し)
 └─ 画面の要求(app://…)を受けて、Python の標準入力へ渡す
        │ 標準入出力(1件 = 見出し1行(JSON) + 本文)
        ▼
bridge.py(Python)                               … ポート無しの入口
 └─ Flask アプリを WSGI として呼ぶだけ(待ち受けない)
        ▼
app/・kanban/(Python)                            … 業務の処理(変わらず)
app/static/js(JS)                                … 画面(変わらず。窓まわりだけ desktop.js)
```

### やりとりの形

```
要求  {"id": 7, "method": "POST", "path": "/api/x", "query": "a=1", "headers": [[k, v]], "len": 12}\n<本文>
応答  {"id": 7, "status": 200, "headers": [[k, v]], "len": 345}\n<本文>
知らせ {"event": "started" | "quit" | "fatal", ...}\n
```

本文は JSON に埋めず(base64 にせず)生のバイト列のまま渡します。Access ファイルの送り込みが数十MBになるためです。
Python は**最初に**本物の標準出力を取っておき、記述子 1 を標準エラーへ付け替えます(`print` が混ざってもずれない)。

## 3. 動きの約束

| 場面 | 動き |
|---|---|
| 起動 | 窓がすぐ出て「起動しています」→ 待機画面(取り込みの進み具合)→ 業務画面 |
| もう1つ起動しようとした | 新しく起動せず、開いている窓を前に出す(OS のファイルロックでも止める) |
| ブラウザ版が動いているときに exe を開いた | ブラウザ版に終わってもらってから開く(未反映の操作があって終われないときは理由を出す) |
| exe が動いているときに Start.vbs を開いた | 起動せず「デスクトップ版が動いています」と出す |
| 窓の × / 画面の「終了」 | 未反映の操作があれば訊く(ブラウザ版の「終了」と同じ確認)。最後の書き戻しを済ませてから終わる |
| 設定でモードを変えた | 「いま切り替える」で Python を立て直し、新しいモードの画面になる(窓は閉じない) |
| 帳票 | 別の窓で開く。「印刷する」で印刷ダイアログ |
| CSV・なぜなぜシートのダウンロード | 「名前を付けて保存」ダイアログ |
| 「参照...」 | Windows の標準のフォルダ/ファイル選択(パスワードは訊かない。開けなかったときだけ従来の一覧) |
| Python が見つからない・起動できない | 理由と次にすること(Python の入れ方・pip の打ち方)・ログの場所を窓に出す |
| Python が途中で落ちた | 窓を読み直して理由の画面を出す |
| exe を止めた | 標準入力が閉じるので Python も終わる(取り残さない) |

## 4. 作り方

**Windows 版は GitHub Actions が作ります**(`.github/workflows/desktop-windows.yml`)。
Python の試験・Rust の試験・exe の作成・exe を起動しての確認(`scripts/desktop_smoke.py`)まで流れ、
成果物 `KanbanSystem-windows` に `KanbanSystem.exe` が入ります。

配るとき: 成果物の `KanbanSystem.exe` をツールのフォルダの**直下**(`bridge.py` と同じ所)に置きます。
`scripts/make_dist.py` は、置いてあれば `資材発注看板システム.exe` の名前で配布フォルダに入れます。

手元で作るとき(開発機):

```
cd src-tauri
cargo build --release            # target/release/KanbanSystem(.exe)
python ../scripts/desktop_smoke.py --exe target/release/KanbanSystem    # Linux は xvfb-run を前に付ける
```

Linux で作るには WebKitGTK が要ります(`libwebkit2gtk-4.1-dev` など)。

## 5. 置き場所の決まり

- exe は `bridge.py` と同じフォルダに置く(上の階層もたどるので `src-tauri/target/...` から動かしても見つかる)。
  `KANBAN_ROOT` で指定もできる
- 使う Python は `KANBAN_PYTHON` で指定もできる
- 版は `config/app.json`・`src-tauri/tauri.conf.json`・`src-tauri/Cargo.toml` の3か所。食い違うと試験が落ちる
- 多重起動の錠は `%LOCALAPPDATA%\KanbanSystem\runtime\desktop.lock`(プロセスが終われば OS が外す)

### 移行の途中で見つけて直したこと

- **ページを移ると操作が断られた**: 窓の中では、離れるページの合図(`sendBeacon`)が届かず、
  前のページが「画面の持ち主」のまま残っていた(盤から設定へ移ると、設定の操作が 423 で断られた)。
  業務の画面を出す窓は 1 つなので、デスクトップ版では**開いたページが持ち主を引き継ぐ**ようにした
- **共有DBの写しの取り合い**(ブラウザ版にもあった): 同じ共有 DB を同時に読むと、読んでいる最中の
  写しへ別の要求が写し直していた。設定画面を開いた瞬間に「倉庫モード(権限なし)」と出ることがあり、
  その空の結果を「前回読めた内容」として覚えていた。写すたびに新しい名前で作るように直した
  (`kanban/db/shared.py`。8 本同時に読む試験を足した)
- **共有DBへの接続を閉じていなかった**(ブラウザ版にもあった。Windows の試験で見つかった): `with conn:` は
  確定するだけで閉じない。共有フォルダのファイルを開いたまま残し、Windows では名前の変更・置き換えを断られる。
  必ず閉じるようにした

## 7. 確かめきれていないこと(Windows の実機で見る)

GitHub Actions(Windows)は「試験・exe の作成・起動して画面が届く・待ち受けない・止めたら終わる」まで
確かめます。次は**Windows の実機で人が見る**必要があります:

- 窓の × で、共有DBへ未反映の操作があるときの確認ダイアログ(「終了」ボタンからの道は確かめ済み)
- 帳票の「印刷する」から実際に紙が出ること(WebView2 の印刷ダイアログ)
- 「中身を入れ替える」へのドラッグ&ドロップ
- 保存ダイアログ・フォルダ選択ダイアログ(Windows の見た目。ネットワークのフォルダを辿れること)
- `Start.vbs` と exe を続けて押したときの案内(Windows のファイルロック)
