# 運用手順

## 1. 導入

### 1.1 Python の準備

python.org の Windows 版インストーラ(3.9 以降)を使います。`tkinter` は同梱です。
インストール時に **「Add python.exe to PATH」** にチェックを入れてください。

追加パッケージは `Flask` と `waitress` の 2 つだけです(デスクトップ版だけを
使うなら `Flask` だけで動きます。waitress はブラウザ版の待ち受けに使います)。

```
pip install -r requirements.txt
```

### 1.1.1 デスクトップ版とブラウザ版

開き方は 2 つあります。**ふだんはデスクトップ版**を使ってください。

| | デスクトップ版(`資材発注看板システム.exe`) | ブラウザ版(`Start.vbs`) |
|---|---|---|
| 画面 | 専用の窓 | 既定のブラウザのタブ |
| ポート | **使わない**(窓の外枠が Python と直接やりとりする) | 使う(現場 8741 / 倉庫 8751 / 倉庫参照 8761) |
| 閉じ方 | 窓の × か「終了」(未反映の操作があれば訊く) | 「終了」か、タブを閉じる(しばらくして自動で終わる) |
| モードの切り替え | **その場で切り替わる**(窓はそのまま) | 次に開いたときから |
| 帳票 | 別の窓で開く | 新しいタブで開く |
| CSV・なぜなぜシート | 「名前を付けて保存」で置き場所を選ぶ | ブラウザのダウンロード先へ |
| 設定の「参照...」 | Windows の標準のフォルダ/ファイル選択 | アプリが出す一覧(管理者パスワードが要る) |

* exe は**アプリのフォルダの直下**(`bridge.py` と同じ所)に置きます。デスクトップに
  置きたいときはショートカットを作ってください(exe だけを移すと起動できません)
* デスクトップ版とブラウザ版は**同時には動きません**。デスクトップ版が開いているときに
  `Start.vbs` を押すと「デスクトップ版が動いています」と出て、ブラウザ版は開きません。
  ブラウザ版が動いているときに exe を開くと、ブラウザ版に終わってもらってから開きます
  (同じ手元の SQLite と共有DBへ 2 つが書き戻しに行かないように)
* Python は exe に入っていません。各 PC の Python を使います(`python.exe` →
  `py.exe -3` の順に探します)。見つからないときは、窓に入れ方が出ます
* Windows 10/11 には、窓の表示に使う WebView2 が最初から入っています
* 作りの詳細と確かめたことは [デスクトップ版.md](デスクトップ版.md) にあります

### 1.2 ファイルの配置

本一式(`main.py` と `kanban/` フォルダ)を、各端末から実行できる場所に置きます。
共有フォルダに置いて全端末から実行しても、各端末にコピーしても構いません。

### 1.3 設定ファイルの作成

まず現在の設定を確認します。

```
python main.py --show-config
```

ふだんは**設定画面から直すだけ**で、ファイルを手で作る必要はありません。
設定は**この端末の設定ファイル** `%APPDATA%\KanbanSystem\config.json` に入ります
(接続先・取り込み/書き戻し間隔・自動印刷・管理者パスワード・担当ライン)。

**アプリのフォルダの中には置きません。** 利用者ごとのフォルダにあるので、
**新しい版をダウンロードしてフォルダごと入れ替えても消えません**(一時期の版は
アプリのフォルダの `data\config.json` に置いていたため、入れ替えるとパスワードや
接続先が消えていました。残っていれば、この端末に無い項目だけ 1 度引き継ぎます)。
配った先の端末に同じ設定を入れるときは「配布設定」で書き出します(1.5)。

手で書くときは `%APPDATA%\KanbanSystem\config.json` に書きます(例)。

`shared_db_path` は正式なデータの置き場所(共有フォルダ上の SQLite ファイル)
を指します。`sqlite_path` は指定不要です(既定でこの端末のローカルディスクを
使います。詳しくは 2 章を参照)。

```json
{
  "shared_db_path": "\\\\nlmfangyshrd\\各課共有\\0130_日軽稲沢\\梱包課\\AIM\\【■】_参照用ファイル\\看板マスタ.sqlite3",
  "export_interval_sec": 60,
  "import_interval_sec": 30,
  "refresh_interval_sec": 5
}
```

**動作確認・テストのときは、本番の参照用ファイル置き場を直接指さないこと。**
`\\nlmfangyshrd\各課共有\0130_日軽稲沢\梱包課\AIM\【■】_参照用ファイル` の下に
`Test環境` フォルダを作り、そこへ複製したファイルを配置したうえで、
`shared_db_path` を
`\\nlmfangyshrd\各課共有\0130_日軽稲沢\梱包課\AIM\【■】_参照用ファイル\Test環境\看板マスタ.sqlite3`
のように指定してください。本番データを誤って書き換えるのを防げます。

### 1.2.1 Access からの移行(初回だけ)

正式なデータは以前 Access(`看板マスタ.accdb`)でした。共有 SQLite へ
移すには次を 1 回実行します。

```
python tools/accdb_to_sqlite.py "看板マスタ.accdb" "看板マスタ.sqlite3"
python tools/accdb_to_sqlite.py "看板マスタ.accdb" --check   # 中身を見るだけ
```

できたファイルを共有フォルダへ置き、`shared_db_path` をそのパスにします。
**元の .accdb は触りません** ── 切り戻したくなったら設定を戻すだけです。

`python start_app.py --check` は、共有 SQLite がまだ無く .accdb だけがある
状態を見つけると、実行すべき変換コマンドをそのまま表示します。

### 1.2.2 【重要】共有フォルダのロックを先に検証する

**正データが SQLite になったことで、共有フォルダのファイルロックが
信頼できるかどうかが直接効いてきます。** Access(ACE/Jet)は共有フォルダで
複数端末が使う前提の設計でしたが、SQLite はそうではありません
([SQLite 公式もネットワーク越しの使用を推奨していません](https://www.sqlite.org/useovernet.html))。

**本番投入の前に、実際に使う共有フォルダで必ず検証してください。**

```
python tools/check_shared_lock.py --path "\\サーバ\共有\看板\_locktest.sqlite3" --workers 8 --seconds 20
```

複数の実端末から同時に同じコマンドを実行すると、より本番に近い検証に
なります。「合計: 成功件数(自己申告)= DB実測値」が一致すれば、その
ファイルサーバではロックが正しく機能しています。**不一致が出た場合は、
その共有フォルダを使わないでください**(データ破損の恐れがあります)。

Windows Server の最新の SMB3 であれば実用上問題ないことが多く、古い NAS や
Linux 実装の Samba は要注意です。

現場・倉庫・倉庫参照のどのモードで起動するかは、設定ファイルでは
なくこの端末の SQLite に保存されます(理由・切り替え方は次の 1.3.1 を
参照)。`line`(担当ライン)は**現場モードで要ります**。選ばずに起動しても
画面は開きますが、そのラインの看板が出ないので、設定画面の「この端末」で
選んでください(`%APPDATA%\KanbanSystem\config.json` に入ります)。

### 1.3.0 設定画面の見かた(9つのタブ)

「設定」は用ごとに9つのタブに分かれています。

| タブ | 何をする場所か |
| --- | --- |
| この端末 | モードと担当ラインを変える(1.3.1) |
| 接続先 | 共有DB・アクセス権限・看板履歴の場所、CSV の書き出し先、取り込み・書き戻しの間隔と自動印刷(動作)を変える(1.3.2) |
| マスタ管理 | 看板を増やす・減らす、資材やサイズを直す(1.3.3) |
| 看板集計 | 出した日・届いた日から回数・日数・提出率を出す、CSV に書き出す(1.3.4) |
| 取り込みの状態 | 取り込み直す・未反映を見る |
| 記録 | エラー・断った操作・画面のエラーを探して開く、なぜなぜ分析シートを作る、記録(ログ)の置き場所(4.1・4.1.1) |
| ファイルの場所 | **複数の PC で共有するファイル**と**この PC だけに置いて引き継ぐファイル**の一覧(1.3.5)・問い合わせのときに読み上げる値 |
| パスワード認証 | 管理者パスワードで認証する・決める・変える(1.3.1) |
| 配布設定 | 1 台で決めた設定を書き出して配る・配布用フォルダを作る(1.5) |

タブの下には**認証の状態**(未設定 / 未認証 / 認証済み)がいつも出ます。

最後に開いたタブはその端末に覚えさせるので、次に「設定」を開くと同じ面が
出ます。

### 1.3.1 モード(現場 / 倉庫 / 倉庫参照)の選び方・変更のしかた

現場・倉庫・倉庫参照は VBA 版と同じく **1 回の起動ではどれか 1 つだけ**
開く独立した画面です。ただし VBA 版のように別々の Excel ブックを配る
のではなく、実行ファイルは 1 つのままで、どのモードを開くかをこの端末の
SQLite に記憶させます。

* **初回起動時**: **現場モードで起動し、それを SQLite に保存します。**
  選択画面は出ません ── 台数がいちばん多いのは現場の端末なので、そのまま
  使い始められるほうが手間が少ないためです。倉庫の端末では初回だけ設定を
  変えてください(次項)。
* **2 回目以降**: SQLite に保存済みのモードで直接起動します。
* **後から変更したい場合**: 画面の「設定」→「この端末」→「モード」。
  **デスクトップ版は、その場で切り替えられます**(「いま切り替えますか？」に
  「OK」。共有DBへの書き戻しを済ませてから、窓はそのままで新しいモードの画面に
  なります)。以下はブラウザ版の場合です。
  **変更は次にアプリを開いたときから効きます。** モードはポート
  (現場 8741 / 倉庫 8751 / 倉庫参照 8761)に結びついているので、
  走ったままでは切り替わりません。いったん閉じて開き直すと、古いモードは
  **自動で終わり**、新しいモードで立ち上がります(手で止める必要は
  ありません)。

**使えるモードはアクセス権限で決まります**(1.3.1.1)。パスワードは訊きません。
「接続パスを変更…」(1.3.2)などほかの変更は、これまでどおり
**管理者パスワード**で保護されています。パスワードがまだ設定されていない
状態で守られた操作を初めて押すと、その場で新しいパスワードの設定を求められ
ます(以後、この端末ではそのパスワードが必要になります)。

#### 1.3.1.1 アクセス権限(誰がどのモードを使えるか)

以前はモードの切り替えを管理者パスワードだけで守っていました。パスワードは
教え合えるので、いまは **梱包資材マスタ(`梱包資材マスタ.sqlite3`)の「アクセス権限」の表**に
**Windows のログインID と PC名** で登録された端末だけが、そのモードを使えます。
python-web-tools(梱包資材総合ツール)と**同じ表・同じ読み方**です。

| ログインID | PC名 | 権限 | 有効 | 意味 |
| --- | --- | --- | --- | --- |
| yamada | (空) | mode:material | 1 | 山田さんはどの PC でも倉庫モード |
| (空) | NGY-PC-0001 | mode:field | 1 | この PC は誰でも現場モード |
| suzuki | NGY-PC-0001 | mode:material | 1 | 鈴木さんがこの PC のときだけ倉庫モード |
| kanri | (空) | Administrator | 1 | 管理者。どの PC でも現場・倉庫の両方を使える(切り替えられる) |

* このツールが読むモードの権限: **`mode:field` = 現場モード / `mode:material` = 倉庫モード**
  (python-web-tools の「資材モード」と同じ文字)、**`Administrator` = 現場・倉庫の両方**
  (日報と同じ書き方。全角半角・大文字小文字は問いません。`Administrator、L-1` のように担当ラインと
  並べて書けます)。**倉庫参照はいつでも使えます**(何も変えないため)
* **ほかの文字列(ほかのツールの権限)も同じ表に入ります。** このツールは使わず、消しもしません
* 空欄は「問わない」。**ログインID も PC名 も空の行は誰にも効きません**(全員への許可になるため)
* 大文字小文字は区別しません。`有効` は空欄なら有効、`0` / `false` / `×` などで無効
* 当てはまる行の権限を**すべて**使えます。**当てはまる行が無い端末は現場モードだけ**です
* 逆に、**このツールの行が 1 つでも当てはまると、その行のモードだけ**になります
  (`mode:material` だけ足すと現場モードは使えなくなる)。倉庫の人・端末が現場モードも
  使うなら `mode:field` の行も足してください(python-web-tools と同じ読み方)
* 権限の無いモードで開こうとすると(保存してあるモード・`--mode` どちらも)、使えるモードで開き、
  **画面の上に「なぜ・何を足せばよいか」を出します**。保存してあるモードは書き換えないので、
  行を足せば次に開いたときから頼んだモードで開きます

**行を足す・直す・消す**: 「設定」→「マスタ管理」→ テーブルの一覧の最後の
「**アクセス権限(梱包資材マスタ)**」。管理者パスワードが要ります(書き間違えても
直せるように、モードは問いません ── python-web-tools と同じ復旧経路)。「+ 行を追加」を押すと
**この端末のログインID と PC名 が入った状態**で開くので、別の端末なら書き換えてください。
足した直後から、モードの切り替えに効きます。

**この端末の権限を見る**: 「設定」→「この端末」→「この端末の権限」。ログインID・PC名、
使えるモード(使えないモードは足すべき行)、当てはまった行(ほかのツールの権限も)が出ます。

**表が無いとき**: 起動したとき(倉庫参照以外)と、マスタ管理を開いたときに、
梱包資材マスタに「アクセス権限」の表を作ります(実物と同じ定義。**ほかの表には触りません**)。

**置き場所**: 既定は**共有DB(看板マスタ)と同じフォルダの `梱包資材マスタ.sqlite3`**。
違う場所なら「設定」→「接続先」→「アクセス権限の置き場所(梱包資材マスタ)」で指定します
(看板マスタは選べません)。配布設定にも入ります。

**届かないとき**: 最後に読めた内容を手元に覚えておき、それで判断します(共有フォルダが
落ちるたびに倉庫の端末が倉庫で開けなくなるのを避けるため)。一度も読めていなければ現場モードだけです。
起動時に待つのは最大 8 秒です。

**担当ラインもこの表で決まります。** `権限` 列にライン名(**正規の呼び名**)が書いてあれば、
その端末の担当ラインにします(読み方は日報 vba-daily-report-python-migration と同じ。対応するラインはこのツールの看板)。

| 正規(マスタに書く) | このツールの看板 |
| --- | --- |
| L-1 | 看板_L1 |
| LVC | 看板_LVC |
| HVC | 看板_HVC |
| 機側 | 看板_LS |
| AIM | 看板_AIM |
| コイル | 看板_コイル |
| トット | 看板_大板小板 |
| バランサー | 看板_大板小板 |
| NS1 | 看板_NS1(倉庫の画面には出さないライン) |

* **紛らわしいのは 3 つ**: 表の名前の `L1` `LS` `大板小板` ではなく、正規の **`L-1` `機側` `トット`(または `バランサー`)**
  と書きます。トットとバランサーは、このツールでは同じ看板(大板小板)です(両方書いてあっても同じラインなので決まります)
* **全角・半角の違いだけは同じ字**として読みます(`ＬＶＣ` = `LVC`、`ﾄｯﾄ` = `トット`)
* 読まない書き方: `L1` `LS` `大板小板`(このツールの表の名前)、`l-1` `ｌ―１` `L 1` のように記号・大文字小文字・
  空白が違うもの。読まなかったときは「設定」→「この端末」→「この端末の権限」に
  「**読まなかった権限: L1(正規は「L-1」)**」「**大板小板(正規は「トット」か「バランサー」)**」と正しい書き方を添えて
  出します(表の全部の行の点検にも出ます)
* 1 つの欄に「、」「,」「/」で並べて書けます(`L-1、mode:field`)
* この端末の行に**違うラインが 2 つ以上**あれば、どちらか分からないので決めません(そう出します)
* **起動するたびに表のラインにします。** 起動しているあいだに表を書き換えたときは、設定の「読み直す」
  (画面を開いたときも読み直します)で当てます
* **管理者パスワードで担当ラインを変える仕組みは残っています**(「設定」→「この端末」→「担当ライン」)。
  ただし変えたラインは**その起動のあいだだけ**で、次に起動すると表のラインに戻ります。
  変えたままにしたいときは、マスタ管理でアクセス権限を書き換えてください(変えたときに画面にもそう出ます)。
  表にこの端末のラインが無ければ、これまでどおり変えたラインのままです
* 現場モードの端末だけに当てます(倉庫・倉庫参照は担当ラインを使いません)

> **入れ替えの前に**: この版に入れ替えると、**アクセス権限に登録の無い端末は現場モードだけ**になります。
> 倉庫の端末(と倉庫で使う人)を先に登録してください。

#### パスワード認証

「設定」→「**パスワード認証**」は、状態によって出るものが変わります。

| 状態 | 出るもの | すること |
| --- | --- | --- |
| **未設定**(パスワードがまだ無い) | 新しいパスワード + 確認 →「決める」 | 決める。決めるとそのまま**認証済み**になる |
| **未認証** | 管理者パスワード →「認証する」 | 認証すると、しばらくパスワードを訊かない |
| **認証済み** | 「認証を解除する」 | そのまま使う。離れるときは解除する |

**認証済みのあいだは、担当ライン・接続先・動作の変更やマスタの編集で
パスワードを訊きません**(マスタを何マス直しても 1 回で済みます)。操作のときに
出る確認画面でパスワードを入れても、同じように認証済みになります。

認証が解除されるのは次のどれかです。

* 「認証を解除する」を押した(タブの下の帯にもボタンがあります)
* 設定の変更を **30 分**しなかった(開けっぱなしの端末を残さないため)
* アプリを閉じた

**未設定のまま置いておかないでください。** 最初に設定を変えようとした人が
パスワードを決められてしまいます(タブの下の帯にも「未設定です」と出ます)。

#### 管理者パスワードの変更

パスワードがあるときは、同じ面に **「管理者パスワードを変える」** が出ます。
**認証済みでも、変えるときは今のパスワードを訊きます**(開けっぱなしの端末で、
通りがかった人に変えられないように)。

パスワードは**この端末の設定ファイル**に(ハッシュで)入ります。配った先も同じ
パスワードにするときは「配布設定」で書き出します(既定で入ります。1.5)。

一時的に別のモードで起動したいだけ(検証用など)であれば、SQLite の
記憶を変えずに `--mode` で 1 回限り上書きできます。

```
python main.py --mode warehouse
```

担当ラインを変えても**アプリは閉じません**(画面を読み直すだけです)。
「開いています」の名乗りも一緒に移るので、前のラインが開いたまま残ることは
ありません ── 以前は前のラインを名乗り続けたため、ラインを切り替えながら
試すと**自分自身が「開いている端末」に他人として並んで**いました(3.6)。

### 1.3.2 接続先の変更

導入後に共有ファイルの場所が変わった場合、`config.json` を直接編集する
代わりに、画面の「設定」→「接続先」から変更できます(管理者パスワードが
必要。1.3.1 参照)。

**変更するとその場で繋ぎ直して取り込みます。開き直す必要はありません。**
取り込めたライン数が画面に出ます。

受け付けられたかは、画面で次のように分かります。

* カードの上の **「いまの接続先」** に、いま繋がっている場所と **届いているか**
  (✔ 届いています / ✖ 届きません / まだ決めていない)がいつも出ます
* 欄を書き換える(「参照...」で選ぶ)と **「まだ切り替わっていません」** と出ます。
  いまの接続先と同じ場所のときは「変更」は押せません
* 「変更」を押すと、結果(**✔ 接続先を変えました** / **✖ 変えられませんでした(元のまま)**)
  がカードの中に残ります。画面が読み直されたあとも出ています
* まだ接続先を決めていない端末(既定の場所を使っている)では、既定の場所のまま
  「変更」を押すと、その場所に決めます

うまくいかなかったときは、同じ設定画面の
「取り込みの状態」にある **「↻ いま取り込む」** をもう一度押してください
(共有フォルダが一時的に落ちていたあとの復旧も、このボタンです)。

**「参照...」** を押すと、この PC から見えるフォルダを一覧できます
(**管理者パスワードが要ります**。開いているあいだは訊き直しませんが、
閉じると次に開くときにもう一度訊きます)。
ブラウザのファイル選択ダイアログはこの PC のパスを返さないため、専用の
一覧を用意しています。直接打っても構いません。

変換前の `.accdb` は**灰色で表示され、選べません**。「フォルダは合っているが
変換がまだ」という状態がひと目で分かるようにしてあります。

**看板の表(`看板_LVC` など)が 1 つも無いファイルは、接続先にできません。** 梱包資材マスタなど
別のツールの sqlite3 を選ぶと、理由(入っている表の名前)を出して断ります。以前は sqlite3 と
して開ければ通してしまい、このツールの表(看板履歴・看板コメント)をそのファイルへ作っていました。
設定ファイルや配布設定ですでに別のファイルを指している端末でも、そのファイルには表を作らず、
「接続先」に「✖ 使えません ── 看板の表が 1 つもありません」と出ます(`start_app.py --check` でも出ます)。

共有DBが見つからないとき、ほかの .sqlite3 を探して代わりに使うことはしません
(「接続先」に書いた場所か、組み込みの既定の場所だけを見ます)。

### 1.3.2.1 接続先に指定できる場所

**届かない場所は保存できません。** 次の3つはその場で断ります。

| 断る場合 | 画面に出ること |
| --- | --- |
| その場所が無い | 綴りを確かめるか「参照...」から選んでください |
| フォルダを指している | ファイルではありません |
| SQLite として開けない | 変換前の `.accdb` を指していないか確かめてください(1.2.1) |

保存できてしまうと、**この端末は次の起動からも届かない場所を指し続けます**
── 画面は「取り込めていません」と言うだけなので、打ち間違いなのか共有が
落ちているのかが分かりません。打った直後なら、どちらかははっきりしています。

なお「いまは共有が落ちているが、あとで復旧する」場合は保存できます
(ファイルさえ見えていれば通します)。

### 1.3.3 マスタ管理(Access の代わり)

Access をやめたため「Access を開いて中身を目視する・手で直す」ができなく
なりました。その受け皿が「設定」→「マスタ管理」です。

**直せるのは `看板_<ライン名>` だけ**です。それ以外の表も一覧に出て中身は
見られますが、直す手立ては出さず、代わりに**なぜ直せないのか**を表の上に
出します(例: `Form状態管理` は「端末が開いているかどうかを各端末が自動で
書き込む表です」)。隠さないのは、隠すと**画面が壊れて見える**ためです。

* テーブルを選んで開くと、中身を表で見られます(100 行ずつ)。
  **見るだけならパスワードは要りません**(調べる手段を塞がないため)
* **列名を押すと並べ替えます。** 押すたびに 小さい順(▲)→ 大きい順(▼)→ 元の順(ファイルの順)。
  100 行ずつのページに分ける前に**表全体を**並べるので、次のページも続きの順です。
  数は数として(10 は 9 のあと)、日時は日時として(`2026/9/1` は `2026/10/1` の前)比べ、
  **空欄は向きにかかわらず最後**です。並べ替えたままでも直す・消すはその行に効きます
* マスを押すと、その場で直せます
* 「**+ 行を追加**」で 1 行足せます(= **看板を 1 枚増やす**)
* 各行の右端の「**削除**」で 1 行消せます
* **読む以外はすべて管理者パスワードが要ります**
* `管理番号`(キー列)は直せません ── 書き換えると、どの行だったのかが
  辿れなくなるためです。番号を打ち間違えたときは**消して足し直して**ください
* **看板の状態は読むだけです**(`欲` `不` `更新日` `発送` `倉庫確認日時`
  `保留` `注文中日時`)。直せるのは `資材` `サイズ` `常設品` です

#### どのファイルを読み書きしているか

マスタ管理の上に「**読み書きする共有DB**」の場所がいつも出ます。直す・足す・消すをしたあとは、
その結果と「**書き込み先**(共有DBの場所と更新日時)」が消えずに残ります
(「Access の最新で表の中身を入れ替える」でも、中を見た時点で書き込み先を出し、入れ替えたあとは
書き込み先・更新日時・ファイルを開き直して確かめた行数を出します)。

#### 看板の状態は、ここでは直せない

発注・発送・注文中は、看板画面のボタンが**いくつかの欄を組にして**書きます
(発注なら `欲 = 〇`・`不 = 空`・`更新日 = いま` を同時に)。マスタ管理で
1 マスだけ直すと、この組が崩れて「`欲` も `不` も `〇`」のような、ボタンでは
作れない看板ができます。しかも各端末にまだ送っていない操作が残っていると、
あとからそれが上書きします。

だから状態の欄は**灰色で、押しても入力欄になりません。** 状態を変えたいときは
看板画面のボタンで操作してください。

#### 看板を 1 枚増やす

1. 「設定」→「マスタ管理」でテーブルに `看板_<ライン名>` を選び、「開く」
2. 「**+ 行を追加**」を押す
3. `管理番号` には**次の番号が入った状態**で出ます(変えても構いません)。
   `資材` と `サイズ` を入れてください。`常設品` には `〇`(常設)が
   入っています ── 非常設品なら `×` に直します
4. 状態の欄(欲・不・発送など)は**出てきません**。**「まだ発注していない」状態**
   (`不 = 〇`、ほかは空)で足します
5. 「足す」→ 管理者パスワード(認証済みなら訊かれません)

足すと**その場で手元へ取り込むので、看板画面にすぐ出ます**。
(開き直す必要はありません。共有フォルダがファイルの大きさ・更新時刻を数秒
覚えて返しても、取り込むときは必ず写し直します。)

**看板画面に出るのは、この端末の担当ラインの看板だけです。** 別のラインの表
(担当が機側なのに `看板_AIM` など)に足したときは、「この端末の看板画面には
出ません」と知らせます。担当ラインを変えると、**変えた先のラインをその場で
取り込む**ので、すぐにそのラインの看板が出ます(以前は起動したときのラインを
取り込み続けていたため、変えた先の看板が出ませんでした)。

#### 看板を消すとき

* **発注中(赤)・発送済み(緑)・注文中(黄)の看板は消せません。** 消すと倉庫からもその発注が
  見えなくなり、注文の行き場が無くなるためです。先に看板の画面で片付けて(届いたら赤を消す・
  倉庫は発送や注文中を外す)から消してください
* 消した看板の**コメントは片付けます**(同じ番号で足し直したとき、前の看板のやり取りが
  新しい看板に出ないように)。やり取りは共有DBに残り、看板集計の明細 CSV で見られます
* 消した看板に、どこかの端末の**まだ共有DBへ送っていない操作**が残っていても、
  その端末が次に取り込んだときに看板ごと取り除きます(送り先が無いため。ログに
  「共有DBから消された看板の未反映の操作を捨てました」と残ります)。以前は
  消した看板が看板画面に出続け、「要確認」からも消えませんでした
* 同じ番号で足し直しても、前の看板の状態は引き継ぎません
* 看板の表(`看板_<ライン>`)以外の表は、マスタ管理では**読むだけ**です(理由が出ます)。
  表そのものを足す・消すことは、このツールではできません

#### 「画面を開き直してください」と出たとき

表を開いたあとに、別の端末が行を消して入れ直した・DB Browser で最適化した、
などで**表の中身が入れ替わっている**と、直す・消すを断ります(以前は別の看板を
直してしまうことがありました)。表を開き直してからもう一度操作してください。

#### 足す・直すときに断られるもの

**看板として盤に出ない形は、足すことも直すこともできません。** どれも以前は
「足しました/更新しました」と言われるのに、盤に出ない・印が効かない、という
気付きにくい形になっていました。

| 断られるもの | なぜ |
| --- | --- |
| `管理番号` が空 | キーが無い行は、あとから誰も直せない |
| すでにある `管理番号` | 同じ番号が 2 行あると、1 回の操作で 2 行とも動く |
| `資材` か `サイズ` が空 | 盤は資材とサイズの両方がある看板だけを出す |
| **同じ資材・同じサイズ**の看板がもうある | 盤はこれを 1 枚にまとめるので、2 枚目は出ない |
| 看板の状態の欄(`欲` `不` `更新日` `発送` など)を直す | 状態はボタンが組にして書く。上の「看板の状態は、ここでは直せない」 |
| `常設品` が `〇` `×` 空欄 のどれでもない | アプリは印を 1 文字で見分ける。似た字は印が無いものとして扱われる |
| 数値の欄に数でないもの(`nan` なども) | `nan` はキーの無い行になっていた |
| (状態以外の)日時の欄に日時でないもの | `2026/08/31 09:00:00`(VBA の `2026/8/31 9:00` も可) |

**`〇` と `○` は別の字です。** `〇` は「ぜろ」で出る漢数字、`○` は「まる」で
出る記号です。看板の印は `〇` です(`常設品` の初期値にも入っています)。
`×` は「ばつ」で出る字で、英字の `x` では効きません。

直すときは**直した欄だけ**を確かめます。昔から入っている変わった値が他の欄に
あっても、関係のない修正まで断ることはありません。

**ここで直した内容は全端末に効きます。** マスタ管理は**看板そのものを
増やす・減らす**、資材やサイズを直すための場所です。

接続先が設定されていない、または共有フォルダに届いていない端末では、
**マスタ管理は開けません**。理由と、次に何をすればよいかが表示されます。

#### Access の最新で表の中身を入れ替える

Access で看板を足した・サイズを直したなど、**Access のほうが新しい**ときに使います
(python-web-tools(梱包資材総合ツール)の「中身を入れ替える」と同じつくり)。

**Access をまるごと変換して共有DBを差し替えないでください。** このツールが共有DBに
足した表・列・行 ── 看板履歴(集計の記録)・看板コメント・それぞれの索引、そして
Access には届いていない看板の状態(赤・緑・注文中とその日時)── が消えます。

1. 「設定」→「マスタ管理」の「**Access の最新で表の中身を入れ替える**」
2. Access(`.accdb`)を枠に**落とす**か、「参照...」で選ぶ(変換した `.sqlite3` でも可)
3. Access と共有DBの**両方にある表**が並びます。看板の表には「変わる・足す・消す」の枚数、
   入れ替えられない表には理由が出ます
4. 入れ替える表に印を付けて「**選んだ表の中身を入れ替える**」(確認が出ます。管理者パスワードが要ります)

| 表 | 入れ替えたときどうなるか |
| --- | --- |
| 看板の表(`看板_<ライン>`) | 管理番号で突き合わせ、資材・サイズなどを Access の最新にする。**状態の列(欲・不・更新日・発送・倉庫確認日時・保留・注文中日時)はいまの値のまま**。Access で足された看板は足し、Access に無い看板は消す ── ただし**発注中・発送済み・注文中のものは消さずに残す** |
| そのほか両方にある表 | 中身を Access の中身にする |
| 看板履歴・看板コメント・Form状態管理 | **入れ替えない**(このツールが書き込む表) |
| Access にだけある表・共有DBにだけある表 | 触らない |

* 表の定義(列・索引)は変えません。**同じ名前の列だけ**を写し、Access にしか無い列は写しません
* 文字化けの疑いがある表・管理番号が空や重なっている看板の表は入れ替えません(理由が出ます)
* 1 つの表は「消す+入れる」を 1 回で確定します。途中で失敗しても、その表は元のままです
* 書く前に共有DBの控えを、この端末の `backup` フォルダ(`%LOCALAPPDATA%\KanbanSystem\backup`)へ
  取ります(新しい 10 個まで)。戻したいときはこの控えを使ってください。
  **控えは「入れ替える前の中身」です。** 入れ替わったかを確かめるときは、結果に出る
  「書き込んだ共有DB」(接続先のファイル)を開いてください。結果には、書いたあとで
  そのファイルを直接開き直して確かめた行数も出ます
* DB Browser for SQLite などで共有DBを開いたまま入れ替えた場合は、その画面は古いままです。
  開き直してから確かめてください
* 入れ替えたらこの端末は取り込み直します。ほかの端末には次の取り込み(30 秒ほど)で届きます
* `.accdb` は移行の変換(`tools/accdb_to_sqlite.py`)と同じ内蔵リーダーで読みます(Access も ODBC も要りません)

### 1.3.4 看板集計

「設定」→「**看板集計**」で、看板を**いつ出して・何日で届いて・次に出すまで
何日空いたか**を数えます。読むだけなのでパスワードは要りません。

#### 何を記録しているか

ボタンを押して看板の状態が変わるたびに、その出来事を記録します。各端末に
溜めた記録は、書き戻しと一緒に **`看板履歴.sqlite3`**(看板マスタとは別のファイル。
全端末で共有)へ集まります。看板集計はこのファイルを読みます。

| 出来事 | いつ |
| --- | --- |
| 出した | 赤(発注)が点いた |
| 発送 | 緑(発送済み)が点いた |
| 届いた | 発送済みのあとで赤を消した(一括リセットも含む) |
| 取消 | 発送される前に赤を消した(押し間違い。回数に数えない。下の例外あり) |
| 発送取消 | 緑だけ消した |
| 注文中 | 倉庫が黄(注文中 = 在庫切れで仕入れ先へ注文)を付けた |
| 注文中解除 | 黄を外した(発送して自動で外れたときも) |
| 倉庫に表示 | 出した看板が**倉庫の端末に初めて取り込まれた**(押す操作ではない。倉庫の端末が自動で書く) |

**押し間違いの扱い** ── 基本は**状態の変わり方**で見分けます(発送前に赤を消した = 取消で、
時間は問わず数えない。緑を付けてすぐ消した = 発送取消で、最後の発送だけを使う)。
状態だけでは見分けられない次の 2 つは、**5 分以内**(「看板集計」タブの「押し間違いとみなす時間」で
変えられます。0 で時間では除かない。配布設定でも配れます)なら押し間違いとして数えません
(記録は残すので、時間を変えれば過去の分も数え直します):

* 注文中(黄)を付けて、すぐ外した
* 発送の無いライン(NS1 など)で、赤を付けてすぐ消した(このラインは赤を消すと「届いた」になるため)

* **置き場所**: 既定は**共有DB(看板マスタ)と同じフォルダの `看板履歴.sqlite3`**。
  「設定」→「接続先」→「看板履歴の置き場所(看板履歴.sqlite3)」で変えられます
  (管理者パスワード。まだ無いファイル名を入れるとそこに作ります。看板マスタ・梱包資材マスタなど
  ほかの表の入ったファイルは選べません)。**全端末で同じ場所を指してください** ── 違うと記録が
  別々のファイルに分かれ、集計が欠けます。配布設定に入ります(既定で入る)。
  置き場所を変えると、**前の場所の記録のうちまだ無いものを新しい場所へ写します**(前のファイルは残ります)
* **ファイルと表は自動で用意します。** 起動したとき・接続先や置き場所を変えたとき・
  記録を送る前に確かめて、無ければ作り、足りない列があれば足します
  (前からある行と余分な列は消しません。足した列は空になります)。
  倉庫参照モードは共有フォルダへ書かないので作りません
* **以前の置き場所の記録**: 以前の版は看板マスタの中の `看板履歴` 表へ書いていました。
  起動するたびに、そこにある行のうち**看板履歴.sqlite3 にまだ無いものだけ**を写します
  (ID で見分けるので 2 回入りません。入れ替えの途中で古い版の端末が看板マスタへ書いた分も、
  次に誰かが起動したときに写ります)。**看板マスタの表は消しません**(控えとして残ります)
* **記録はこの版から始まります。** それより前の分はありません。
* 押した記録は、その端末の書き戻し(数秒〜60 秒)のあとで集計に入ります。
  共有フォルダに届かない間は端末に残り、届いたときに送られます。

#### 画面

* 期間(月から月まで。既定は今月までの 12 か月)とライン(全部 / 1 本)を選んで「集計する」
* **届くまでの日数** … 期間全体の平均・最短・最長・届いた回数を、いちばん上に出します
* **グラフ** … ライン × 月の線グラフ。「提出率(%)」「出した回数」「届くまで(平均日数)」を
  切り替えます。
  線に指を合わせると、その月の全ラインの値が出ます。凡例を押すとそのラインを
  隠せます。数字は「表で見る」にもあります
* **ラインごとの要約** … 出した回数・週平均・月平均・届くまでの日数(平均・最短・最長)・
  次に出すまでの平均日数・未着(出したがまだ赤が消えていない回)
* **注文中(在庫切れ)・倉庫の画面に出るまで** … いちばん上の 2 段目。注文中の回数(何枚の看板で・
  いまも注文中の回)、注文中の平均日数、出してから倉庫の画面に出るまでの平均時間、出てから発送までの
  平均時間。「出した → 倉庫に出る → 発送」のどこで時間が掛かっているかを分けて見られます
  (倉庫に出るまでが長い = 倉庫の端末が閉じていた、出てから発送までが長い = 準備)
* **よく切れる資材** … 注文中にした看板を回数の多い順に。平均・最長・合計の日数と、いま注文中なら
  いつからか
* **使用量** … 1 回の量(サイズ欄の「:」の右。`2200 × 50M : 3本` なら 3 本)× 出した回数。
  月あたりの多い順。在庫の量・仕入れ先への注文量の目安
* **看板ごとの届くまでの日数** … 看板ごとの出した回数・届いた回数・届くまでの日数
  (平均・最短・最長)・次に出すまでの平均日数。平均の長い看板から並びます

#### 数え方

* **提出率** = その月に 1 回以上出した看板の枚数 ÷ そのラインの看板の枚数
  (いまマスタにある、資材・サイズの入った行)。同じ看板を月に 2 回出しても 1 枚
* **日数**は日付の差です(9/1 に出して 9/3 に届けば 2 日)
* **届くまでの平均・最短・最長**は、届いた回だけで出します(まだ届いていない回は入れない)。
  月ごとの平均は、その月に**出した**回で数えます
* **週**は月曜日から日曜日まで
* 回は「出した日」の月・週に数えます
* 1 回は**出した日時**で見分けます(どの記録にもその回の出した日時が入っています)。
  端末ごとに時計が少しずれていても、記録が届く順番が前後しても、同じ回としてつなぎます
* 「取消」でも、次のときは**届いた**として数えます
  * その回に倉庫が発送していた(倉庫の発送を現場の端末が取り込む前に赤を消すと、
    現場の端末は「取消」と記録するため)
  * 発送する人のいないライン(倉庫の画面に無く、現場も発送を押せない。NS1)。
    赤を消すのは届いたときだけなので

### 1.5 設定を入れてから配る(配布設定)

**1 台で決めた設定を、配った先の端末でそのまま使うための仕組みです**
(python-web-tools(梱包資材総合ツール)の「配布設定」と同じつくり)。

設定は端末ごとの設定ファイル(`%APPDATA%\KanbanSystem\config.json`)に入ります。配った先で 1 台ずつ設定画面を
開いて打ち直すのは手間で、打ち間違えると別のファイルを読み書きする端末が
できます。しかも管理者パスワードが空のまま配ると、**最初に押した人が
パスワードを決められます。**

#### 流れ

1. 1 台で起動して設定し、設定画面の「**配布設定**」で**書き出す**
2. アプリのフォルダの直下に **`配布設定\`** ができ、配るものが全部そこに入る
3. 「**配布用フォルダを作る**」(または `scripts\make_dist.bat`)で、配るものだけを
   アプリの**隣**の新しいフォルダへ写す
4. そのフォルダを配る。配った先は**起動したとき `配布設定\` を見つけて読み込む**

```
看板システム\                    ← 1 台目(ここで設定して書き出す)
  配布設定\                      ← 書き出すとできる
    設定.json                    ← 接続先・間隔・自動印刷・管理者パスワード(撹拌した値)
    はじめに読む.txt             ← 何が入っているか・配った先で何が起きるか

資材発注看板システム_VER3.0.0_<日時>\   ← 「配布用フォルダを作る」でできる(これを配る)
  配布設定\  配布メモ.txt  start.bat  …
```

#### 手順

1. 配る元の端末で、接続先(「接続先」タブ)・動作・管理者パスワード(「パスワード認証」)を設定する
2. 「設定」→「配布設定」→「この端末の設定を配布設定にする」で、入れる項目に
   チェックを付けて「**配布設定を書き出す**」
   * 各項目の横に、この端末のいまの値が出ます。**この端末で変えていない項目は
     入りません**(配った先も同じ既定で動くため)
   * **担当ラインは既定で入れません**(入れたまま配ると全部の現場が同じラインを名乗る)
3. 書き出した直後に、**配った先と同じ読み方で読み戻して確かめた結果**が出ます。
   すべて ✓ なら完了です
   * 「配布設定」フォルダがある / `設定.json` がある / 読める
   * 書き出した値がそのまま入っている / 管理者パスワードが入っている
   * `はじめに読む.txt` がある
4. 「**配布用フォルダを作る**」を押す。アプリの隣に `資材発注看板システム_VER…_<日時>`
   ができ、画面に中身(入れた配布設定・ファイル数)が出ます
5. そのフォルダを配る。中の `配布メモ.txt` に、配った先ですることが書いてあります

#### 配った先で起きること

* **起動したときに `配布設定\` を読み込みます。その端末にすでにある設定は
  読み込みません**(値が入っている項目はそのまま。無い項目だけ埋める)
* 埋まった項目は次から「すでにある」ので、端末で直した値が戻されることは
  ありません
* 狙って揃えたいときは「配布設定」→「**配布設定を読み込み直す**」
  (すでにある設定も上書きします。接続先が変わればその場で繋ぎ直します)
* 担当ラインとモードは、配った先で「この端末」から選んでください

読み込めたかは、配った先の「配布設定」タブの「この端末が最後に読み込んだ日時」、
ログの `配布設定を読み込みました: …`、`python start_app.py --check` の
`配布設定` で分かります。

#### 配布用フォルダに入れないもの

* `tests\`・`.git`・`__pycache__`・`*.sqlite3` など
* `data\`(一時期の版がアプリのフォルダに置いていた、その端末の設定)

この端末の設定はアプリのフォルダの外にあるので、アプリのフォルダを手でコピーして
配っても構いません(`配布設定\` が一緒に入っていれば、配った先が読み込みます)。

#### 新しい版に入れ替えるとき

新しい版のフォルダで「配布用フォルダを作る」前に、古い版で書き出した
`配布設定\` を新しい版のフォルダの直下へコピーしておけば、設定ごと入れ替え
られます(`配布設定\` はリポジトリ(GitHub)には入っていません)。
すでに使っている端末の設定は `%APPDATA%` にあるので、**アプリのフォルダを
入れ替えてもそのまま残ります**。

#### 前の版からの引き継ぎ

* 一時期の版がアプリのフォルダの `data\config.json` に置いていた設定は、残って
  いれば**この端末に無い項目だけ** 1 度引き継ぎます(この端末で決めてある値は上書きしない)
* 前の版で作った `配布設定\config.json`(項目が平らに並ぶ形)も読みます。
  次に書き出すと今の形(`設定.json`)に置き換わります

どちらも、空欄と組み込みの既定と同じ値は「決めていない」として読みます
(空欄のパスワードで配布設定のパスワードを消さないため)。

#### 手で書き換えるとき

`%APPDATA%\KanbanSystem\config.json` と `配布設定\設定.json` はメモ帳で直せます。

* 数字は `45`、する/しないは `true` / `false` で書きます。`"45"` や
  `"false"` のように引用符で囲んでも、意味どおりに読みます
* 読めない値は**読まずに**組み込みの既定で動きます
* この端末の設定ファイルが壊れて読めないときは、上書きせずに
  `config.json.読めなかった_<日時>` として残します(直せば中身を取り戻せます)

## 2. 複数ライン(複数端末)での運用

### 2.1 既定の構成: 各端末ローカル SQLite + Access が正データ

`sqlite_path` は指定不要です(既定でこの端末のローカルディスクを使います)。
**手元の SQLite を複数端末で共有する構成ではありません。** 共有 SQLite
(`shared_db_path`)が唯一の正式なデータであり、各端末のローカル SQLite は
「その端末専用の作業用の写し + 送信待ちの一時置き場」です。

```
 ライン1のPC              共有 SQLite(.sqlite3)            ライン2のPC
┌───────────────┐        ┌──────────────┐        ┌───────────────┐
│ SQLite(ローカル)  │        │              │        │ SQLite(ローカル)  │
│ ・マスタの写し      │◀──読込── │   共有・正データ   │ ──読込──▶│ ・マスタの写し      │
│ ・入力した発注/発送 │──書込──▶│              │◀──書込── │ ・入力した発注/発送 │
└───────────────┘        └──────────────┘        └───────────────┘
```

動作の流れ:

1. ボタンを押すとローカル SQLite に保存され、即座に画面へ反映される(高速)
2. その直後(数秒〜既定 60 秒以内)に、変更のあった列だけを自動で共有DBへ
   書き戻す(2.2 参照)
3. 既定 30 秒ごとに共有DBを読み直し、他ライン・倉庫が書き戻した内容を
   このローカル SQLite へ取り込む(2.3 参照)

複数端末が同時に読み書きする相手は **共有 SQLite 1 つ**です。書き込みの
直列化は SQLite 自身のファイルロックに依存するので、**その共有フォルダで
ロックが正しく効くことを先に確かめてください**(1.2.2)。

手元での工夫は次のとおりです。

* ロック競合は 3 回・1/2/3 秒でリトライする(`kanban/db/shared.py`。VBA 版と同じ)
* **WAL を使わない。** WAL は共有メモリ(`-shm`)を要求しますが SMB には
  それが無く、共有フォルダに置いた WAL のファイルは読むことすらできません
* 読むときは読み取り専用(`mode=ro`)で開く
* 書き込みは 1 文ずつ自動コミットし、長く掴み続けない
* 送るのは 60 秒ごとのまとめ送り(と操作直後)で、1 回の量も小さい

ローカル SQLite はどの端末でも 1 プロセスしか触らないため、そちらは
共有フォルダの事情に影響されません。

### 2.2 Access への書き戻し(SQLite → Access)

* 既定 60 秒ごと、および操作の直後に書き戻しを試みます
* 変更のあった **列だけ** を UPDATE します(2.4 参照)。マスタ列
  (資材名・サイズ等)は書き戻しません
* 画面右下に「Access へ未反映 N 件」と表示されます
* アプリ終了時にも必ず 1 回書き戻します(未反映があれば進捗画面が出ます)
* 書き戻せなかった変更はローカル SQLite に残り、次回起動時に再送されます
  (5 回失敗すると「要確認」として保留され、自動再送は止まります → 4.3)

書き戻しを 1 台に集約したい場合は、他の端末で `export_interval_sec` を `0` にし、
集約する端末だけタスクスケジューラで以下を定期実行してください。

```
python main.py --export-only
```

### 2.3 Access からの再取り込み(Access → SQLite)

他ライン・倉庫が Access へ書き戻した内容は、次のいずれかのタイミングで
この端末のローカル SQLite へ反映されます。

* **定期的な自動取り込み**: 既定 30 秒ごと(`import_interval_sec`)
* **手動更新**: 「設定」→「取り込みの状態」→「↻ いま取り込む」で即座に実行
  (**ふだんは押す必要はありません**。共有フォルダが一時的に落ちていた
  あとなどに使います)

いずれも失敗しても(Access に一時的に接続できない等)ローカルの内容で画面は
動き続けます。手動更新が失敗した場合は「Access への接続に失敗しました。
前回取得できている内容を表示しています。」と表示されます。

現場モードは担当ラインだけ、倉庫モード・倉庫参照モードは表示中の全ラインを
定期取り込みの対象にします(表示していないラインまで取り込むと、その分
Access への問い合わせが増えるため)。

### 2.4 列単位での保護(同じ行を別の列で同時編集しても安全)

現場(欲・不・更新日)と倉庫(発送・倉庫確認日時)は、しばしば **同じ行の
別々の列** をほぼ同時に操作します。ローカル SQLite が端末ごとに独立している
ため、単純に「行全体を読んで書き戻す」実装だと、片方の端末が自分の知る
(Access より古いかもしれない)値で相手の変更を上書きしてしまう恐れが
あります。

これを避けるため、各行には「この端末が実際に変更を意図した列」だけを
記録しており(`dirty_columns`)、

* 書き戻しはその列だけを Access へ送る(他の列には触れない)
* 再取り込みはその列だけを保護し、それ以外の状態列は Access の最新値へ
  更新する

という列単位の粒度で動きます。これにより「現場が発注解除した直後、まだ
Access へ送っていない間に倉庫が発送済みにした」というケースでも、どちらの
操作も消えません(`tests/test_sync.py` の
`test_site_and_warehouse_do_not_clobber_each_others_column` で検証)。

同じ行の **同じ** 列をほぼ同時に操作した場合(例: 同じ資材ボタンを 2 人が
ほぼ同時に押す)は、先着が反映され、後着は「他の端末が同じ項目を更新しました。
画面を更新してからやり直してください。」と表示して自動で再読み込みします
(行バージョン `rev` による楽観ロック)。

### 2.5 Access 側を直接編集した場合

Access で `看板_*` テーブルを直接編集した(資材やサイズを追加した)ときは、
既定 30 秒以内に各端末の定期取り込みで反映されます。すぐに反映したい場合は
「設定」→「取り込みの状態」→「↻ いま取り込む」を押すか、以下で取り込み
直してください。

```
python main.py --import-only
```

未反映(まだ Access へ書き戻していない)行の状態は、取り込みで上書きされません。

### 2.6 検証結果

同一の SQLite に対する排他制御(行バージョン `rev`・トランザクション)は、
別プロセス(= 別端末相当)を複数同時に起動して確認しています
(`tests/test_concurrency.py`)。6 プロセス × 40 操作(計 240 回)で
**エラー 0 件・ロック待ちによる失敗 0 件**、`rev` の増分合計と実際に適用
された操作件数が一致(**更新の取りこぼし・二重反映なし**)、矛盾した状態
(欲と不が同時に `〇` 等)も 0 件でした。

「各端末が別々の SQLite を持ち、Access を介して伝播する」という既定の構成
そのものについても、2 台分の SQLite と Access 役を用意し、PC1 の操作が
Access を経由して PC2 に伝播すること、PC2 自身の未反映操作が PC1 由来の
再取り込みで消えないこと、現場と倉庫が別々の列を同時に操作しても互いを
消し合わないことを確認しています(`tests/test_sync.py` の
`LocalPerMachineConvergenceTest`)。

### 2.7 共有フォルダ上の SQLite について(必読)

正データが共有フォルダ上の SQLite になったため、以下は**既定の構成に
そのまま当てはまります**。

* SQLite は「読み取りは複数プロセス同時可、書き込みは常に 1 プロセスずつ」
  という制約を持ちます。この構成では、複数端末からの書き込みの直列化を
  SQLite 自身の OS ファイルロックに依存することになります
  (1 回の書き込みはミリ秒未満で終わるため、通常は体感上問題になりません)
* SQLite は公式にネットワークファイルシステム上での使用を推奨していません
  (SMB/NFS 実装によってはファイルロックが不完全な場合がある)。採用する
  場合は必ず本番投入前に実環境で検証してください。

検証のしかたは 1.2.2 を参照してください(導入前に必ず実施)。

## 3. 日常操作

### 3.1 現場モード

* サイズボタン: 発注 ⇄ 発注解除
* 発注中(赤)+ 発送済み(緑)のボタンを押すと「この資材は届いていますか？」の確認
* 「届いた資材を一括確認(リセット)」: 赤と緑が両方点灯している項目をまとめてリセット
* 「印刷」: 未発送の注文票を新しいタブで開く。**刷る前に打ち替えられます**(3.4)
* ボタンにマウスを乗せると発注 / 発送時刻が出る

### 3.2 倉庫モード

* タブでラインを切り替え(選択中は `【 ライン名 】`)
* 発送ボタンで発送済みにする。**注文中なら一緒に解除されます**
* 注文中ボタンで「仕入れ先へ注文した」を立てる。**発注(赤)のある行だけ
  押せます** ── 発注が無い行は押せない見た目になり、乗せると理由が出ます
  (外すほうはいつでも押せます)
* 「表示中のラインを全て発送済みにする」: 未発送の発注をまとめて処理。
  **1 つずつ押したときと同じで、注文中も解除されます**
* 「発送明細」/「非常設品リスト」: 新しいタブで開く。**刷る前に数などを打ち替えられます**(3.4)

### 3.3 倉庫参照モード

表示のみ。クリックしても何も起こりません。

### 3.4 印刷する前に直す(現場・倉庫ともに)

「🖨 注文票」「🖨 発送明細」「🖨 非常設品リスト」を押すと、新しいタブに
**印刷前の確認画面**が出ます。ここで**そのまま打ち替えられます**。

```
[🖨 印刷する] [元に戻す]  印刷する行: 3
  マスを押すと直せます(紙だけ。看板のデータは変わりません)。
  左のチェックを外した行は印刷されません。
```

* **マスを押して打ち替える** … 数や資材名をその場で直せます。直したマスは
  黄色くなります
* **左のチェックを外す** … その行は印刷されません(画面では取り消し線)
* **「元に戻す」** … システムが出した値に戻ります
* **「印刷する」** … 印刷ダイアログが出ます(Ctrl+P と同じ)

**ここで直しても看板のデータは変わりません。** 直るのはその紙だけです。
資材名やサイズそのものを直したいときは、「設定」→「マスタ管理」を使って
ください(1.3.3)。

直した跡の色・取り消し線・チェック欄は**紙には出ません**。打ち替えなければ、
出来上がる紙は今までと変わりません。

タブを閉じると打ち替えた内容は消えます。刷り直すときはもう一度打ち替えて
ください。

#### 紙の端の余白

**プリンターは紙の縁から 4mm ほどには印刷できません。** 画面のプレビューは
紙の端まで描くので、収まって見えても紙では切れることがあります。帳票は
**文字・罫線・見出しの灰色の帯をすべて紙の端から 5mm 以上内側**(上下 8mm・
左右 7mm)に置き、どのページも同じ余白で刷ります。長い資材名・サイズは
マスの中で折り返します(以前は折り返さず、右端が紙の端まで出ていました)。

印刷ダイアログの「**余白**」は「**既定**」のままにしてください。「なし」に
すると、ブラウザがこの余白を 0 に上書きします。

### 3.5 更新のしかた(**何もしなくて構いません**)

**VBA 版のように画面をダブルクリックする必要はありません。** 開きっぱなしに
していても、勝手に最新になります。

| | 間隔 | 設定 |
| --- | --- | --- |
| 画面が手元のデータを見に行く | 5 秒 | `refresh_interval_sec` |
| 手元が共有DBから取り込む | 30 秒(**共有DBが変わったらすぐにも**) | `import_interval_sec` |
| 共有DBが変わったかを見る(大きさと更新時刻だけ。中身は写さない) | 2 秒 | - |
| 手元が共有DBへ書き戻す | 60 秒(**押した直後にも**) | `export_interval_sec` |

つまり **5 分放置しても、そのとき画面に出ているのは最新**です。自分が押した
操作・書いたコメントは即座に画面へ出て、他の端末の操作は上の経路で届きます。

**他の端末の操作・コメントが自分の画面に出るまで**は、実測で **5 秒前後**です
(押した直後に書き戻し → 2 秒ごとの見張りが共有DBの変化に気付いてすぐ取り込む →
画面が 5 秒ごとに見に行く)。**何も押さなくても出ます。** Windows の共有フォルダは
ファイルの大きさ・更新時刻を数秒覚えて返すので、もう数秒遅れることがあります。
見張りが気付けなかったときも、30 秒ごとの取り込みで必ず届きます。

画面を裏に回していた(別の窓が上にある、別のタブを見ていた)場合は、**戻って
きた瞬間に取り直します**。ブラウザは裏のタブの動きを間引くので、戻ったときに
古いまま数十秒待たされないようにしてあります。

どうしても今すぐ確かめたいときは、ブラウザの再読み込み(F5)で構いません。
共有フォルダから取り込み直したいときは「設定」→「取り込みの状態」→
**「↻ いま取り込む」**です(1.3.2)。

#### 更新が止まったら、帯に出ます

自動更新の弱点は「**動かなくなったことに気付けない**」ことです。共有フォルダが
落ちていると、画面は元気に動いているのに中身だけ古いまま ── VBA 版で
「更新できていないのに気付かない」が起きたのと同じ形です。

そこで、**取り込めていない時間が延びたら帯に出します**。

```
担当 LVC   未反映 0   ⚠ 取り込めていません 12 分前
```

出たら、共有フォルダに届いているかを確認してください(4.2)。**順調なときは
何も出ません** ── いつも出ていると読まれなくなるためです。

### 3.6 いま誰が開いているか(帯の「開いている端末」)

看板画面の帯に、**いまアプリを開いている他の端末**が出ます。

```
担当 LVC   未反映 0   開いている端末  ( HVC? ) ( 倉庫 )
```

倉庫から見て現場が開いていれば、**これから看板が出るかもしれない**と
身構えられます。現場から見て倉庫が開いていれば、いま見てもらえていると
分かります。**押さなくても変わります**(VBA 版は画面をダブルクリックして
更新する必要がありました)。

| 見え方 | 意味 |
| --- | --- |
| 色付きの札(`倉庫`) | いま開いています。マウスを乗せるとホスト名と最終更新が出ます |
| 破線に `?`(`HVC?`) | **開いた印は残っていますが、しばらく更新がありません。** その端末が異常終了した可能性があります |

破線の `?` が出たままのときは、その端末でアプリが強制終了された(電源を
落とした、タスクマネージャーから終了した等)可能性があります。そのまま
放置しても害はありません ── その端末で普通に起動して普通に終了すれば
消えます。**アプリを「■ 終了」で閉じるか、ブラウザのタブを閉じれば、
きちんと消えます。**

出るのは**現場モードと倉庫モードだけ**です。倉庫参照モードは読むだけの
端末なので名乗りません(名乗らせると「倉庫が開いている」が出っぱなしに
なり、本物の倉庫と見分けが付かなくなります)。

「開いた」「閉じた」は**その瞬間に**共有DBへ書かれるので、相手の画面には
取り込み間隔(`import_interval_sec`、既定 30 秒)のうちに出ます。

破線の `?` に変わるまでは **10 分**かかります。開いている端末は 2 分ごとに
「まだ居ます」と書き直しており、それが 10 分途切れたら異常終了とみなす、
という間隔です。**正常に閉じた場合はすぐ消える**ので、この 10 分が効くのは
強制終了されたときだけです。

### 3.6.1 「未反映 N 件」の中身を見る

帯の「未反映」は、**まだ共有DBへ届いていない操作の数**です。押した操作は
まず手元に保存され、数秒〜60 秒のうちに共有DBへ送られます。その待ち行列に
何件あるか、という数です。

**何が届いていないのかは、設定 →「取り込みの状態」で見られます。**

| 列 | 中身 |
| --- | --- |
| ライン / 管理番号 / 資材 / サイズ | どの看板か |
| 操作 | 発注 / 発送 / 注文中 |
| 押した時刻 | いつから残っているか |
| 状態 | 送信待ち / 再送待ち(N 回失敗)/ 要確認(送れません) |

数秒で 0 に戻るのが普通です。**減らないとき**は:

1. 設定 →「取り込みの状態」→「↻ いま取り込む」を押す
2. それでも減らなければ、共有フォルダに届いているかを確かめる(4.2)
3. 「要確認(送れません)」と出ている行は、**待っても減りません**(4.3)

### 3.7 「この画面では操作できません」と出たとき

**同じ PC で、このアプリを 2 枚以上開いています。**

```
この画面では操作できません
このアプリは別のタブで開いています。
2枚とも押せる状態にしておくと、同じ看板を2画面で取り合うことになり、
片方が古い盤のまま押してしまいます。

        [ こちらの画面を使う ]

押すと、もう一方のタブが使えなくなります。
もう一方のタブを使うなら、このタブは閉じてかまいません。
```

いちばん多いのは、**ショートカットをもう一度ダブルクリックした**ときです。
アプリ本体は 1 つのままですが、**ブラウザのタブが 1 枚増えます**(アプリが
すでに動いているので、開いている画面をもう一度出しに行きます)。

やることは 2 つのどちらかです。

| どうしたいか | 押すもの |
| --- | --- |
| **この画面を使いたい** | `こちらの画面を使う` を押す。もう一方のタブが使えなくなります |
| **もとのタブを使いたい** | このタブを閉じる。もとのタブはそのまま使えます |

どちらでも構いません。**放っておいても害はありません** ── 使えないほうの
画面は押せないだけで、データには何もしません。

#### なぜ 2 枚とも使えるようにしないのか

同じラインの同じ看板を 2 画面で取り合うことになるからです。片方で発送を
押した時点で、もう片方は**押す前の古い盤**を見ています。その古い盤で押すと
「別の端末が更新しました」と断られますが、これは**別の端末ではなく自分の
もう 1 枚**です。「まとめて発送」のように件数を数える操作では、見えている
件数と実際の件数がずれます。

VBA 版はフォームが 1 つしか開けなかったので起きなかった形です。ブラウザに
なってタブが開けるようになったぶんの手当てです。

#### 印刷は巻き添えになりません

「🖨 注文票」などを押すと新しいタブが開きますが、**印刷用のタブは別物**
なので、この覆いは出ません。刷る前の打ち替え(3.4)もそのまま使えます。

2 分と長めなのは、**共有フォルダへの書き込みを減らすため**です。共有ファイルは
書き換わると全端末が写し直すので、短く打つほど誰も操作していない時間帯
(夜間・休憩中)まで共有フォルダが働き続けることになります。どれくらい
往復しているかは、「設定」→「取り込みの状態」の**「起動してから写した回数」**で
確認できます ── 誰も操作していないのに伸び続けるようなら、ご相談ください。

### 3.7.1 「発送処理中に注文が取り消されました」と出たとき

**倉庫が発送したのと入れ違いに、現場が赤(発注)を消しました。** 倉庫の発送が
現場の端末に取り込まれる前(最大 30 秒ほど)に赤を消すと、その看板は
「赤なし・緑あり」で残ります(赤を消しても発送の印には触れない。VBA と同じ)。

* 盤面の上に赤い帯が出て、その看板に ⚠ と点線の枠が付きます
* **現場**: 資材を確かめてから、帯の「**確認した**」(またはその看板のサイズ)を押します。
  確認すると発送の印(緑)が消えます。もう一度必要なら、そのあとで出し直してください。
  **確認するまで、その看板は出し直せません**(黙って出し直すと、倉庫が発送した物の
  行方が分からなくなるため)
* **倉庫**: 同じ帯に「現場の確認待ち」と出ます。**倉庫の帯は全ライン分**です
  (どのラインのタブを開いていても出ます)。起きているラインのタブには ⚠ が付き、
  帯の「○○ を開く」でそのラインへ移れます。倉庫で操作する必要はありません
  (倉庫が発送を外しても片付きます)
* 帯は「更新」を押さなくても出ます・消えます(取り込みの間隔 30 秒ほどで)
* 画面がまだ気付いていないうちにその看板を押した場合も、出し直さずに同じ確認が出ます

看板集計では、この回は「届いた」として数えます(1.3.4)。

### 3.7.2 看板ごとのコメント(倉庫 ⇔ 現場のやり取り)

看板の右端の **💬** を押すと、その看板についてのやり取りを書けます・読めます
(例:「来週入荷です」「月曜朝に使うので急ぎでお願いします」)。

* **書けるのは現場と倉庫**。倉庫参照モードは読むだけです。1 件 200 文字まで、
  Ctrl+Enter でも送れます。パスワードは要りません
* **コメントは段階に結び付いています**(どの段階の話なのかが分かるように)。

  | 書ける側 | 書けるとき |
  |---|---|
  | 現場 | **赤を付けたあと**、倉庫がまだ黄・緑を付けていないあいだ |
  | 倉庫 | **黄(注文中)か緑(発送)を付けたあと**、現場が赤を消すまで。赤だけのあいだは、**現場のコメントへの返事だけ**書けます(押す前に問い返せる) |

  赤が付いていない看板、緑が付いたあとの現場(受け取るだけ)は書けません。書けないときは、
  💬 を開くと理由が出ます(読むことはいつでもできます)
* **ボタンが押されると、それまでのコメントは確認済みになります**(赤・黄・緑・赤を消す・一括確認・一括発送。
  現場・倉庫どちらが押しても)。やり取りの中に「── 倉庫が注文中(黄)にした(ここまで確認済み)」の区切りが入ります
* **やり取りは、現場が受け取る(赤と緑を消す)・赤を取り消すまで開いたまま**です。赤 → 現場の一言 → 倉庫の返事
  → 黄 → 倉庫の一言 → 緑 と、その回のやり取りを続けて読めます(盤の 💬 の数もそのまま)。受け取ったら
  「前の回のやり取り」へ畳みます(消えません。最後に「ここでこの回は終わり」と出ます)
* 確認済みの分を隠したいときは、やり取りの下の「**確認済みを畳む**」を押します(区切りは残り、吹き出しだけ
  隠れます。「確認済みの N 件を開く」で戻せます)。畳むかどうかはこの端末に覚えます(はじめは開いたまま)
* **相手のコメントは、読んでからでないとボタンを押せません。** 相手からの未読がある看板を押すと、
  先に「💬 相手からのコメントがあります」の小窓で中身を出します(この時点ではまだ何も変わりません)。
  「確認して進める」で押したことになり、読んで押すボタンが変わるときは「やめる」を押して押し直します。
  * **もう読んだコメント(💬 を開いた・同じ側のほかの端末で開いた)なら、小窓は出ずにそのまま押せます。**
    自分の側のコメントだけの看板も出ません
  * 相手のコメントがこの端末に届いたばかりで、盤にまだ出ていない数秒のあいだに押しても、押したところで
    止まって小窓が出ます(読まずに進むことはありません)。ただし、**相手が送ったのとほぼ同時(2〜3 秒以内)に
    押した**場合は、まだこの端末に届いていないので止められません(同時に押したのと同じ扱い)
* 例: 現場が赤 +「100 個で」→ 倉庫が開いて読み「了解」と返事 → 倉庫が黄(読んだので小窓なし。区切りが入る)
  → 倉庫が「在庫切れ、来週入荷」→ 倉庫が緑(区切り)→ 現場が読んで受け取る(赤と緑を消す)→ ここで前の回へ畳む。
  受け取るまでは、どの端末で開いても最初の「100 個で」から全部見えます
* 書いた相手には、看板の 💬 に**赤い点**と、盤面の上に「**💬 新しいコメント N 件**」の帯が
  出ます。「開く」か 💬 を押して開くと既読になります(返事を書いたときも既読)
* **既読は側ごとに共有します。** 倉庫の端末のどれか 1 台で開けば**倉庫の全端末**で既読に、
  現場はそのラインの端末のどれか 1 台で開けば**そのラインの現場の全端末**で既読になります
  (ほかの端末には取り込みの間隔で届きます)。現場が開いても倉庫の未読は消えません(逆も同じ)。
  **倉庫参照モードで開いても倉庫の既読にはしません**(見るだけの端末なので、その端末の中だけ)
* 自分の側が書いたコメントには、相手側が読むと「**✓ 既読 日時(倉庫 PC名)**」、まだなら
  「まだ読まれていません」と出ます
* **倉庫の帯は全ライン分**です(どのタブを見ていても出ます)。コメントのあるラインの
  タブに 💬 が付き、帯の「開く」で別のラインのやり取りもそのまま開けます
* 受け取って畳んだ分は、開いたときの「前の回のやり取り」と、看板集計の
  **明細 CSV の「コメント」列**で見られます(消えません)
* 書いたもの・既読の印は押した(開いた)直後に共有DB(看板マスタ)の `看板コメント` 表へ送られ、
  **ほかの端末には 5 秒前後で届きます**(何も押さなくても出ます。3.5)。表は自動で用意します。
  既読の印は同じ表に「種類 = 既読」の行として入ります(集計・CSV には出ません)

### 3.8 画面の明るさ(ライト / ダーク)

帯の右上、モードの札の隣のボタンで切り替えます。押すたびに
**◐ 自動 → ☀ ライト → ☾ ダーク → ◐ 自動** の順に変わります。

* **自動**(はじめはこれ)… Windows の設定(「設定」→「個人用設定」→「色」→ アプリのモード)に合わせます
* 選んだものは**この PC に覚えます**(ほかの PC には広がりません)。ブラウザ版とデスクトップ版は
  別々に覚えます
* **看板の赤・緑・黄はダークでも同じ色です**(押せない看板も色が分かるように少しだけ沈めます)。
  何も出ていない看板(灰色)だけ、暗い灰色になります
* 帳票(印刷)は紙に出すものなので、いつも白地です

## 4. トラブル対応

### 4.1 ログと記録の場所

```
<置き場所>\KanbanSystem\<ライン名>\DebugLog_<日時>.txt        … 動作のログ(起動ごとに 1 本)
<置き場所>\KanbanSystem\記録\<年月>\<PC名>_<年月日>.jsonl    … 記録(後追い・なぜなぜ用)
```

置き場所は「設定」→「記録」→「記録(ログ)の置き場所」で変えられます(管理者パスワード。
**変えたその場で書き先が切り替わります**)。既定はこの端末のローカル領域の `logs`
(`%LOCALAPPDATA%\KanbanSystem\logs`)。**共有フォルダを指定すると、全端末の記録を 1 か所に
集めて「記録」タブの「すべての端末」で見られます**(記録のファイルは PC ごとに分かれるので混ざりません。
配布設定で配れます)。この端末の記録は 365 日で片付けます(ほかの PC の分には触りません)。

DebugLog の 1 行は `日時 | 重さ(INFO / WARNING / ERROR)| どこが書いたか | 文` です。
警告・エラーの行の末尾には `[記録 R-…]` の**記録番号**が付き、記録の同じ番号の 1 件に詳細があります。

**デスクトップ版の手がかり**: 起動の記録に `画面: デスクトップ版(ポートなし)` が付きます(ブラウザ版は
`ブラウザ版`)。DebugLog には開いた画面ごとに `画面 GET /board → 200`、最初に
`デスクトップ版の窓から画面がつながりました` が出ます。後者の代わりに「画面から外枠の機能が見えません」と
出ていたら、帳票の窓・保存ダイアログ・モードの切り替えが動いていません(exe の作り直しが要ります)。
Python が起動できなかった・途中で止まったときは、窓に理由・ログの場所・Python の最後の出力が出ます。

### 4.1.1 記録で後追いする(なぜなぜ分析)

**エラーが出たら、まず画面の「記録番号」を控えてください**(想定外のエラーの文の末尾に
「記録番号 R-1001-091530-ab12」の形で出ます)。

記録に残すもの:

| 種類 | いつ |
| --- | --- |
| エラー | 想定外のエラー・処理の失敗。**原因の連鎖**(外側 → 内側の例外と、それぞれが起きたプログラムの場所)とトレースバックまで |
| 警告 | 共有フォルダに届かない・送れない、など(業務は続いたもの)。裏の処理の同じ警告は 10 分に 1 件にまとめ、間引いた数を添えます |
| 断った操作 | 画面の操作が断られた(入力の誤り・権限なし・パスワード違い…)。画面に出した文と理由コード |
| 画面のエラー | ブラウザの中で起きたエラー(押しても何も起きない・表示が止まった、の正体) |
| 操作(足跡) | 状態を変えた操作が通った(何をした直後に起きたかを追うため) |
| 起動・終了 | 版・モード・アクセス権限・各ファイルの場所 |

どの記録にも **端末(PC名・ログインID)・モード・担当ライン・版** を、画面の操作から来たものには
**経路と入力**(パスワードは伏せる)を、エラー・警告には **その時の状態**(未反映・要確認の件数、
最後の取り込み・書き戻しの結果)を付けます。

「設定」→「**記録**」で:

1. 期間・端末(この端末 / すべての端末 / PC ごと)・種類・文字で絞って**探す**。
   記録番号が分かっていれば「記録番号で開く」
2. 1 件を**開く** … 何が・画面に出した文言・いつ・どの端末・モード・どこで・そのときの入力・
   同じ操作の記録・**原因の連鎖**・**直前の操作**(同じ端末・同じ起動のあいだ)・**その時の状態**・
   技術的な詳細(トレースバック)
3. **なぜなぜ分析シート** … 事象・直前の操作・原因の連鎖を入れた下書きが出ます。なぜ 1 は画面に
   出た理由、なぜ 2 から先は原因の連鎖を内側へたどった**候補**です。確かめて書き直し、真因・対策・
   確認を書いて「テキストで保存」(`なぜなぜ_<記録番号>.txt`)
4. 一覧は「一覧を CSV で」で Excel に出せます(件数の傾向を見るとき)

読むだけなのでパスワードは要りません。

### 4.2 共有DBに書き戻せない

**ACE OLEDB / ODBC ドライバの話は無くなりました。** 共有側も SQLite に
なったので、外部ドライバは一切要りません(以前はここに Access Database
Engine の導入手順が並んでいました)。

いま書き戻せない場合、原因は次のどれかです。

1. **共有フォルダに届いていない。** エクスプローラでそのパスを開けるか、
   `python start_app.py --check` で確認してください
2. **読み取り専用になっている。** 共有フォルダの権限を確認してください
3. **ロックが解放されていない。** 他端末が書いている最中なら 3 回・
   1/2/3 秒でリトライします。それでも通らない場合、その共有フォルダの
   ロック実装に問題がある可能性があります(1.2.2 の検証を実施してください)

書き戻しができなくても、**取り込みと画面操作は動作します**(変更は手元の
SQLite に貯まり、書き戻せるようになった時点で送信されます)。

#### 記録に `invalid uri authority` と出ている場合

**アプリ側の不具合でした(直してあります)。** 共有フォルダ
(`\\nlmfangyshrd\…`)へ**書くとき**だけ、パスを SQLite が受け付けない形に
組み直していました。読むのは動くので看板は見えるのに、書き戻し・マスタの
追加や修正がすべて失敗します(マスタに行を足すと「通信に失敗しました
(500)」、書き戻しは「未反映」が減らない)。

新しい版に入れ替えて起動すると、**この理由で諦めていた操作は自動で送り
直します**(記録に「共有フォルダへ書けなかった不具合で止まっていた操作を
N 件 送り直します」と出ます)。

### 4.3 「要確認 N 件」と出る

共有DB側に対象の行が見つからない、または書き戻しが 5 回失敗した項目です。
`看板_*` テーブルから該当の `管理番号` が削除された可能性があります。
ログに `対象行なし` として管理番号が記録されます。

もう 1 つの理由は **「共有DBにその列が無い」** です。`保留` と
`注文中日時` は任意の列なので、持たない `看板_*` テーブルがありえます。
その場合ログにこう出ます。

```
共有DBの 看板_LVC に 保留, 注文中日時 列がありません。この変更は送れません
```

**その列を共有DBの看板テーブルに足せば直ります**(設定 → マスタ管理では
列を足せないので、共有 SQLite を直接直すか、変換前の Access に列を足して
変換し直してください)。列が無いあいだ、その端末では「注文中」ボタンを
**出しません** ── 押せて色も変わるのに共有DBには一生届かない、という
状態を作らないためです。

**「要確認」になった行は、アプリの終了を止めません。** 送りようが無いと
分かっている行なので、待っても減りません。「未反映」の数には出たままです
(届いていないことに変わりはないため)。

### 4.4 起動時に「表示できるデータがありません」

`shared_db_path` が正しいか、共有フォルダへ到達できるかを確認してください。

```
python main.py --show-config
python main.py --import-only --verbose
```

### 4.5 SQLite ファイルが壊れた場合

手元の SQLite を削除して再取り込みすれば復旧できます。ただし **未反映の操作は失われる**ため、
先に `--export-only` を試してください。

```
python main.py --export-only        # 可能なら書き戻す
del <sqlite_path>
python main.py --import-only        # 作り直す
```

### 4.6 画面が重い / 更新が遅い

* `refresh_interval_sec` を大きくする(既定 5 秒)
* `frames_per_row` を増やして 1 画面に収める
* SQLite を共有フォルダに置いている場合、ネットワークの応答が影響します

### 4.7 「すでに起動しています」と出て開けない(閉じたはずなのに)

**デスクトップ版**では、2 つ目を開こうとすると**開いている窓が前に出るだけ**です
(新しく起動しません)。窓が見当たらないときはタスクバーを見てください。
「デスクトップ版が動いています」と出てブラウザ版が開かないのも同じ理由です
(1.1.1)。以下はブラウザ版の場合です。

```
すでに起動しています: site (pid=8372 port=8741)
起動しません: 同じアプリが起動中
```

**このアプリに窓はありません。** 画面はブラウザ、本体は `pythonw.exe` です。
タスクマネージャーの「アプリ」には出てこず、「バックグラウンド プロセス」に
います。だから「どこにも開いていないのに開いている扱い」に見えます。

いまは**ブラウザを閉じれば本体も終わります**(閉じた合図を受けて 8 秒後、
届かなくても無通信 90 秒で終了。書き戻しの途中なら終わってから)。
それでもこの表示が出るときは:

1. **断り書きに出ている `場所` の URL をそのまま開く。** たいていは
   前に開いた画面がまだ生きています。それで用が足りるならこのままで構いません
2. 見覚えが無い・使えない画面なら **`stop.bat`** で止めてから開き直す
3. 「未反映の操作があるため止められません」と言われたら、共有フォルダへ
   届く状態にして書き戻しを終わらせてください。急ぐ場合は
   **`stop.bat --force`**(未反映の操作は手元の SQLite に残り、次の起動で
   送られます)

**「開き直してください」という案内は無くしました。** 窓が無いアプリでは
その案内どおりにできないためです。接続先を変えたときはその場で繋ぎ直し、
取り込み直したいときは設定画面の「↻ いま取り込む」を使ってください
(1.3.2 参照)。

### 4.8 押しても何も起きない / 「この画面では操作できません」と出る

**このアプリを 2 枚以上開いています。** 押してよいのは 1 枚だけです。
やることは「`こちらの画面を使う` を押す」か「このタブを閉じる」の
どちらかです。詳しくは 3.7 を見てください。

これは 4.7 とは別の話です。4.7 は**本体(`pythonw.exe`)が 2 つ**、
こちらは**本体は 1 つでブラウザのタブが 2 枚**です。ショートカットを
もう一度ダブルクリックすると、本体は増えずにタブだけが増えます。

### 4.9 「共有DBに 看板_○○ がありません」と出る

**共有DBから、そのラインの看板の表が無くなっています**(消された・名前が変わった・
中身の違う共有DBを指している)。

* 看板の画面にこの帯が出て、そのラインの**ボタンは止まります**(押しても共有DBへ
  届かないため)。出ているのは最後に取り込んだ内容です
* 「↻ 更新」を押したときも同じことを言います(以前は「Access へ接続できませんでした」と
  出ていて、原因が分かりませんでした)
* 表が戻れば、次の取り込みで帯が消え、元どおり押せるようになります
* 共有DBを Access からまるごと変換し直した直後なら、表の名前が変わっていないか
  (`看板_LVC` など)を確かめてください。中身だけ入れ替えるなら 1.3.3 の
  「Access の最新で表の中身を入れ替える」を使ってください

看板履歴(看板履歴.sqlite3)・看板コメントの表が消された場合は、次に送るときにこのツールが作り直します
(記録は端末に残っているので失われません)。

### 4.10 「未反映 N(要確認 M)」「対象行なし」と出る

**この端末で押した操作が、共有DBへ届いていません。** 送り先の行が共有DBに見つからず、
5 回失敗したものが「要確認」です(待っても減りません)。「設定」→「取り込みの状態」に、
看板ごとに理由が出ます。

| 理由 | 何が起きたか |
| --- | --- |
| `共有DBの 看板_○○ に管理番号 N の行がありません` | 共有DBからその看板が消えた(マスタで消した・Access から差し替えた・接続先を変えた) |
| `管理番号が「６」と書かれていて…一致しません` | 共有DBの管理番号の書き方が違う(全角・空白・文字として入っている) |

**片付け方**(どちらも管理者パスワードが要ります)

* **送れない操作を片付ける** … この端末の届かなかった操作を捨て、共有DBの今の状態に
  戻します。共有DBにある看板は共有DBの状態に、共有DBに無い看板は手元からも消えます
  (捨てた中身はログに残ります)。ふつうはこちら
* **もう一度送る** … 共有DBの側を直した(消した看板を足し直した・管理番号を半角に直した)
  あとに押すと、もう一度送ります

捨てた操作(例: 倉庫が押した発送)は共有DBに届いていないので、必要なら看板の画面で
押し直してください。

帯の「開いている端末」に `L-1?` のような **`?` 付き**が出ているのは、その端末の
「開いている」印が残ったまま 10 分以上返事が無いものです(異常終了・スリープ・
強制終了など)。その端末でアプリを開いて普通に閉じれば消えます。
なお、倉庫・倉庫参照モードでは帯に「担当」は出ません(以前は現場の頃の担当ラインが
残って出ていました)。

## 5. 更新のしかた(版を上げる)

新しいコードを配ったら、`config/app.json` の `version` も上げてください
(例 `3.0.0` → `3.0.1`)。**この番号が、入れ替えの合図になります。**

上げ忘れると、すでに動いている端末は「同じ版だ」と判断して**古いコードのまま
動き続けます**。画面の版バッジも古いままなので、気付けません。

上げてあれば、次に誰かがショートカットを押したときに自動で入れ替わります。

```
動いているのは別の版です(動作中=3.0.0 / ファイル=3.0.1)。古いほうを終わらせます
古い版(3.0.0)を終わらせました。3.0.1 で立て直します
```

* 取り込み・書き戻しの**途中なら終わらせません**。中途半端な書き戻しを残す
  ほうが害が大きいので、そのときは古いほうに合流して次の起動に任せます
* 止められなかったときも合流します(理由は画面に出ます)
* **入れ替えた直後だけ、ポートが 1 つずれることがあります**(`8741` →
  `8742`)。終わったばかりのポートは OS がしばらく離さないためです。
  ブラウザはアプリが正しい URL で開くので操作に支障はありませんが、
  `8741` をお気に入りに入れている場合はその回だけ届きません。
  **次に普通に起動し直せば `8741` に戻ります**

**デスクトップ版は、動いている窓を閉じてから開き直してください。** 窓が開いて
いるあいだに新しい版の exe を押しても、開いている(古い版の)窓が前に出るだけです。
版は 3 か所(`config/app.json`・`src-tauri/tauri.conf.json`・`src-tauri/Cargo.toml`)を
揃えて上げます(食い違うと試験が落ちます)。

どの端末がどの版で動いているかは、画面の帯のバッジ(`VER3.0.0`)、
「設定」→「ファイルの場所」、およびデバッグログの冒頭で確認できます。

## 6. 定期メンテナンス

操作履歴(`operation_log`)は自動削除されません。必要に応じて次を実行してください。

```python
from kanban.db.store import Store
store = Store(r"<sqlite_path>")
store.prune_operation_log(keep_days=90)
```

## 7. VBA 版との並行運用

移行期間中、VBA 版と Python 版を同時に使うことは **推奨しません**。
どちらも Access を更新するため、書き戻しの間隔によっては新しい変更が
古い内容で上書きされる可能性があります。

やむを得ず並行させる場合は、

* Python 版の `export_interval_sec` を短く(10 秒程度)する
* ライン単位で「このラインは Python 版」と決め、同じラインを両方から操作しない

のいずれかにしてください。
