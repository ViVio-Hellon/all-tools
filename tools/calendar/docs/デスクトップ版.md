# デスクトップ版(Tauri)の作り

VER4.0.0 から、ブラウザで開く代わりに**専用の窓(exe)**で動かせるようになりました。
**ポートを使いません。** ブラウザ版(`start.bat` / `Start.vbs`)もそのまま残してあり、予備として使えます。

作りは梱包資材総合ツール(python-web-tools)の VER4.0.0 と同じです(外枠・入口・試験の形をそろえてあります)。

## 何が何をするか(各言語が得意なことをする)

```
ライン管理カレンダー.exe(Rust / Tauri)      … src-tauri/
 ├─ 窓(WebView2)・印刷の窓・終了の確認・多重起動の防止
 ├─ ファイルの保存先を訊く窓(なぜなぜ分析の材料の「ファイルに保存」)
 ├─ Python を子として起動・監視(落ちたら理由の画面。理由は desktop_shell.log にも残す)
 └─ 画面の要求(app://…)を受けて、Python の標準入力へ渡す
        │ 標準入出力(1件 = 見出し1行 + 本文)
        ▼
bridge.py(Python)                             … ポート無しの入口
 └─ Flask アプリを WSGI として呼ぶだけ(待ち受けない)。終わる前に未送信を送り切る
        ▼
app/・calendar_app/(Python)                   … 登録の規則・同期・マスタ管理・画面の組み立て(変わらず)
app/static/js(JS)                             … 画面の操作(変わらず。窓まわりだけ desktop.js)
```

| 担当 | 理由 |
|---|---|
| **Rust**: 窓・起動・終了・多重起動・Python の監視・保存先の窓 | OS の窓とプロセスを扱うのが得意。exe 1つで配れる。ブラウザ版が心拍・自動終了・タブの取り合いで**ブラウザの事情を推し量っていた部分**が、窓の出来事として直接わかる |
| **Python**: 登録の規則・二重登録の防止・同期(送信待ち)・マスタ管理・アクセス権限・配布設定・ログとなぜなぜ分析 | 重い計算は無く、遅いのは共有フォルダとのやりとり(言語では速くならない)。**試験 700 件近くがこの形で書かれている**。書き直す利点が無く、危険だけがある |
| **JS**: 画面の操作 | 今までどおり。デスクトップ版のときだけ、印刷の窓を開く・閉じる・ファイルに保存する を外枠に頼む(`desktop.js`) |

## ポートを使わない仕組み

- 画面は独自の宛先 `app://localhost/`(Windows の WebView2 では `http://app.localhost/`)を読む。
  これは**ネットワークを通らない**(外枠の中で受ける名前)
- 外枠はその要求を Python の標準入力へ渡し、標準出力から応答を受け取る(`src-tauri/src/bridge.rs` と `bridge.py`)
- 起動トークン・Host の確認・別オリジンの確認・画面の取り合いの確認など、アプリ側の守りはそのまま生きている
- 試験で確かめていること:
  - `tests/test_bridge.py`: **ソケットを開くと落ちるようにして** Python を起動しても、画面・操作・印刷・終了が通る
  - `tools/desktop_smoke.py`: exe を本当に起動し、画面の JS から操作が届く・exe・Python・WebView の
    **どのプロセスもポートで待ち受けていない**・exe を止めたら Python も終わる

## ブラウザ版から変わったこと / 要らなくなったもの

| ブラウザ版 | デスクトップ版 |
|---|---|
| 心拍が 90 秒途切れたら自動終了・裏のタブの見張り(`idle_exit`) | **使わない。** 窓を閉じたら終わる(窓が開いている限り動く) |
| タブを閉じたあと、未送信があれば送り切るまで粘る | **終わる前に送り切る**(最大 8 秒。`sync_service.send_before_exit`)。送れなければ件数を覚えて端末一覧に出す(今までと同じ) |
| ポート選び・ロックファイル・多重起動の判定(`launch_guard`) | 外枠が持つ(2つ目は開いている窓を前に出す。OS のファイルロックでも止める) |
| 印刷は別タブ | **別の窓**。「印刷する」で印刷ダイアログ、「閉じる」でその窓だけ閉じる |
| 「ファイルに保存」はダウンロード | **保存先を訊く窓**(OS のもの)。メモ帳で化けないよう BOM・CRLF 付き |
| Edge / Chrome / Firefox | WebView2(Edge と同じ仕組み)。Windows 11 には入っている |
| `start.bat` / `Start.vbs` / `stop.bat` | `ライン管理カレンダー.exe`。止めるのは窓の × か画面の「終了」 |

業務の機能(登録・削除・二重登録の防止・繋ぎ・履歴・マスタ管理と並べ替え・アクセス権限・
管理者パスワード・配布設定・端末一覧とライン予約・同期・ログと記録番号・なぜなぜ分析)は、
**同じ Python がそのまま動く**ので変わりません。

## 動きの約束

| 場面 | 動き |
|---|---|
| 起動 | 窓がすぐ出て「起動しています」→ Python の待機画面 → カレンダー |
| もう1つ起動しようとした | 新しく起動せず、開いている窓を前に出す(OS のファイルロックでも止める) |
| 窓の × / 画面の「終了」 | 同期の途中なら訊く(ブラウザ版の「終了」と同じ確認)。通ったら**未送信を送ってから**閉じる |
| 印刷 | 別の窓で開く。「印刷する」で印刷ダイアログ、「閉じる」でその窓だけ閉じる |
| なぜなぜ分析の材料の「ファイルに保存」 | 保存先を訊く窓が出る |
| Python が見つからない・起動できない | 理由と次にすること(Python の入れ方・pip の打ち方)・ログの場所を窓に出す。`desktop_shell.log` にも残す |
| Python が途中で落ちた | 窓を読み直して理由の画面を出す(最後の出力つき)。`desktop_shell.log` にも残す |
| exe を止めた | 標準入力が閉じるので Python も終わる(取り残さない)。終わる前に未送信を送れるだけ送る |

Python は**同梱しません**。各PCに入っている Python を使います(`python.exe` → `py.exe -3` の順に探す。
`CALENDAR_PYTHON` で指定もできる)。必要なパッケージは Flask だけです(waitress はブラウザ版用)。

## 作り方

**Windows 版は GitHub Actions が作ります**(`.github/workflows/desktop-windows.yml`)。
押すたびに、Python の試験・Rust の試験・exe の作成・exe を起動しての確認まで流れ、
成果物 `LineCalendar-windows` に `LineCalendar.exe` が入ります。

配るとき:

1. 成果物から `LineCalendar.exe` を取ってきて、ツールのフォルダの**直下**に置く
2. `tools\make_dist.bat` を流す(`ライン管理カレンダー.exe` の名前で配布フォルダに入る)

手元で作るとき(開発機):

```
cd src-tauri
cargo build --release            # target/release/LineCalendar(.exe)
python ../tools/desktop_smoke.py --exe target/release/LineCalendar    # Linux は xvfb-run を前に付ける
```

Linux で作るには WebKitGTK が要ります(`libwebkit2gtk-4.1-dev` など)。

## 置き場所の決まり

- exe は `bridge.py` と同じフォルダに置く(上の階層もたどるので、`src-tauri/target/...` から動かしても見つかる)。
  `CALENDAR_ROOT` で指定もできる
- 外枠の記録は `%LOCALAPPDATA%\LineCalendar\logs\desktop_shell.log`(**Python が書けないこと**だけ:
  見つからない・起動できない・知らせずに落ちた)。ふだんのログは今までどおり `calendar_YYYYMMDD.log`
- 版は `config/app.json`・`src-tauri/tauri.conf.json`・`src-tauri/Cargo.toml` の3か所。食い違うと試験が落ちる
- アイコンは `tools/make_desktop_icon.py` で作る(`src-tauri/icons/`)

## 確かめきれていないこと(Windows の実機で見る)

この版の確認は、Linux(WebKitGTK)の上で窓を実際に動かして行いました(WebDriver で
カレンダー → 印刷の窓 →「印刷する」→「閉じる」→ 設定・参照 →「終了」まで操作。Python が
見つからないときの理由の画面・2つ目の起動を止めることも確認)。Windows では GitHub Actions が
「起動して画面の操作が届く・守りに断られない・待ち受けない・止めたら Python も終わる」まで確かめます
(ここで Windows だけの不具合 ── 全操作が「別のページ」と断られる ── が見つかり、直しました)。
次は**実機で人が見る**必要があります:

- 印刷の窓の「印刷する」から実際に紙が出ること(WebView2 の印刷ダイアログ)・余白が 8mm 内側に収まること
- 窓の × で、同期の途中のときの確認ダイアログ
- なぜなぜ分析の材料の「ファイルに保存」(保存先の窓)
- 共有フォルダ(UNC)の参照パスで、同期・マスタ管理が今までどおり動くこと
- exe が社内のセキュリティ(SmartScreen・ウイルス対策・AppLocker)で止められないこと(**未署名**)
