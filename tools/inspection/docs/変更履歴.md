# 変更履歴

版は `config/app.json` の `version` **ただ1つ**が出どころです
(python-web-tools と同じ決まり)。次の場所はすべてここを読むので、
**上げる場所は1か所**です。

| どこに出るか | 形 |
|---|---|
| 画面左上の帯(アプリ名の右) | `VER2.0.0` |
| ブラウザのタブの名前 | `点検表 選択・印刷 VER2.0.0` |
| プレビュー・印刷の進み具合・設定の各画面の右下 | `VER2.0.0` |
| 起動待機画面・終了した画面・起動エラーの画面 | `VER2.0.0` |
| `start.bat`(診断起動)の最初の表示 | `バージョン    : 2.0.0` |
| `stop.bat --status` | `[稼働] 版=2.0.0 …` |
| ログ(`inspection_YYYYMMDD.log`) | `起動: pid=… 版=2.0.0` |
| `GET /api/health` | `"version": "2.0.0"` |

```json
{ "version": "2.0.0" }
```

## 版の上げ方

`メジャー.マイナー.パッチ` の3つの数字だけを使います。
判断の基準は「**現場が何をし直すことになるか**」です。

| 桁 | 上げるとき | 現場に起きること |
|---|---|---|
| **メジャー** | 手順が変わる。押す場所・並び・言葉が変わる | 覚え直しが要る。事前に周知する |
| **マイナー** | できることが増える。既存の手順はそのまま | 触らなければ今までどおり |
| **パッチ** | 直しただけ。見た目も手順も変わらない | 何も要らない。黙って入れ替えてよい |

判断に迷ったら**大きいほうへ寄せます。**

### 上げるときの手順

1. `config/app.json` の `version` を書き換える
2. このファイルの「版ごとの変更」の先頭に、その版で何が変わったかを1節足す
3. 試験を通す(`python -m unittest discover -s tests -t .`)
   ── 版の書き方と、この節があるかを `tests/test_app_config.py` が機械で見ています

配るときは**フォルダごとコピー**します。版が上がっていれば、起動したときに
古い版が動いていても自動で止めて入れ替わります(`launch_guard.py`)。
入れ替えたあとに「どれが入っているか」と聞かれたら、画面左上のバッジを
読んでもらえば答えられます。

## 版ごとの変更

## VER2.1.0

### 統合ツールの通しの点検で見つかったものを直した

操作の手順は変わりません。

- **点検表フォルダが一時的に見えないあいだに「再読込」すると、選んでおいた点検表を全部
  解除していた**(フォルダが戻っても0件のまま。選択の控えも消えていた)。見えないあいだは
  選択とカテゴリの位置を保ち、「点検表フォルダが見えません。選んだものはそのまま残しています」
  と知らせる(「一覧を読み直しました」とは言わない)。見えた時点で一覧と突き合わせる
- ブラウザ版の待ち受けの既定を **8781〜8784** に変えた(日報と同じ 8733 で、起動の順で番号が
  入れ替わっていた)。デスクトップ版はポートを使わないので変わらない
- 既定の見た目をライトにそろえた(統合ツールの4ツールで同じ)
- **フォルダの確認(検索)の途中で点検表フォルダを変えると、前のフォルダの一覧が出ていた**
  (画面は「フォルダを変更しました」と言うのに、出ているのは前のフォルダの点検表。控えにも
  前のフォルダを書いていた)。フォルダを変えたら走っている検索の結果は捨てさせ、いまの
  フォルダで調べ直す。検索の結果は、終わった時点の設定と同じフォルダのときだけ入れる
  (`InspectionService.start_scan(supersede=True)`・検索の世代)
- **共有の1つのサブフォルダが一時的に読めなかっただけで、その中の選択が黙って永久に解除
  されていた**(フォルダ全体が見えないときしか守っていなかった)。読めなかったフォルダの中の
  選択は「いったん外しています(読めたら戻します)」と知らせて覚えておき、読めた一覧で
  元の位置に戻す。読めたのに無いときだけ解除する
- サーバが入れ替わって画面を読み込み直すとき、**打ちかけの部数と、設定に打ちかけたフォルダが
  消えていた**。持ち越して戻す(フォルダは設定の画面を開き直して「まだ保存していません」と添える)
- 印刷の進み具合の見張りが、印刷を始めた・表に戻った・再接続した、が重なると2本・3本に
  増えていた。いちばん新しい1本だけが続きを仕掛ける
- 設定のフォルダ参照を続けて押したとき、遅れて届いた前の返事で一覧が戻っていた。最後に
  押したものの返事だけを描く

## VER2.0.0

### デスクトップ版(Python/Tauri/Rust)── ポートを使わない

ブラウザで開く代わりに、専用の窓(`InspectionSheet.exe`)で動くようにしました。
作りは python-web-tools(梱包資材総合ツール)VER4.0.0 と同じです。詳しくは
[デスクトップ版.md](デスクトップ版.md)、移行前の確認は [デスクトップ版_事前確認.md](デスクトップ版_事前確認.md)。
**起動の手順が変わる**ので、版の上の桁を上げました。

- **ポートを使わない**: 窓は `app://`(Windows は `http://app.localhost/`)を読み、外枠(Rust)が
  Python へ標準入出力で渡す。プロキシ・セキュリティ製品・ポートの取り合いに左右されない
- 各言語が得意なことをする: Rust は窓・Python の監視・同時起動の防止・終了の確認・フォルダーの選択窓・
  画面の部品(CSS/JS)の配信、Python は業務(ブラウザ版と同じもの)、VBScript は Excel
- **ブラウザ版とデスクトップ版は同時に動かない**。どちらを後から開いても、後から開いたほうが理由を出して止まる
  (Store 版 Python のファイルの振り替えに左右されない、名前付きミューテックスで判定)
- 窓の × でも、印刷中なら「中断して終了しますか?」と訊く
- 点検表フォルダ・ログの保存先を、Windows の「フォルダーの選択」窓でも選べる(デスクトップ版)
- stop.bat はデスクトップ版を止めず、窓で閉じるよう案内する
- ブラウザ版(Start.vbs / start.bat)は予備としてそのまま使える
- GitHub Actions(Windows)で、試験・exe の作成・exe を起動しての確認まで流す

## VER1.5.0

### start.bat でブラウザがすぐ開くようにし、進み具合を棒で出す

実機(ラインPC)で、start.bat からブラウザが開くまで十数秒かかり、そのあいだ
黒い窓も止まって見えていました。原因は「実行環境の確認」で Excel を起動して
確かめたあと、**Excel が閉じきるのを待っていた**こと(実機で 12 秒)です。

- Excel の確認は**ブラウザが開いたあと**に行う。確かめた Excel は閉じずに残し、
  最初のプレビュー・印刷にそのまま使う(使われなければ 120 秒で閉じる)
- start.bat の窓に進み具合の棒を出す。段の中で待っているあいだも秒数が増える

  ```
  [■■■■■■■■■■■■□□□□]  77%  8/9 前回の一覧を読み込み、前回の残りを片付けています
  [■■■■■■■■■■■■■■■■] 100%  起動しました。ブラウザの画面で操作してください  (1.2秒)
  [■■■■■■■■■■■■■■■■] 100%  Excel の確認: OK(Excel 16.0)。この Excel を最初のプレビュー・印刷に使います  (1.5秒)
  ```

- 棒を出しているあいだ、窓のログは注意(WARNING)以上だけにする(棒の行が崩れないように)。
  ログのファイルには今までどおり全部残る。起動が終われば窓のログも元に戻る
- 「ポート 8733 は使用中です」のログに、OS が返した理由(エラー番号)を添える。
  Windows で 10013 なら、その番号は OS が予約している(毎回次の番号で立ち上がる)
- Start.vbs(普段の起動)は変わらない(窓が無いので棒も出ない)

## VER1.4.1

### タブを何枚も開いて使ったときの送受信を見直した

ツールのタブを3枚とほかのサイトのタブを開いた状態で、送信・受信を試し直しました
(画面番号・同時のプレビューと印刷・進み具合の問い合わせ・ほかのサイトからの送信・
閉じる合図・再起動)。操作の手順は変わりません。

- プレビューで↓↑を押し続けたり、一覧を続けてクリックしたりしても、**最後に選んだ
  点検表だけ**を Excel に作らせる。これまでは途中の点検表も全部順番に作ってから
  最後のものを出していた(10件送ると最後が出るまで10件分待った)
  - 同じ画面から次のプレビューが来たら、前の要求は順番待ちをやめる
  - ↓↑は止まってから(0.18秒)頼む
- 順番待ちのプレビューがサーバの手をふさいで、**ほかのタブの進み具合や接続確認が
  止まる**ことがあった(試験で最大2.2秒 → 0.01秒)。順番待ちは4件までにした
- 再起動した直後に、前と違う番号(ポート)で立ち上がることがあり、開いたままの
  タブが「バックエンドに接続できません」のままになっていた。同じ番号で立ち上がる
  ようにした(開いたままのタブは自分でつながり直す)。赤い帯にもそう書いた
- ほかの画面の印刷が1件目に入る前は「印刷中です(0/3 件目)」ではなく
  「印刷の準備中です(全 3 件)」と断る
- 動いているあいだにプレビューの控えのフォルダが消されても、作り直して続ける

## VER1.4.0

### 設定をタブに分け、配布設定(設定値の保存と配布)を入れた

python-web-tools(梱包資材総合ツール)の「配布設定」を移植しました。
1台で決めた設定を、ほかのラインの端末でそのまま使えます。

- 右上の「フォルダ設定」は「**設定**」になり、中を3つのタブに分けた
  - **点検表フォルダ** … これまでのフォルダ設定(中身は同じ)
  - **管理者パスワード** … 配布設定を書き出す・読み込み直す・消すときの確認。

  - **配布設定** … この端末の設定(点検表フォルダ・管理者パスワード・表示)を、
    アプリのフォルダの直下の `配布設定\` へ書き出す
- 各ラインは起動したときに `配布設定\` を読み込む。**その端末ですでに設定してある
  項目は上書きしない**(揃えたいときは、その端末で「配布設定を読み込み直す」)
- アプリを共有フォルダに置いていれば、書き出すだけで全ラインに届く
- 表示(ダーク/ライト)は人ごとの好みなので、既定では入れない
- ほかの道具(梱包資材総合ツール)の配布設定は読まない

## VER1.2.0

### 起動・プレビュー・印刷を軽くした

ラインPCで「起動も印刷もやや重い」という声への手当てです。操作の手順は変わりません。

- **Excel を使い回す。** これまではプレビュー1枚・印刷1回のたびに Excel を起動して終了
  しており、それぞれ数秒かかっていた。いまは処理のあとも 2分 残し、続けて使うときは
  すぐに始める(`config/inspection.json` の `excel.keep_alive_sec`。0 で以前の動き)。
  使われなければ自動で閉じ、アプリを終了したときも閉じる
- **点検表を選び始めたら、Excel を裏で起動しておく。** プレビュー・印刷を押したときに
  Excel の起動を待たずに済む
- 画面は Excel の終了を待たずに結果を出す
- **起動したら、前回の一覧をすぐ出す。** 共有フォルダの確認は裏で続け、終わったら新しい
  一覧に替わる。確認のあいだ、帯の「更新」は「確認中…」になる
  (フォルダ設定を変えたときは前の一覧を出さない)
- `Start.vbs` が起動前に Python を2回起動して確かめていたのを1回にした
- 利用者がダブルクリックで開いた Excel ファイルが、裏で動いている Excel に入り込まない
  ようにした(`IgnoreRemoteRequests`。終了時に元へ戻す)
- stop.bat とアプリの終了処理が同時に片付けると、記録ファイルの書き換えが失敗することが
  あったのを直した

## VER1.1.1

### Microsoft Store 版の Python でもプレビュー・印刷ができるようにした

ラインPCで次のように出て、プレビューも印刷もできませんでした(点検表のファイルはある)。

```
対象の点検表ファイルが見つかりません。
OpenTextFile 0x4C パスが見つかりません。 : C:\Users\…\AppData\Local\InspectionSheetPrint\work\excel_jobs\…\job.txt
```

- 原因: **Microsoft Store 版の Python は、%LOCALAPPDATA% や %TEMP% へ書いたファイルを
  自分専用の控えへ振り替える**(Python の公式文書「Known issues」)。Python が書いた
  指示ファイル(job.txt)が、Excel を動かす cscript からは存在しないように見えていた
- Python と Excel 処理プログラム(excel_worker.vbs)のあいだで**ファイルを一切受け渡さない**
  ようにした。指示は標準入力、結果とプレビュー画像(予備の経路)は標準出力で送る
- 指示が届かなかったときは「処理の指示を読み込めませんでした」と出す
  (「点検表ファイルが見つかりません」とは言わない)
- `start.bat` とログに、Store 版の Python であることと、ログなどがエクスプローラーから
  見える実際の場所(`%LOCALAPPDATA%\Packages\…\LocalCache\Local\InspectionSheetPrint`)を出す
- `Start.vbs` から起動して起動に失敗したときは、ブラウザに加えて Windows の窓でも知らせる
