# 変更履歴

版は `config/app.json` の `version` **ただ1つ**が出どころです
(python-web-tools と同じ決まり)。次の場所はすべてここを読むので、
**上げる場所は1か所**です。

| どこに出るか | 形 |
|---|---|
| 画面左上の帯(アプリ名の右) | `VER2.0.0` |
| ブラウザのタブの名前 | `点検表 選択・印刷 VER2.0.0` |
| プレビュー・印刷の進み具合・設定の各画面の右下 | `VER2.0.0` |
| 起動待機画面・終了した画面・起動エラーの画面 | `VER2.0.0` |
| `start.bat`(診断起動)の最初の表示 | `バージョン    : 2.0.0` |
| `stop.bat --status` | `[稼働] 版=2.0.0 …` |
| ログ(`inspection_YYYYMMDD.log`) | `起動: pid=… 版=2.0.0` |
| `GET /api/health` | `"version": "2.0.0"` |

```json
{ "version": "2.0.0" }
```

## 版の上げ方

`メジャー.マイナー.パッチ` の3つの数字だけを使います。
判断の基準は「**現場が何をし直すことになるか**」です。

| 桁 | 上げるとき | 現場に起きること |
|---|---|---|
| **メジャー** | 手順が変わる。押す場所・並び・言葉が変わる | 覚え直しが要る。事前に周知する |
| **マイナー** | できることが増える。既存の手順はそのまま | 触らなければ今までどおり |
| **パッチ** | 直しただけ。見た目も手順も変わらない | 何も要らない。黙って入れ替えてよい |

判断に迷ったら**大きいほうへ寄せます。**

### 上げるときの手順

1. `config/app.json` の `version` を書き換える
2. このファイルの「版ごとの変更」の先頭に、その版で何が変わったかを1節足す
3. 試験を通す(`python -m unittest discover -s tests -t .`)
   ── 版の書き方と、この節があるかを `tests/test_app_config.py` が機械で見ています

配るときは**フォルダごとコピー**します。版が上がっていれば、起動したときに
古い版が動いていても自動で止めて入れ替わります(`launch_guard.py`)。
入れ替えたあとに「どれが入っているか」と聞かれたら、画面左上のバッジを
読んでもらえば答えられます。

## 版ごとの変更

## VER2.4.6

### ログをツール名のフォルダに・ツール名で始まる名前に

ログの出力先(共有フォルダ)に、いろいろなツールのログが同じ階層に混ざっていて、何のツールのものか分からなかった。
現場から「ファイル名にツール名を入れる・ツール名のフォルダの下に作る、の両方を」(取り出すと開かないと分からないため)。
置き場所を `<出力先>\inspection\` に(無ければ作る)、名前を必ず `inspection_` で始めるようにした
(`core/logging_utils.py`)。この PC のローカル(既定)・書けないときの退避先も同じ形。

| | 前(VER2.4.5 まで) | いま |
|---|---|---|
| 指定のフォルダ | `inspection_YYYYMMDD_<PC>_<利用者>.log`<br>`events_YYYYMMDD_<PC>_<利用者>.jsonl` | `inspection\inspection_YYYYMMDD_<PC>_<利用者>.log`<br>`inspection\inspection_events_YYYYMMDD_<PC>_<利用者>.jsonl` |
| この PC(既定) | `logs\inspection_YYYYMMDD.log`<br>`logs\events_YYYYMMDD.jsonl` | `logs\inspection\inspection_YYYYMMDD.log`<br>`logs\inspection\inspection_events_YYYYMMDD.jsonl` |

前の場所・前の名前のファイルは移さず、そのまま**読みます**(問い合わせ番号での検索・最近のエラーの一覧・保存日数での片付け)。
前の場所はほかのツールのファイルと同じ階層なので、**点検表が書いた形の名前と一致するものだけ**を扱い、
ほかのツールのファイル(`dbviewer_….log`・`nippou.log`・`出来事_….jsonl` など)は読まない・消さない。
`events_….jsonl` は種類と拡張子の組・8 けたの日付・共有では `_<PC>_<利用者>` まで合うものだけ、行も点検表の出来事の形のものだけ読む。
設定の「ログ」タブの「いま書いているフォルダ」「フォルダを開く」は `inspection` のフォルダを指す。

(起動トークンを確かめる・`check` は訊くだけ)。

## VER2.4.1

### Word の点検表の印刷を、VBA 版(PrintWordFile)と同じ手順にした

VBA 版では印刷できていた Word の点検表が、この版の前まで印刷できなかった。VBA 版がしていたのは
「Word を起こす → 確認の窓を出さない・隠す → 読み取り専用で開く → 刷り終わるまで待って印刷 → 保存せずに閉じる
→ 最後に Word を終える」だけ。こちらはそれに加えて Word にいくつも設定をし、隠れた文書に問い合わせていた。
それをやめて、VBA 版と同じにした。

| | VBA 版 | VER2.4.0 まで | VER2.4.1 |
|---|---|---|---|
| Word の設定 | 確認の窓を出さない・隠す | ＋マクロを強制で止める(AutomationSecurity)・WordBasic で自動マクロを止める・足りない機能を入れない(FeatureInstall) | VBA 版と同じ2つだけ |
| 開き方 | 読み取り専用・最近使ったファイルに載せない・隠す | ＋仮のパスワード2つ・元に戻す・形式の指定 | VBA 版と同じ(＋変換の確認の窓を出さない) |
| 印刷の前 | 何もしない | ページ数を数えさせる(ComputeStatistics)・文書の窓の番号を聞く | 何もしない(Word の PID は文書を開く前に Windows に聞いて分かっている。分からなかったときだけ窓の番号を聞く) |
| 印刷 | 刷り終わるまで待つ・部数 | 同じ | 同じ |
| Word を終える | 最後に1回 | 同じ | 同じ |

- 隠れた Word の文書にページ数や窓を聞くと、その場で Word が落ちる(0x1CE)ことがあった
  (VER2.3.2 のプレビューで「1ページ目をコピーする所」で落ちていたのと同じ類)。
- マクロを止める設定は Excel では続ける(Word だけ VBA 版に合わせた)。

### プレビューの画面に移ったときは何も作らない

**プレビュー** を押すと、これまでは画面に移った途端に1件目を Excel・Word で作り始めていた。
VBA 版と同じく、**画面に移る → 左の一覧で選ぶ → その点検表だけを作る** にした。
行の右の ◧ で開いたときは、その点検表を選んだのと同じなので、すぐに作る。
まだ何も選んでいないときに ↓ を押すと1件目、↑ を押すと最後の点検表を出す。

## VER2.4.0

### Word の点検表のプレビューを PDF にした(Word が途中で終わる問題を方式から直す)

> プレビュー: Word が途中で終わりました。この PC で Word を開いているなら閉じてから、もう一度押してください。
> リモート サーバー マシンが存在しないか、利用できません。 0x1CE = VBScript 462: リモート サーバー マシンが存在しないか、利用できない ── つかんでいた Word / Excel が途中で終わった(落ちた・閉じられた・止められた) (失敗した所: Word の1ページ目をコピーする所)
> 問い合わせ番号: 1015-0934-AVS6
> そろそろ直してください

- **原因は方式でした。** 隠れた Word(文書も非表示で開く)で1ページ目を絵にする(`EnhMetaFileBits`)・クリップボードへ
  写す(`CopyAsPicture`)と、Word ごと落ちる文書がありました。VER2.3.2 で入れた「Word を起こし直して1回やり直す」でも、
  1回目は1ページ目の絵(word.page)、2回目はコピー(word.copy)で2回とも落ちていました
- **Word のプレビューは PDF にします。** Word の `Document.ExportAsFixedFormat`(PDF・画面用の品質・PDF を読むアプリは
  開かない)で PDF にして、**プレビューの画面の中にそのまま出します**(ブラウザ・WebView2 の PDF の表示。
  ダウンロードにはしません。`Content-Disposition: inline`)。描く窓を使わないので、隠れた Word でも落ちにくい書き出しです
- **全部のページが見られます**(1ページ目だけだったのは、絵にする方式の都合でした)。とても長い文書は先頭の 20 ページまで
  (`config\inspection.json` の `excel.word_preview_max_pages`。0 で全ページ)。画面の下に「全 ○ ページ」と出ます
- PDF は処理プログラム(VBScript)が**自分の TEMP(`%TEMP%\isp_preview`)に書き、送ったらすぐ消します**。途中で止められて
  残ったものは、次に処理プログラムが起きたとき(1時間より古いもの)に消します。名前は毎回別(`isp_pv_…`)で、2つの画面・
  2人が同時にプレビューしてもぶつかりません。届いた PDF は Excel の画像と同じ控え(`cache\preview`)に入り、2回目からはすぐ出ます
  (古い控えは起動のたびに片付けます)。プレビューを閉じた・次の点検表へ移ったときは、画面の PDF の枠を空にします
- **PDF にできないときだけ、これまでの方式に落とします**(PDF の書き出しが無い古い Word・PDF にする所で Word が終わった・
  届いたものが PDF の形でない → 1ページ目の絵 → クリップボード経由)。PDF にする所で Word が終わったら、起こし直した2回目は
  1ページ目の絵から(やり直しは VER2.3.2 と同じ1回だけ)
- PDF を表示できない画面(Edge・WebView2 の PDF の表示が切られている)では、PDF を枠に入れずに
  「**この画面では PDF を表示できません。**」と断り、「画像で表示する(1ページ目)」でこれまでの画像を頼めます
  (枠に入れると PDF がダウンロードされてしまうため)
- 止めるときは `config\inspection.json` の `excel.word_preview_pdf` を `false` に(前の版と同じ1ページ目の絵)
- **Excel の点検表のプレビューはこれまでどおり画像です。印刷は Excel・Word とも今までどおり `PrintOut`** です
- 文書を開く設定(読み取り専用・変換や「使用中」の確認を出さない・最近使ったファイルに載せない・ダミーのパスワード・
  確認の窓を出さない・自動マクロを止める)は、PDF にする前にも同じく効いています
- 試験: `tests/test_word_pdf.py`(偽の処理プログラムで、PDF で返る・一時ファイルが片付く・長い文書の上限・PDF でなければ
  1ページ目の絵・PDF にする所で落ちたら起こし直して1ページ目の絵・画像で頼める・Excel は画像のまま/画面: inline で返る・
  ダウンロードにしない・トークンが要る/処理プログラムの書き方: ExportAsFixedFormat の引数の位置・段階・消す所/画面の
  PDF の枠と断り)。**本物の Word・WebView2 では未確認**

### 大設定の「画面の色の既定」に従う(前の版の明暗の覚えを「選んだ」に数えない)

> 大設定で ダークにしているのに ライト表示される(大設定の値がデフォルトになっていない)

- **原因:** 明暗は `user_settings.json` の `dark_mode` に覚えていて、値が入っているだけで「この画面で選んだ」扱いでした。
  大設定の既定ができる前(VER2.2.0 より前)に明暗のボタンを押した端末・配布設定で表示を配られた端末は、**既定のライトが
  保存されたまま**大設定の既定を一切受けず、しかも選ばない状態へ戻る手段がありませんでした(看板 VER3.5.0 と同じ形)
- 選んだものは `theme_choice`(ライト / ダーク)に覚え直します。前の版の `dark_mode` は起動したときに一度だけ移し、
  **ライト(= 既定の値)は選んだに数えません**(大設定に従う)。ダークだけ「ダークを選んだ」として残します。前の版の
  配布設定の表示も同じ決まりで読みます
- 帯の明るさのボタンは **☀ ライト → ☾ ダーク → ◇ 既定** と回ります(看板と同じ)。ボタンには、いまの選び方が出ます。
  「◇ 既定」は大設定の既定に合わせます(届いていなければライト)。ライト・ダークを選べば、そちらが優先です
- 大設定の合図は画面を読み込んだ時点で受けます(配線の途中で止まっても取りこぼさない)。起動待機画面も届いた既定を
  覚えて、次に出る点検表の画面が描く前にその色を当てます
- 試験: `tests/test_theme.py`(前の版のライトは選んだに数えない・ダークは残す・既定に戻せる・配布設定・画面の頭の
  スクリプト・画面の JS を node で動かして、大設定に従う/選んだら優先/既定に戻る)

## VER2.3.2

### Word のプレビューで「0x1CE」が出たときに、Word を起こし直してやり直す・開いたままの点検表を閉じてから刷る

> 印刷範囲の取得に失敗しました。
> リモート サーバー マシンが存在しないか、利用できません。 0x1CE (失敗した所: Word の1ページ目をコピーする所)
> Excel を操作する処理プログラム(VBScript)が途中で終わった(WORKER_FAILED)
> これ例えばどこかで開きっぱなしにしていた場合にもこのエラーになるのでは?
> docのときはWordを読んでいますと出したほうがいい

> もしエクセル、ワードが開いている場合は(他PCで)強制で閉じてもよいです。点検表原紙なので編集する必要のないもので印刷オンリーです。開いたままになっているのがおかしいです

- **0x1CE は、つかんでいた Word が途中で終わっていた(落ちた・閉じられた)ときの VBScript のエラー 462 です。**
  開きっぱなしの文書では起きません(読み取り専用で開くので、この PC・ほかの PC で開かれていても開けます)。
  報告の流れでは、1ページ目を絵にする所(EnhMetaFileBits)で Word が終わり、そのあとのコピーで 462 が出ていました
- **462(と RPC のエラー 0x800706BA / 0x800706BE / 0x80010108)が出たら、Word を起こし直して1回だけやり直します**
  (プレビュー・印刷とも)。1ページ目の絵で落ちたときは、2回目はクリップボード経由にします。
  印刷の途中で落ちたときは、紙に出ているかもしれないのでやり直しません(「プリンターに出ていないか確かめてから」と出ます)。
  2回とも駄目なら「**Word が途中で終わりました。この PC で Word を開いているなら閉じてから、もう一度押してください。**」
- エラー番号の意味に 0x1CE(= 0x800A01CE、VBScript 462)・0x800706BE・0x80010105 を足しました
- **この PC の Excel・Word でその点検表が開いたままなら、保存せずに閉じてから**プレビュー・印刷します
  (原紙で印刷するだけのため。閉じるのはそのファイルだけで、ほかのブック・文書・アプリは閉じません)。
  閉じたことは画面(プレビューは知らせ、印刷は1件ずつの欄)とログに出ます。止めるときは `config\inspection.json` の
  `excel.close_open_copy` を `false` に
- **ほかの PC で開かれている点検表は閉じられません**(相手の Word・Excel を止める手段はありません)。読み取り専用で
  開くので、そのまま印刷・プレビューできます。共有フォルダの所有者ファイル(`~$…`)から名前が読めれば
  「○○さんが開いたままです(印刷はできます)」と出します(`~$` ファイルは消しません)
- CreateObject が利用者のすでに動いている Word を返したとき(ふつうは新しい Word が起きますが、約束ではありません)は、
  その Word を隠さない・設定を戻す・終えない・PID を覚えない(時間切れの後始末・起動時の片付けでも止めない)ようにしました
- **Word の点検表のときは Word と言います。** プレビューの読み込み中「Word で画像を作成しています」、印刷の
  「Wordを起動しています...」「Word の空き待ち...」、断りの文・ログの「なぜ」(「Word を操作する処理プログラム…」)
- ログの `excel.job` が、点検表1件の失敗(終了コード 4)まで「処理プログラムが途中で終わった(WORKER_FAILED)」と
  記録していたのを、本当の原因の種類(WORD_GONE・RANGE_FAILED など)で残すようにしました。途中で終わった
  と言うのは、処理プログラムが FINISH を返さなかったときだけです
- 試験: `tests/test_word.py`(偽の処理プログラムで 462 を起こす → 起こし直して成功/2回目も失敗なら分かる断り/
  利用者の Word を止めない/閉じる指示が渡る・ほかの文書は閉じない/読み取り専用で開く/所有者の名前/文言が Word になる)。
  本物の Word では未確認

## VER2.3.1

### Word のプレビュー・印刷ができないときに、どこで止まったかを出す

> ワードのプレビューができません　印刷もできません

- 処理プログラムが段階ごとに `STAGE`(Word を起動する・文書を開く・1ページ目を絵にする・印刷する …)を知らせます。

- 失敗したときは、どの段階で失敗したか(`item.<i>.step`)と、よく出るエラー番号の意味を添えます
- 文書を開く前に、確認の窓を出さない設定(DisplayAlerts)・自動マクロを止める設定をし直します
- 起動した Word の PID を、文書を開く前に WMI で確かめて覚えます(止まったときに確実に終えるため)
- 試験: `tests/test_word.py`(偽の処理プログラムで、止まった所・窓・エラー番号の出方を確かめる)
