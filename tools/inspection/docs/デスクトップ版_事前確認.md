# デスクトップ版(Python/Tauri/Rust)への移行 ── 事前確認

VER1.6.0 の機能を、デスクトップ版(Rust/Tauri の外枠 + Python)へ移したときに**維持できるか**を、
移行の前に1つずつ確かめた結果です。参照したのは移行済みの python-web-tools(VER4.0.0〜4.3.2)。

## 結論

**すべて維持できる**(下の表)。ただし次の4点は作りを変えないと壊れるため、移行の中で手当てする。

| # | そのまま移すと起きること | 手当て |
|---|---|---|
| A | **ブラウザ版とデスクトップ版の同時起動を、ファイルの錠では止められない。** ラインPCの Python は Microsoft Store 版で、`%LOCALAPPDATA%` への書き込みが Python 専用の場所へ振り替えられる(VER1.1.1 の 0x4C と同じ仕組み)。Python が書いた錠を exe(Rust)が見つけられない | 錠を**ファイルではなく OS の名前付きの錠**(Windows の名前付きミューテックス。利用者のログオンごと)にする。どちらの言語からも同じ名前で見える |
| B | 画面を閉じたら自動で終わる仕組み(心拍)は、ブラウザのタブのためのもの。デスクトップ版で動かすと、窓を最小化しているだけで終わることがありうる | デスクトップ版では使わない。窓の × と「終了」で終える(印刷中は確認) |
| C | 共有フォルダに置いた exe は、どこかのラインで動いている間は**上書きできない**(Windows が使用中のファイルを守る) | 入れ替えの手順を決める: 動いている exe は**名前を変えることはできる**ので、`古い.exe` に名前を変えてから新しい exe を置く(手順書に書く) |
| D | 起動できないときの案内に出すログの場所を exe が自分で計算すると、Store 版 Python の振り替え先とずれる | 場所は Python から受け取る(Python が起動できないときだけ exe が推定し、その旨を書く) |

| 多重起動 | 2つ目の exe は開かず、開いている窓を前に出す | 試験 |
| **ブラウザ版との同時起動** | **後から開いたほうが止まる**(下の「同時に動かさない」) | 試験(両方向) |

| プレビュー(Excel の CopyPicture) | そのまま。Excel は今までどおり VBScript(cscript)が操作する。ポートは元から使っていない | 既存の試験(Excel の実物は Windows 実機) |

| ログ・問い合わせ番号・なぜなぜ・画面のエラーの記録 | そのまま(要求ごとの番号は Python が振る) | 既存の試験 |
| 「ログのフォルダを開く」 | そのまま(Python がエクスプローラーを開く) | Windows 実機 |
| 新しい版が置かれた帯 | そのまま | 既存の試験 |
| 接続が切れた帯 | Python が落ちたら、窓が理由の画面に替わる | 試験(Python を止める) |

| プロキシ・セキュリティ製品 | **ポートを使わないので影響を受けない** | 試験(ソケットを禁止して起動) |

## 何をどの言語に書かせるか

| 言語 | 受け持ち | 理由 |
|---|---|---|
| **Rust**(exe) | 窓・Python の起動と監視・多重起動と同時起動の防止・終了の確認・**フォルダーの選択窓**・社内サイトを既定のブラウザで開く・**画面の部品(CSS/JS)を直接返す**・Python が居ないときの理由の画面 | OS の窓・プロセス・錠を扱うのが得意。exe 1つで配れる。部品の読み込みを Python に渡さないので画面の表示が軽い |
| **Python** | 一覧・設定・配布設定・ログ・Excel の段取り(使い回し・順番待ち・後片付け)・プレビューの控え・印刷の進み具合 | **ブラウザ版(予備)と同じものを1つだけ持つ**ため。2つの言語で同じ業務を持つと、片方だけ直す事故が起きる。VBA と同じ並びを守る試験もこの形で書かれている |
| **VBScript** | Excel の操作(開く・CopyPicture・PrintOut・閉じる) | 今までどおり。VBA と同じ言葉で Excel を扱える |
| **JS** | 画面の操作 | 今までどおり。デスクトップ版のときだけ、フォルダーの選択と別窓を外枠に頼む |

**業務を Rust へ書き直さない理由**(実測): 重い処理が無い。点検表フォルダの確認は共有フォルダの読み取り待ち
(111 件で 170 ms)、プレビュー・印刷は Excel の待ち時間がほとんどで、言語を替えても速くならない。

## ポートを使わない仕組み

```
点検表.exe(Rust/Tauri)
 ├─ 窓(WebView2)が app://localhost/(Windows は http://app.localhost/)を読む ── ネットワークを通らない
 ├─ /static/… は exe が自分でファイルから返す
 └─ それ以外は Python の標準入力へ渡し、標準出力から応答を受け取る
        │ 1件 = 見出し1行(JSON)+ 本文
        ▼
bridge.py(Python)── Flask の画面・API をそのまま呼ぶ(待ち受けない)
        ▼
app/ ・ core/(Python)── 業務(ブラウザ版と同じもの)
        ▼
excel_worker.vbs(VBScript)── Excel(今までどおり標準入出力。元からポート無し)
```

## 同時に動かさない(どちらを後から開いても止まる)

| 先に動いているもの | 後から開いたもの | 動き |
|---|---|---|
| ブラウザ版 | デスクトップ版 | 「ブラウザ版が動いています。ブラウザの画面の『終了』で閉じてから開いてください」と出して終わる |
| デスクトップ版 | ブラウザ版(Start.vbs / start.bat) | 「デスクトップ版が動いています」と出して終わる(デスクトップ版の窓を前に出す) |
| デスクトップ版 | デスクトップ版 | 開かず、開いている窓を前に出す |
| ブラウザ版 | ブラウザ版 | 今までどおり(開いているものにブラウザでつなぐ) |

錠は Windows の名前付きミューテックス(`Local\` = 利用者のログオンごと)。プロセスが落ちても OS が外すので残らない。
同じPCに別の利用者がリモートでログオンしていても、互いに止め合わない。
