# ログとなぜなぜ分析(VER1.6.0)

エラーが出たあとで「何が・なぜ起きたか」を辿れるようにする仕組みです。

## 1. 現場でやること

画面の断りの文・印刷の結果・プレビューの失敗には、最後に **問い合わせ番号** が出ます。

```
印刷完了: 2 ファイル(1 部ずつ)
エラー: 1 ファイル
問い合わせ番号: 1001-1502-7KQ2
```

- 番号は `月日-時分-4文字`(電話で読み上げやすく、日時でも探せる)
- 現場はこの番号だけ控えて(写真でもよい)、管理者に伝える

## 2. 管理者がやること

設定 →「ログ」タブ →「問い合わせ番号で探す」に番号を入れます。

| 出るもの | 中身 |
|---|---|
| **なぜなぜ** | 記録から言えるところまで。`現象`(画面に出した文)→ `なぜ1`(何が起きたか)→ `なぜ2`(Excel・OS が返した詳しい原因)。その先の段は空けてあり、下の3つを見て考えます |
| **確かめること** | エラーの種類ごとの「次のなぜ」の手がかり(`app/why_hints.py`) |
| **そのときの状況** | 対象の点検表・ファイル・プリンター・シート・かかった時間・Excel の返答・処理プログラムの記録など |
| **同じ番号の記録** | 印刷なら「開始 → 1件ずつの結果 → 全体の結果」 |
| **直前に起きていたこと** | 同じアプリで、その前に起きていたこと(古い順)。ほかの画面の印刷・Excel の起動し直し・フォルダの確認など |

「文にして写す」で、なぜなぜの表に貼れる文になります(メール・Teams に貼れる)。

「最近のエラー・断り」には、この端末の直近 7 日のものが新しい順に並びます。押すと同じ表示になります。

### 例: 印刷できなかった

| 段 | 記録から | 考えること |
|---|---|---|
| 現象 | 印刷に失敗しました。 | |
| なぜ1 | Excel が印刷の命令(PrintOut)に失敗した(PRINT_FAILED) | |
| なぜ2 | 0x800A03EC プリンターが見つかりません | |
| なぜ3 | | 「そのときの状況」のプリンター = 別ラインのプリンター → 既定のプリンターが替わっていた |
| なぜ4 | | 直前に、別ラインの作業で既定のプリンターを切り替えて戻していなかった |
| なぜ5 | | 1台で2ラインを受け持つ手順に「戻す」が無い → 手順書に追加 |

## 3. ログの保存先(設定 →「ログ」)

| 項目 | 既定 | 説明 |
|---|---|---|
| 保存先のフォルダ | この PC のローカル | **共有フォルダを指定すると、全ラインのログが1か所に集まり、管理者の席から後追いできます**。番号での検索もほかの端末の分まで探します |
| 保存日数 | 90 日 | 過ぎた**この端末の**ログは起動時に消します(7〜3650 日) |

- 保存先・保存日数は **配布設定** に入れて全ラインへ配れます
- 変えるとその場で切り替わります(再起動は要りません)。前のファイルには「ここから先は○○へ」、
  新しいファイルには「前は○○」を残すので、どちらからでも続きを辿れます
- 書けないフォルダは保存しません(理由を出します)
- 共有に書けなくなったとき(ネットワークが切れた等)は **この PC に退避して書き続け**、5 分ごとに
  戻れるか試して、戻れば戻ります。設定画面には「退避中」と理由が出ます
- この PC のログは、Microsoft Store 版の Python では次の場所に見えます(設定画面にも出ます)
  `%LOCALAPPDATA%\Packages\PythonSoftwareFoundation.Python.3.x_…\LocalCache\Local\InspectionSheetPrint\logs`

### ファイル

| ファイル | 中身 |
|---|---|
| `inspection_YYYYMMDD.log` | テキストのログ(流れ)。出来事の行には `[ref=問い合わせ番号]` が付く。例外の全文もここ |
| `events_YYYYMMDD.jsonl` | 出来事の記録(1行1件の JSON)。なぜなぜ分析はこちらを読む |

指定したフォルダでは、名前の後ろに `_<端末名>_<利用者名>` が付きます
(`inspection_20261001_LINE3-PC_xfa-ngykonpo.log`)。**ほかの端末のファイルには書かない・消さない**ので、
何台で共有しても混ざりません。Excel で開くときは、`events_*.jsonl` は「データ → JSON から」で表になります。

## 4. 記録するもの

| 操作(op) | いつ | おもな項目 |
|---|---|---|
| `startup` | 起動できた / できなかった | 版・Python・ポート(使えなかった番号と理由)・ログの保存先・点検表フォルダ・プリンター |
| `shutdown.request` / `shutdown` | 終了ボタン・stop.bat・自動終了 / 終了 | 誰が・稼働秒数 |
| `cleanup` | 前回の Excel が残っていた | 件数(前回は正しく終われていない) |
| `scan` | 点検表フォルダの確認 | フォルダ・件数・読めなかったもの・きっかけ |
| `preview` | プレビュー | 対象・ファイル・控えか・シート・範囲・かかった時間 |
| `print.start` / `print.item` / `print.end` | 印刷 | 対象・ファイル・部数・プリンター・1件ずつの結果と原因 |
| `excel.open` / `excel.close` / `excel.job` | Excel の起動・終了・失敗 | PID・理由・**処理プログラムの記録と Excel の返答**(失敗のとき) |
| `settings.*` | 設定の変更 | 点検表フォルダの前後・ログの保存先の前後・配布設定・管理者パスワード(**値は残さない**) |
| (各 API) | 業務の断り・失敗 | 種類・文・詳しい原因・宛先・HTTP |
| `client.*` | 画面(ブラウザ)の中のエラー・つながらなかったあいだ | 文・場所・何秒・何回・どの宛先 |

- 結果(result): `ok` できた / `ng` できなかった / `refused` 業務として断った / `info` 記録
- 画面からの送りすぎは捨てます(1画面 10 分 30 件まで)
- 記録に失敗しても業務(印刷など)は止めません

## 5. 作りの場所

| ファイル | 役目 |
|---|---|
| `core/logging_utils.py` | 保存先(設定・退避・戻り)・ファイル名・片付け |
| `core/event_log.py` | 出来事の記録・問い合わせ番号・読み出し(番号・直前の操作) |
| `app/why_hints.py` | エラーの種類 → 何が起きたか・確かめること(新しい種類を作ったら1行足す) |
| `app/__init__.py` | 要求ごとに番号を振る・断りと失敗を記録して番号を返す |
| `app/routes/logs.py` | 「ログ」タブの API・画面のエラーの受け口 |
| `app/static/js/logs.js` / `clientlog.js` | 「ログ」タブ / 画面のエラーを送る |
